# 业界洞察：多模态交互

联网检索 33 个页面 + 本机博客/论文 40 条。

## 一句话结论

现有竞品可以先按五类看：系统或 App 助手有小艺看世界、小艺、Gemini Live、ChatGPT、Apple Visual Intelligence、Copilot Vision、Bixby、SeedRealtime、小度、理想同学、NOMI、vivo看见、Be My Eyes；AI/AR 眼镜有 Ray-Ban Meta、Android XR、Snap Specs、夸克AI眼镜；屏幕与家居终端有 Samsung Vision AI、海信；视频理解基础设施有 TwelveLabs；视觉交易基础设施有拍立淘。它们的关键区别不在于能不能识图，而在于是否连续实时、是否会主动引导、是否拿得到系统数据并执行动作、交互载体是什么，以及最终解决的是随手问答、无障碍、工作流、家庭看护还是交易。

## 差异在哪

- 实时性分层明显：Gemini Live、ChatGPT、SeedRealtime 和小艺看世界强调连续音视频或实时对话；Apple Visual Intelligence、TwelveLabs 和拍立淘更偏一次触发或已上传内容的识别与检索。
- 主动程度不同：Gemini 的 Guided Vision 会指导用户移动镜头，Snap 强调 anticipatory AI；多数手机和电视助手仍等待用户提问。
- 系统数据权限形成硬差异：小艺能够调用天气、日历和位置等服务，Copilot 能结合工作数据，但材料没有证明其他多数产品具有同等权限。
- 执行边界不同：Bixby 和部分系统助手可围绕屏幕或系统内容操作；Copilot 明确只回答和高亮，不会替用户点击或输入，视觉理解与任务执行之间仍有明显断层。
- 硬件载体决定交互：手机支持拍照、圈选和屏幕共享；眼镜支持第一视角、语音和近眼显示；电视围绕大屏点击与家庭看护；汽车增加座位、指向和车身传感器。
- 同为眼镜，路线不同：Ray-Ban Meta 先做语音问答、翻译和轻量显示；Android XR 把 Gemini 和第一视角共享做成平台；Snap 强调跨设备主动提醒；夸克把导航、支付、购物和出行服务直接串起来。
- 目标人群分裂：ChatGPT、Gemini、Apple 面向通用消费者；vivo看见和 Be My Eyes 面向视障用户；Copilot 面向知识工作者；小度、三星和海信更偏家庭场景。
- 基础设施和终端产品不是同一层竞争：TwelveLabs 和拍立淘提供可集成的视觉能力，SeedRealtime 提供实时音视频模型底座，而其他产品直接争夺终端用户入口。
- 第三方实测与官方演示存在张力：官方材料强调小艺的实时对话，第三方无障碍横评却称其更偏静态识别；因此不能把演示能力直接当成稳定体验。
- 语言与地区不能按产品推断：材料明确展示了中文、英文及部分跨语言能力，但没有系统给出各产品的支持语言、地区覆盖和合规边界。

## 场景拆解

### 日常随看随问

- 谁在做：Gemini Live、ChatGPT、小艺看世界、Ray-Ban Meta
- 做法差异：Gemini 会主动指导镜头；ChatGPT 强调边说边看和多轮追问；小艺结合手机或眼镜及系统服务；Ray-Ban 以语音和第一视角换取免手持体验。

### 完成任务时的实时引导

- 谁在做：Gemini Live、vivo看见、Be My Eyes
- 做法差异：Gemini 用自然语言纠正镜头并解释画面；vivo 面向视障用户自动播报；Be My Eyes 在复杂或高风险场景可让人工代理接手。

### 免手持第一视角

- 谁在做：Ray-Ban Meta、Android XR、Snap Specs、夸克AI眼镜
- 做法差异：Meta 先做问答、翻译和镜片显示；Android XR 做平台化第一视角助手；Snap 做跨设备主动提醒；夸克直接接交易和出行服务。

### 系统操作与屏幕理解

- 谁在做：小艺、Bixby、Apple Visual Intelligence、Copilot Vision
- 做法差异：小艺可调系统服务；Bixby 支持相机、文档和圈屏；Apple 偏单次视觉任务；Copilot 结合工作数据但明确不执行点击输入。

### 电视客厅场景

- 谁在做：Samsung Vision AI、海信
- 做法差异：三星同时做屏幕上内容问答、点选搜索和家庭摄像头看护；海信强调模型接入、万物识别、画质和语音对话。

### 汽车座舱

- 谁在做：理想同学、NOMI
- 做法差异：理想重点是通过多音区和空间传感器判断谁在说话、坐哪里、指向什么；NOMI 更强调座舱内外识别和情感陪伴。

### 企业视频与工作流

- 谁在做：Copilot Vision、TwelveLabs
- 做法差异：Copilot 把画面与工作数据放进交互式会话；TwelveLabs 把视频上传、搜索、分析和嵌入做成可计费 API。

### 视觉搜索与交易

- 谁在做：夸克AI眼镜、拍立淘
- 做法差异：夸克把第一视角搜索接到导航、支付和购物链路；拍立淘提供可被开发者调用的同款搜索和比价基础能力。

### 家庭看护与陪伴

- 谁在做：小度、Samsung Vision AI
- 做法差异：小度定位家庭智能体中枢；三星从电视摄像头切入异常检测、宠物和家庭看护。

## 可商用变现的切入点

### 实时多模态交互 harness 的评测、失败归因与自动优化平台

- 目标客户：手机、眼镜、汽车和家庭终端厂商，以及多模态模型团队
- 为什么现在能做：终端已经能连续看和听，但公开材料主要集中在功能演示，缺少对触发、中断、延迟、工具调用和任务完成率的统一评测；本地归档的 HarnessOpt-Bench 与交互式失败分类正好指向这个空白
- 怎么收钱：企业订阅的评测席位、私有化部署、按测试轨迹或调用量计费，以及后训练和 harness 优化项目费
- 壁垒：真实设备轨迹、跨设备任务集、模型与 harness 的失败归因 schema、可复现的 grounded verifier 和版本化候选审计
- 风险：客户不愿交出摄像头轨迹；隐私和数据处理成本高；任务集容易泄漏或被厂商定制成排名游戏

### 安全可控的实时主动引导 SDK

- 目标客户：无障碍服务机构、公共部门、保险与远程协助公司，以及手机和眼镜 OEM
- 为什么现在能做：Guided Vision 已能提示镜头怎么移动，vivo看见已能自动播报并多轮对话，但主动何时提醒、何时停止和何时转人工仍没有清晰产品标准
- 怎么收钱：按设备或用户席位的年度 SaaS、机构采购合同，以及高风险任务的人工接管服务费
- 壁垒：可审计的任务脚本、低延迟取景引导、多语言表达能力、人工升级协议和针对危险场景的策略护栏
- 风险：错误引导可能造成人身或财产损失；无障碍用户对打断和语气敏感；采购周期长，低价公共项目难覆盖服务成本

### 策略自适应的多模态安全护栏与工具权限路由

- 目标客户：多模态助手厂商、企业 Agent 平台和系统级手机/汽车厂商
- 为什么现在能做：系统助手开始拿到屏幕、位置、摄像头和工作数据；本地归档的 Shieldstral 说明小模型可以适配不同文本与多模态安全政策，而 verifier 级联研究提醒简单叠加验证器会受相关盲点限制
- 怎么收钱：按调用量收费的审核 API、私有化许可、策略配置与审计订阅
- 壁垒：策略自适应数据构造、多模态证据校验、模型与规则去相关设计，以及对工具调用前后状态的审计能力
- 风险：低延迟视频场景下护栏成本高；安全政策随地区和行业变化；过度拦截会破坏用户体验，漏拦则带来责任风险

### 车内空间意图与指代理解 harness

- 目标客户：汽车厂商、座舱 Tier 1 和车载语音团队
- 为什么现在能做：理想同学已经用多音区、3D ToF 和红外信号判断谁、坐哪、指向哪；NOMI 已融合图像、音频和车身传感器，但两类能力还需要统一评测和可靠的后训练闭环
- 怎么收钱：按车辆预装授权、车型项目开发费、持续 OTA 优化与车队数据评测订阅
- 壁垒：多人多音区与指向数据、空间指代 schema、车规级安全约束，以及模型和 harness 的在线失败定位
- 风险：车规验证周期长；车内隐私敏感；错误识别可能导致误控车辆功能，数据回传受严格限制

### 面向现场作业的多模态视频理解与行动助手

- 目标客户：巡检、维修、零售运营和远程专家服务企业
- 为什么现在能做：TwelveLabs 已证明视频搜索和分析 API 可以商业化，但当前主要是上传视频；实时第一视角、主动纠错和任务完成验证仍稀缺
- 怎么收钱：按视频分钟或事件量计费、企业平台订阅、私有化部署和专家接管服务
- 壁垒：行业事件本体、低码率实时理解、任务完成 verifier、成本与延迟优化，以及可追溯的现场证据
- 风险：通用视频模型快速降价；行业数据获取困难；客户要求端到端解决而非只给识别结果；现场误报会消耗信任

### 可验证的视觉导购与支付 Agent

- 目标客户：眼镜厂商、电商平台、品牌商家和线下零售企业
- 为什么现在能做：夸克AI眼镜已经连接近眼导航、支付宝、淘宝和飞猪，拍立淘也有成熟的同款检索接口；下一层竞争会从“搜到”转向“确认、比价、下单和可撤销”
- 怎么收钱：交易佣金、导流费、商家 SaaS、按调用量 API 和会员订阅；具体价格与佣金结构需由合作方另行确定
- 壁垒：实时商品目录、跨渠道比价、价格与库存核验、支付前确认机制和失败回滚审计
- 风险：商品匹配误差导致买错；商家数据封闭；支付和推荐涉及高合规要求；用户可能只把助手当比价工具而不完成交易

## 空白与机会

- **空白**：当前材料展示了大量“能看会说”的功能，但几乎没有给出准确率、响应延迟、任务成功率、误报率和长期使用数据，无法据此判断真实产品成熟度。
- **空白**：多数助手停留在回答问题，真正能执行系统动作的边界不清楚；Copilot Vision 明确不点击也不输入，说明视觉理解与可靠行动之间仍有断层。
- **空白**：主动引导还没有形成可信的触发机制。材料能看到 Gemini 指导镜头和 Snap 主动提醒，但看不到何时该提醒、何时应沉默、如何纠错以及误触发成本。
- **空白**：系统权限和隐私边界不透明。哪些数据在端侧处理、哪些会上传、保留多久、如何防止摄像头中的敏感信息被二次使用，材料均未说明。
- **空白**：长时上下文和跨设备记忆仍割裂。Snap 和 Copilot 展示了跨设备入口或工作数据，但没有证据表明它们已经形成连续、可撤销、可解释的个人情境记忆。
- **空白**：实时交互基础设施仍不均衡。TwelveLabs 和拍立淘偏上传与检索，真正面向连续视频流、低延迟和可恢复会话的成熟 API 展示较少。
- **空白**：无障碍产品虽然已有实时描述和付费企业平台，但在复杂任务中的转人工、风险升级、可审计性和跨地区服务仍缺少统一标准。
- **空白**：安全评测没有跟上多模态入口。本地归档已研究策略自适应护栏、验证器相关盲点和具身多模态欺骗，但现有终端材料几乎没有公开对应的上线前评测体系。
- **空白**：第三方横评与官方演示存在落差，尤其是小艺被官方描述为实时对话、被第三方描述为偏静态识别，说明需要更透明的独立测试条件。
- **空白**：许多产品的语言、地区、价格和上市范围未说明，因此不能仅凭中文或英文官网推断其全球可用性。
- **机会**：把“看见”做成可验证的交互闭环，而不只是识图：围绕连续视频流记录观察、推理、工具调用、用户纠正和最终结果，作为后训练和 harness 优化的统一轨迹格式。
- **机会**：切入模型与 harness 的故障定位：面向实时手机、眼镜和车内助手建立交互级失败分类，区分模型理解错误、harness 控制错误、权限缺失、设备延迟和用户意图不清，这比再做一个通用视觉问答壳更有科研与商用价值。
- **机会**：研究主动交互的触发与停止策略：用真实任务衡量何时插话、如何纠错镜头、何时要求用户确认，以及错误提醒造成的认知负担；这正是当前 anticipatory AI 与 Guided Vision 之间尚缺的共同问题。
- **机会**：将多模态安全护栏做成可配置的基础设施：基于策略适配分类器和多来源证据校验，服务不同国家、行业和设备权限，而不是给所有模型套一套固定风险标签。
- **机会**：做面向工作流的多模态 Agent 评测与自演进：结合企业真实流程、人工耗时和成本指标，验证多模态助手是否真的完成交付，而不只看单轮回答质量。
- **机会**：围绕无障碍与现场作业建立“视觉助手加人工后备”的高信任产品：NLP 背景可用于意图澄清、指代消解、危险提示和多轮纠错，比单纯堆模型参数更接近实际用户价值。
- **机会**：研究相关验证器的组合边界：不同模态、不同模型和不同证据源可以降低相关性，但相关论文同时表明盲点原子会形成可靠性上限；商业系统应把去相关和拒答设计成核心，而不是无限叠加验证器。
- **机会**：从 API 工具层切入，而不是先做通用眼镜：把实时视频理解、主动引导、失败归因和成本控制封装为可嵌入 SDK，先服务 OEM 和企业，再验证消费级入口。

## 接下来盯什么

- Android XR 眼镜从演示走向开发者套件或正式销售的时间、价格和可用地区。
- Snap Specs 的服务是否真正上线、眼镜是否开售，以及 anticipatory AI 的提醒频率、关闭方式和用户反馈指标。
- Gemini Guided Vision 是否公布独立任务成功率、延迟和误引导数据，而不只是展示取景辅助演示。
- 手机助手是否从问答扩展到可撤销的系统操作，包括点击、填表、支付、跨 App 调用和权限确认。
- 实时视频助手的部署方式、端云分工、摄像头数据保留策略，以及针对画面中他人隐私和敏感信息的处理规则。
- 多模态助手是否出现可独立复现的评测集，覆盖连续交互、多人场景、指向指代、工具调用和长时任务。
- 主动交互产品是否公开“何时不打扰”的指标，包括误触发率、用户纠正率、中断后恢复成功率和任务净收益。
- 眼镜、汽车和电视厂商是否开放第三方开发者接口，还是继续把多模态能力锁在自家应用和交易生态中。
- 无障碍产品的个人免费与机构付费模式能否规模化，以及企业客户是否真正为远程人工接管和合规审计付费。
- 视觉导购 Agent 是否能从搜同款走到可验证的库存、价格、下单和退款闭环，而不是仅做流量入口。
- 策略自适应多模态安全分类器能否在真实摄像头流上同时满足低延迟、低误杀和可解释拒答。
- harness 自动优化与多模态失败归因是否形成行业共享标准；若只有单厂商内部评测，外部产品之间的能力比较仍会失真。
