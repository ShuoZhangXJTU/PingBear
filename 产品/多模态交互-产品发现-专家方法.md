# 多模态交互：按专家方法重做产品发现

上一份产品决策报告是从竞品和市场数据反推的。这一份换顺序：先看产品专家怎么做判断，再按他们的方法重做一遍。
用的五个方法都来自公开资料：

- Amazon Working Backwards：先写 PR/FAQ，再决定要不要做（AWS Executive Insights、workingbackwards.com）
- Marty Cagan 四风险：价值、可用性、可行性、商业可行性（SVPG）
- Rob Fitzpatrick《The Mom Test》：只问过去发生的事实，不问对未来的看法
- Teresa Torres 持续发现：每周真实用户访谈 + Opportunity Solution Tree + 假设测试
- AI 产品 eval-driven development：先把「什么叫做好」写成可执行评测，再开始做（Anthropic、OpenAI、Apple）

## 一、先写 PR/FAQ（Amazon Working Backwards）

> **标题：看得懂、控得住的第二双眼睛**
>
> 我们今天发布一款多模态交互助手：用户不用掏出手机，只要把镜头对准眼前，就能问「这是什么」「下一步怎么做」，
> 它会在 2 秒内给出答案，并明确标出它看到了什么、依据是什么；不确定时会直接说不知道，并请用户换个角度。
> 它不替代手机，只在你双手忙、光线差、字太小或不方便操作时补上「看和问」这一步。
>
> 首批场景：读菜单/药品说明书、电视画面问答与控制、车内指向操作。
> 用户说：「以前要拍照、切 App、放大、再打字问，现在抬头说一句就好了。」

FAQ 必须先回答的问题（现在就要写，不是上线前）：

| 问题 | 当前答案 | 证据状态 |
|---|---|---|
| 谁最需要它？ | 双手忙的人、长辈、视障用户、开车/做饭/带娃的人 | 竞品与评测支持，但尚无本项目一手访谈 |
| 为什么不用手机？ | 掏手机 + 拍照 + 打字这 3 步在特定场景很贵 | 需要 Mom Test 访谈验证「上一次你是怎么做的」 |
| 和 Gemini/ChatGPT/小艺差在哪？ | 可验证（说出了什么证据）、可关闭、低打扰、能执行控制 | 是假设，必须用对照实验验证用户是否愿意为「可验证」多付钱 |
| 隐私怎么办？ | 拍摄提示、本地处理优先、默认不留原始视频、权限可审计 | 设计假设，需用户测试 |
| 怎么收费？ | 硬件合作分成 + 企业订阅；个人基础功能免费 | 未验证，需做定价访谈 |
| 最大的失败风险？ | 像 Humane 一样「演示很好、日常不用」；像 AI 眼镜一样 30–50% 退货 | 已有市场证据，必须用复用率门槛把关 |

## 二、四风险体检（Cagan）

| 风险 | 我们的假设 | 已有证据 | 还缺什么 | 最便宜的测试 |
|---|---|---|---|---|
| 价值 | 用户愿意在「不方便掏手机」时用它，且第二天还会用 | Ray-Ban 700 万副、中国 AI 眼镜 +107%，但退货率 30–50% | 一手访谈：上一次遇到这个场景时他做了什么、花了多久 | 8 个场景各访谈 5 人，只要事实不要意见 |
| 可用性 | 抬头说一句话比掏手机少 3 步 | 小艺支持指向问答，但入口分散；三星电视被投诉通知/许可 | 真实任务下的首次成功率、平均时长 | 用纸面原型 + 现有模型做「绿野仙踪」测试 |
| 可行性 | 现有模型 + harness 能做到 2 秒内响应、可验证 | SeedRealtime 已做到音视频全双工；Gemini 有取景引导 | 端侧延迟、弱网、长会话稳定性 | 3 个场景各 200 条轨迹原型 |
| 商业可行性 | 硬件厂商愿意为软件层付费，或企业愿意订阅 | Be My Eyes 企业版收费、TwelveLabs 按量 API、拍立淘 API 商业化 | 谁付钱、付多少、采购周期 | 5 个 OEM/企业买家的付费意愿访谈（不是「你觉得好不好」） |

**结论：价值风险最高，也最没被验证。** 上一份报告直接推荐「harness 平台」是跳过了价值验证——按专家方法，这只能算假设，不能算结论。

## 三、机会树（Torres）

目标结果（Outcome）：让用户在「不方便掏手机」的场景里，**次日复用率 ≥40%**，而不是先追求下载量。

机会（Opportunities，来自用户 pains，暂为假设，等访谈确认）：

1. 「要先拍照再打字」这一步太麻烦。
2. 看不清小字/远处物体，手机也拍不清。
3. 看到画面后不知道该问什么、怎么操作。
4. 担心 AI 说错，但没有办法核实。
5. 双手忙（做饭、带娃、开车、搬东西）没法操作手机。
6. 长辈/视障用户需要别人帮忙看。

解决方案（每个机会至少两个方案，不锁死）：

| 机会 | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 拍照打字麻烦 | 实时视频直接问 | 拍一张后语音追问 | 眼镜/耳机形态免手 |
| 看不清 | 引导取景（Gemini 式） | 多帧融合/超分 | 请求补拍 |
| 不知道怎么操作 | 给步骤 + 高亮区域 | 直接执行（需授权） | 转人工 |
| 怕说错 | 附画面证据 | 置信度/不知道就说 | 二次确认 |
| 双手忙 | 语音优先 | 指向交互 | 穿戴设备 |
| 长辈/视障 | 自动播报 | 远程家人协助 | 机构服务 |

假设测试（最便宜的先做）：

- 用 10 段真实视频 + 现有模型做「有证据 vs 无证据」对照，看用户信任度和纠错时间差多少。
- 用纸面原型做「3 步 vs 1 步」任务计时，看是否真的省事。
- 用假门测试（landing page + 预约）测「谁愿意留下联系方式试用」。

## 四、Mom Test 访谈提纲（只问过去，不问未来）

不要问：「你会用吗？」「你觉得这个想法怎么样？」「你愿意付费吗？」

要问：

1. 上一次你遇到「想看清/看懂某个东西但不方便掏手机」是什么时候？当时在做什么？
2. 你具体是怎么做的？拍了吗？用的哪个 App？花了多久？
3. 那一次最后解决了吗？没解决的话，你后来怎么办？
4. 过去一个月这种事发生了几次？哪一次最烦？
5. 你有没有为此装过什么工具、买过什么设备？花了多少钱？
6. 如果当时有人帮你看/读/操作，你希望他做到哪一步就够了？
7. 你有没有因为这个问过别人（家人/同事/客服）？他们怎么帮的？
8. 还有谁经常遇到这种事？能帮我引荐吗？

访谈对象：普通用户 10 人（做饭/带娃/开车/购物各 2–3 人）、视障或长辈用户 5 人、企业买家 5 人（电视/车厂/无障碍机构）。
记录方式：每场一页 interview snapshot（场景、原话、现有替代方案、花费、痛点强度）。

## 五、AI 产品的 eval 合同（Anthropic/OpenAI/Apple 的 eval-driven development）

在写第一行产品代码之前，先定义「什么叫做好」：

| 评测维度 | 门槛（先定，后调） | 测试集 |
|---|---|---|
| 任务完成率 | ≥85%（3 个场景分别统计） | 每场景 200 条真实轨迹 |
| 首次正确率 | ≥80% | 同上 |
| 「不知道」的准确率 | 该拒答时 ≥90% 拒答，不该拒答时 ≤5% 误拒 | 含 50 条对抗样本 |
| 证据可核对 | 100% 的关键结论能指出画面位置/时间点 | 人工抽查 |
| 延迟 | p95 ≤2.5 秒（首字/首答） | 端侧与云端各测 |
| 权限违规 | 0 次未确认的高风险动作 | 红队测试 |
| 打扰 | 主动提示被关闭后不再触发；误提醒率 ≤10% | 用户测试 |

规则：

- 评测是产品合同的一部分，不能等上线后再补；每个版本都要跑同一套 eval。
- 每周抽 30 条线上真实样本做人工复核，把失败拆成模型 / harness / 权限 / 执行器四类。
- 不用「看起来不错」当验收标准（vibe-based evals），也不让模型给自己打分。

## 六、30 天发现计划（把上面的方法排进日程）

| 周 | 动作 | 产出 | 决策门槛 |
|---|---|---|---|
| 第 1 周 | 15 场 Mom Test 访谈（普通 10 + 无障碍 5） | 机会树 v1、访谈快照 | 至少 3 个机会被 ≥5 人独立提到 |
| 第 2 周 | 3 个场景的纸质/模型原型，绿野仙踪测试 | 可用性与任务完成数据 | 首次成功率 ≥70% 才继续 |
| 第 3 周 | 证据 vs 无证据对照 + 定价访谈 | 信任度差、付费意愿分布 | 证据版纠错时间显著更短 |
| 第 4 周 | 5 个企业/OEM 买家访谈 + eval 合同定稿 | PR/FAQ v2、eval 基线 | 至少 2 家愿进入试点；否则回到机会树 |

## 七、这份方法改变了什么

1. **从「我推荐 harness 平台」改成「把 harness 平台当假设去验证」**：先做价值风险访谈，再决定要不要投入平台建设。
2. **从「看竞品在做什么」改成「看用户上一次实际怎么做」**：竞品功能不等于用户需求，Humane/Rabbit 就是反面证据。
3. **从「先做产品再评估」改成「先写 eval 合同」**：AI 产品的质量门槛必须在第一行代码前定义。
4. **从「功能清单」改成「目标结果 + 机会树」**：所有方案都挂在具体机会下，没被验证的机会不立项。
