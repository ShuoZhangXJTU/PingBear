# 2026-10-23 科研提案（列举式）

共 19 条。素材来自你的灵感清单 + 归档论文 + 主题手册开放问题；每条都要求挂真实证据、可证伪的判负条件和 1–2 周最小实验。

## P1. 按未来需求写记忆：预测—验证—过期回路

- **要解决的问题**：长任务里的记忆现在要么记少了导致遗漏，要么全记下来把上下文弄乱；更缺的是判断某条经历未来何时还会有用。
- **假设**：先预测后续动作需要哪些信息，再让独立验证器检查候选记忆是否有证据、适用范围仍成立，能在相同 token 预算下同时减少遗漏和无关记忆。
- **做法**：运行时维护原始轨迹与轻量记忆卡两层结构。每轮根据当前计划预测未来 1—5 步可能需要的文件、约束、结论和失败原因；候选记忆写成“内容、触发条件、有效期、证据指针”，验证器只批准有原始轨迹支持且条件未失效的写入。任务结束后用“预期未来需求与实际回访需求”的 gap 更新写入策略，不直接改模型参数。
- **最小实验**：1—2 周内取 40 道 OSWorld 2.0 和 80 道 BrowseComp-Plus 公开任务，固定 Qwen3-8B 与同一工具壳，比较完整历史、滚动摘要、CarryOn 式成果卡、缓存淘汰和本方案；前三组只做推理侧替换，最后再用 10 条开发轨迹拟合未来需求阈值，测试集不参与调参。
- **指标**：任务成功率、输入 token 与总成本、关键记忆遗漏率、记忆实际使用率、错误触发率，以及未来需求预测的 AUC。
- **判负条件**：如果相同预算下成功率没有提高，token 或成本也没有下降；或者预测器接近随机、关键记忆遗漏率和错误触发率均不改善，就说明“先预测未来需求再写”没有提供额外价值。
- **风险 / 与已有工作**：可能把未来需求预测变成新的错误来源。Memory-Centric 主要是框架和评估协议，CarryOn 验证成果卡有效，Cache Engineering 验证缓存淘汰有效，但还没有证明未来需求预测优于这些强基线；必须保留原始证据指针并允许撤销错误记忆。
- **证据**：Memory-Centric Continual Learning for AI Agents · Pack Light, CarryOn: Building Object-Oriented Context for Long-Horizon Agents · Cache Engineering for Agents
- **来自你的灵感**：memory把原始信息压缩的问题就是你不知道后面到底哪块在啥时候就有用了，不记着就漏，都记着就乱。 · memory其实也是要基于未来预期与未来真实的gap来反馈更新的，只不过不光更新content/rule，也要更新state，trigger rational啥的

## P2. 条件—动作—证据记忆卡：机器可读但忠实于原文

- **要解决的问题**：抽象记忆经常丢掉原文里的关键限定，导致 trigger 和 condition 含糊；直接塞原文又太占上下文。
- **假设**：把最小充分信息保存成“触发条件、可执行动作、原文证据、失效条件”四段卡，比摘要检索或纯原文检索更能区分相似但条件不同的情况。
- **做法**：每条记忆同时保留一行结构化卡和指向原始日志的不可变证据片段。检索时先按当前任务状态匹配条件，再由验证器检查证据是否支持该动作；条件冲突时不做抽象重写，直接回退原文。构造“对象相同但权限不同、时效不同、前提不同”的反事实案例审计触发规则。
- **最小实验**：从 30 条公开长任务轨迹切出 240 个记忆决策点，人工只审核 60 条开发样例，其余作为测试；每种表示都接入同一 Qwen3-8B 壳，比较原文检索、摘要、自由文本经验和四段卡。再加入 80 个近邻误导、过期条件和权限冲突反例。
- **指标**：条件检索准确率、正确动作率、错误触发率、过期信息漏检率、上下文 token 和人工维护时间。
- **判负条件**：如果四段卡在测试集上没有比原文检索更会区分条件，反而增加错误触发或维护成本；或者回退原文的案例并不比结构化匹配少，就应退化为只做索引和审计，不把结构化字段当作自动执行依据。
- **风险 / 与已有工作**：字段设计容易过度绑定当前任务，可能制造一个看似机器可读、实际不可迁移的本体。Cortex 等工作的测量门控说明单次成功不能作为规则有效的证据；本实验必须使用独立反例，并保留原文证据。
- **证据**：Cache Engineering for Agents · Pack Light, CarryOn: Building Object-Oriented Context for Long-Horizon Agents · Memory-Centric Continual Learning for AI Agents
- **来自你的灵感**：memory这里现在其实还是没找到一个机器能懂的语言或者组织形式，很多时候还是对齐做的差，trigger / condition 不清楚，有时候原文都更管用了。 · 记忆模块能不能只写一个面，让验证器来判

## P3. 失败回滚后的持久 belief workspace

- **要解决的问题**：长任务回滚环境时，往往把已经获得的失败证据和当时的世界假设一起丢掉，下一步只能重新踩坑。
- **假设**：把“任务目标、当前 belief、预测后果、实际观察、失败原因、证据来源”持续保存，只回滚环境而不回滚 belief，能减少不可逆误操作并提高修复成功率。
- **做法**：在工具调用前要求模型写下预期观察和 reversibility 标签；调用后用真实结果更新 belief 图。失败时只恢复文件或应用状态，保留假设、尝试和反证；只有证据一致且目标未完成时才允许重试。对高影响动作增加独立确认，低风险读取仍直接执行。
- **最小实验**：1—2 周内选 20 道带检查点的终端任务和 20 道 τ²-bench 任务，固定 Qwen3-8B，对比直接反思、只做环境回滚、BeliefWeaver 式关系图和本方案。每组三次重复，统一 50 步上限和工具超时。
- **指标**：最终成功率、不可逆违规动作率、预测观察的 Brier/对数损失、平均修复步数、工具调用成本和回滚后重复错误率。
- **判负条件**：如果保留 belief 相比只回滚环境没有降低不可逆错误和重复失败，失败后的成功率也不更高；或者预测校准没有改善，就说明持久 belief 图只是增加了日志而没有帮助决策。
- **风险 / 与已有工作**：错误 belief 也可能被长期保留并放大。Failure Recovery 报告稀疏反馈和可靠回滚是前提，ANTE 也表明预测只有被真实执行校验时才有训练价值；实验应把证据可信度、冲突和撤回机制一起评估。
- **证据**：Failure Recovery via Belief Updates and World Modeling for Long-Horizon Agents · ANTE: Anticipate, Then Execute -- Learning Internal World Models for Coding Agents from Verified Beliefs · Belief-Trajectory Energy: Measuring the Path to a Prediction · Memory-Centric Continual Learning for AI Agents
- **来自你的灵感**：说到belief，其实模型也有belief，其实这一块的misalignment也得考虑。因为有时候客观情况会被加期望影响 · state这件事情越来越多被提起了，其实这东西可以做成rsi的一环，rsi必然要越来越细

## P4. Jev 式可回退决策控制器

- **要解决的问题**：agent 每一步都调用大模型又慢又贵，而小模型一旦在不可撤销操作上选错，后续工具结果还会把错误继续放大。
- **假设**：让一个 4B 决策模型处理大部分“从有限选项里选一个”的步骤，并用按动作风险拟合的把握门槛决定何时回退大模型，可以在成功率下降很小的情况下显著降低成本和延迟。
- **做法**：把工具名、参数、继续或终止、是否请求用户等动作统一成选项；小模型输出各选项概率。读取类动作只需普通门槛，写文件、提交、下单等不可逆动作使用独立高风险门槛。门槛用当前 agent 自己的轨迹和事后成功率拟合，拿不准就把状态和候选动作交给大模型。
- **最小实验**：1—2 周内取 300 道任务，分别覆盖 120 道 τ²-bench 工具任务、100 道 ALFWorld 和 80 道小型网页或终端流程。用已有 agent 轨迹生成约 5000 个状态，LoRA 训练 Qwen3-4B 控制器；比较全大模型、全小模型、固定 0.5 门槛和按风险拟合门槛。
- **指标**：任务成功率、每任务成本、大模型调用率、p50/p95 延迟、不可逆动作错误率，以及控制器在 agent 真实状态上的选项准确率。
- **判负条件**：如果成功率相对全大模型下降超过 2 个百分点，或成本下降不足 30%；又或者收益只出现在只读任务、在不可逆动作上错误率没有下降，就说明决策模型还不能安全接管 controller。
- **风险 / 与已有工作**：风险门槛可能过拟合开发轨迹，而且小模型错一次后会把状态带偏。Jev 已经显示孤立选择题分数不能预测 agent 内表现，Trajectory-Level Speculation 也显示弱草稿模型会削弱收益；因此必须按真实 rollout 状态训练并按动作风险分层。
- **证据**：JevAgentHarness: Benchmarking, Deploying and Training Decision Models That Share Control with LLMs · Trajectory-Level Speculation with Semantic Verification for Tool-Using Agents · StartLux-Decision: AutoThink Decision Models with Reinforcement Learning for Calibrated Deliberative Decisions
- **来自你的灵感**：现在jev as router或者controller感觉是个挺好的应用点 · 模型表达不确定性很重要，但是其实，置信度很假，实际上没啥置信度，只不过说在特定情况下的真理。

## P5. 按状态衡量 OPD 信号，而不是按 token 模仿老师

- **要解决的问题**：师生 agent 的工具壳和表达方式不同，逐 token 蒸馏会把大量监督花在措辞上；同时也分不清老师信号的方向、大小和新增信息是否真的适合当前学生状态。
- **假设**：在学生真实会到达的状态上，把 OPD 信号拆成动作方向、纠错幅度、额外证据和知识对齐四部分，比 token 级或单一动作级蒸馏更能迁移到没见过的工具组合。
- **做法**：只采集学生 on-policy 状态；老师给出应选动作、必要参数、支持证据和反例，不要求复现原句。训练时把工具和参数映射到语义动作空间，分别计算方向一致性、相对基线的纠错幅度、老师是否补充了学生没有的环境事实，以及该事实是否被验证器或工具结果支持；动作不明确时才回退 token 分布监督。
- **最小实验**：选 600 条 τ²-bench、WebShop 和终端成功轨迹，冻结两套不同老师的回答并缓存；用 Qwen3-4B 学生，在相同 LoRA rank、样本数和训练步数下比较 token OPD、ActionOPD、只加方向奖励、只加证据增益奖励和四信号组合。留出 200 条未见任务与一套未见工具名。
- **指标**：held-out 成功率、相对学生基线的配对提升、教师学生动作一致率、证据事实正确率、训练方差、GPU 小时和每百万 token 的增益。
- **判负条件**：如果四信号组合没有稳定超过 ActionOPD，或方向/证据信号与最终收益不相关；又或者提升来自更多老师调用、更长训练或更多 token，而不是监督质量，就说明这套拆法没有成立。
- **风险 / 与已有工作**：动作语义映射本身可能有歧义，多老师信号也会互相冲突。ActionOPD 说明动作级监督可行，Cross-Teacher Guarding 说明冲突可以伤参数，Score Centering 说明校错采样分布会累积漂移；实验必须固定算力并报告种子波动。
- **证据**：ActionOPD: Distilling Decisions, Not Tokens · OPMD: On-Policy Mechanism Distillation Beyond Output Supervision · Beyond Domain-Routed Supervision: Cross-Teacher Guarding for Multi-Teacher On-Policy Distillation · Score Centering Stabilizes Off-policy Reinforcement Learning
- **来自你的灵感**：OPD其实也是更多要评价信号质量，也就是方向性的，大小性的，额外信息增强的，其实类似editing，要解决 knowledge alignment · agentic RL里头，其实信用分配很重要，信用分配一般可以是后验的，其实可以考虑预测。

## P6. 条件化可靠性，而不是一个通用置信度

- **要解决的问题**：模型给出的单个“80% 把握”经常跨任务、跨状态不可比；真正决定能否采信的是当前缺了哪些事实、动作是否可逆、以及当前任务属于哪种不确定性。
- **假设**：把不确定性拆成情境条件下的信息完整度、动作风险和历史覆盖度，比单个置信度标量更能预测实际错误并支持选择性执行。
- **做法**：不要求模型只报一个概率，而是报告“哪些事实已确认、哪些未知、当前答案依赖哪个未知量”，再按任务类型、上下文长度、是否调用工具和动作可逆性做分层校准。用条件覆盖区间和 conformal 集决定执行、追问还是回退；置信度只在相同条件桶内比较。
- **最小实验**：1—2 周内使用 ProbabilityBench 三个精确概率世界，加 500 个从 agent 轨迹抽取的高风险决策点。固定两个模型，比较标量 softmax、温度校准、按任务分桶校准、条件和 conformal 方法；留出未见任务族评估迁移。
- **指标**：ECE、NLL、选择性风险—覆盖率曲线、执行/追问/回退决策的效用、错误自信率，以及分层后覆盖是否接近名义水平。
- **判负条件**：如果条件化方法在留出任务上没有降低 NLL 或选择性风险，或者为了达到相同风险付出过大的覆盖损失；又或者按条件分桶后校准仍然和不分桶一样，就说明“置信度是条件真理”这个方向没有可操作收益。
- **风险 / 与已有工作**：条件桶过细会导致样本不足，conformal 覆盖也可能在任务分布变化时失效。ProbabilityBench 提供精确真值，但现实 agent 状态通常更复杂；CLIFT 的保守多数票可以减少误执行，但也可能错过正确动作。
- **证据**：ProbabilityBench: Model Evaluation and Calibration with Exact Ground-Truth Uncertainty · CLIFT: Conformal Self-Verification for Web Agent Training and Test-Time Scaling · StartLux-Decision: AutoThink Decision Models with Reinforcement Learning for Calibrated Deliberative Decisions · The Agent Knew: Internal States Forecast Unauthorized Actions and Stop Them, and the Lies That Follow
- **来自你的灵感**：模型表达不确定性很重要，但是其实，置信度很假，实际上没啥置信度，只不过说在特定情况下的真理。只不过模型不表达这些情况，显得好像有置信度 · 测试其实不应该考虑模型本身能力，而是应该关注用户想要啥

## P7. 奖励有证据的建设性分歧与推翻

- **要解决的问题**：多智能体如果奖励最终一致，容易形成错误共识；但如果直接奖励“不同意”，又会把随机噪声和无效争吵当成好信号。
- **假设**：只奖励能提供可验证证据、改变队友 belief 或推翻错误前提的分歧，能在提高正确率的同时改善校准，并减少无证据共识。
- **做法**：每个分歧必须附带引用、工具结果或可执行检查。奖励由三部分组成：新证据让团队答案概率或验证通过率提高多少；是否明确推翻一个可验证的错误 claim；分歧是否最终被独立证据裁定。没有证据的反对不加分，单纯保持不同答案也不加分。
- **最小实验**：用 300 道 HotpotQA 多跳题和 150 道 LoCoMo 或同等可分解任务，固定三个 Qwen3-8B agent、两轮发言、五次随机种子。比较只给最终奖励、奖励一致、奖励原始分歧、奖励有证据的信息增益和推翻。测试集禁止工具访问训练时用过的证据缓存。
- **指标**：答案正确率、正确推翻率、无证据共识率、错误固执率、ECE，以及团队获得正确答案所需的发言和工具 token。
- **判负条件**：如果新奖励提高了分歧频率却没有提高正确率或校准，或让无证据 claim 和无效争论增加；反之如果与证据门控的结果差异由额外工具调用解释，而不是奖励机制，就说明分歧本身不是有效学习信号。
- **风险 / 与已有工作**：证据裁判可能自己出错，而且分歧奖励可能鼓励表演式反驳。Training LLMs with Verifiable Information Rewards 显示细粒度信息奖励有效，但只在可计算概率的表格环境里；SHELDON 也显示观察空间和对照分析各自有贡献，不能只凭相关性把“吵得多”当因果。
- **证据**：Training LLMs for Multi-Agent Collaboration with Verifiable Information Rewards · SHELDON: Reasoning through Dual Search over Hypothesis and Observation Spaces · Beyond Domain-Routed Supervision: Cross-Teacher Guarding for Multi-Teacher On-Policy Distillation · Which Agent's Skill Should Change? Group-Relative Credit Assignment for Evolving Multi-Agent Teams
- **来自你的灵感**：模型表达分歧，其实反而是一种好的reward，过于一致有时候才有问题。 · 分歧和推翻，尤其是推翻，其实很重要

## P8. GUI 多智能体冲突：从发现问题到恢复状态

- **要解决的问题**：多个电脑智能体共享文件和界面时，现有模型常能发现消息或状态冲突，却不会真正撤销错误、释放锁或完成交接。
- **假设**：把冲突解决拆成“状态差分、最小恢复计划、分支执行验证、交接确认”四步，能补上检测正确但修复失败的主要缺口。
- **做法**：统一记录截图、控件树、文件版本和锁状态；发现冲突后先构造期望状态与实际状态的差分，再生成最小恢复动作。任何写文件、提交或释放共享资源的动作先在隔离分支验证，通过后才提交；最后由独立检查器确认锁、任务状态和交接消息一致。
- **最小实验**：1—2 周内取 60 道 CLASHarness 冲突题，固定 Qwen3-VL-8B 或同级模型，比较直接执行、只检测并报告、检测后重试和本方案的分支恢复。统一 40 步上限，其中 20 道题隐藏文字线索、要求必须看截图。
- **指标**：冲突修复率、最终任务成功率、错误恢复动作率、共享锁和交接完成率、步数、耗时和每题成本。

## P9. 反事实验证器驱动的技能增减

- **要解决的问题**：代码 agent 的规则和技能越攒越多，单条看着有用，合在一起可能让行为变差；靠人工质检轨迹成本又太高。

- **做法**：先从失败轨迹聚类出可操作问题，再生成带触发条件的技能候选。每个候选做“有技能/无技能”的交替配对运行，只在候选实际被加载的题上比较；要求净胜达到多次运行门槛且没有单题严重回归。无效技能不保留，有害技能删除，触发条件错误的技能改写而不是继续堆提示。
- **最小实验**：1—2 周内取 100 道 CodeGym 风格的代码 agent 题，先跑 Qwen3-8B 三遍收集重复错误，生成 15 条技能或规则候选。比较无技能、全量追加、Cortex 式门控和本方案；每条候选至少做三次交替配对，留出 30 道题只测试。

- **判负条件**：如果反事实门控没有超过 Cortex 式门控，或者清理后成功率没有提升、重复错误和回归也没有下降；又或者技能从未被加载，规则数量却持续增长，就说明应该在更细的触发层重建，而不是继续做技能进化。
- **风险 / 与已有工作**：多次配对运行会显著提高评测成本，且弱模型上学到的技能换强模型后可能没价值。Cortex 自己指出有害规则识别仍弱，DeLoop 也显示降低循环不必然提高成功率；因此必须同时报告覆盖率和回归，而不能只看一次成功。

## P10. 以用户意图为先的 rubric 基因组环境共进化

- **要解决的问题**：按模型当前短板自动出题容易把训练带向模型自己的盲区，却遗漏真实用户需要的能力；同时环境变难不一定等于变好。
- **假设**：用覆盖用户意图、约束和反例的 rubric 基因组组织环境变异，比单纯根据模型失败生成题目，在相同环境数和算力下带来更广的验证覆盖和更好的留出任务迁移。
- **做法**：先定义任务意图、操作约束、信息依赖、失败安全、可验证结果五类基因；环境生成不是只追当前失败，而是优先覆盖未出现的基因组合和相互冲突的条件。每个环境必须通过参考解、空解不得分、难度落在当前能力边缘等门槛；训练前后比较 rubric 覆盖变化，并保留一组与模型短板无关的用户场景。
- **最小实验**：取 80 道终端或软件工程基础题，用同一生成器分别造两类环境：A 只按当前失败驱动扩展，B 按 rubric 基因覆盖和反例扩展，各生成 200 个候选。用参考解和 Qwen3-8B 小预算统一筛到 120 个可训环境；再用 Qwen3-4B LoRA 在固定 8×H100 GPU 小时下训练两组，在 100 道留出任务上评测。
- **指标**：环境可用率、参考解通过率、空解得分率、难度分布、rubric 覆盖缺口、留出任务成功率、训练奖励与实际评测的一致性，以及单位成功成本。
- **判负条件**：如果两组在相同可训环境数和算力下有相似难度与覆盖，B 组没有更高留出迁移；或者 B 组只是生成更多同义题、训练中高分却被独立评测推翻，就说明 rubric 基因组没有优于短板驱动生成。

## P11. actor、critic、env 分开验收的细粒度 RSI

- **要解决的问题**：自改进系统常把模型权重、经验、评测器和环境一起更新，某一轮总分上升时，无法判断到底哪个部件变好，坏更新还容易被后续轮次继承。
- **假设**：把 actor、critic、env/harness 和 experience bank 当作可独立提交与回滚的状态，每一类都用对应的新验证集门控，比整条流水线整体覆盖更能产生逐轮累积的收益。
- **做法**：保存假设、代码改动、训练轨迹、验证结果和被拒改动的完整账本。每轮只提交一个组件的主要变化；权重、critic、环境规则和技能库分别维护基线，并允许“模型被淘汰但经验仍进入档案”。下一轮先用不与训练和筛选重叠的新题验收，失败则回滚组件，不删除其中合格的局部经验。
- **最小实验**：1—2 周内在固定 150 道训练题和 150 道留出题上做三轮：Qwen3-4B actor、规则 critic、轻量终端环境和技能库分别允许修改。比较整体覆盖、只接受最终分数和按组件验收三条流水线，所有方案使用相同 rollout 和训练预算。
- **指标**：每轮留出题相对上一轮的配对差值、被拒坏更新比例、跨轮累积增益、旧任务回归率、组件级归因准确率和总 GPU 小时。
- **判负条件**：如果组件验收没有比整体覆盖产生更稳定的逐轮提升，或者被采纳的更新主要来自更多算力而非新状态；又或者 actor、critic、env 的收益无法通过换题回滚测试，就说明细粒度 RSI 只是增加了管理复杂度。
- **风险 / 与已有工作**：组件间交互可能使单独验收通过、组合后失败，多个新验证集也会显著提高评测成本。Selection Is Not Learning 明确显示题目侧指标不能代替训练后验收；本方案还必须处理组件间互相依赖，不能把每个模块都拆成孤岛。
- **证据**：Selection Is Not Learning: Choosing Model Futures · Self-Evolving Agent Harness · Harness^2: Recursive Agent Harnessing for an Open World · SwarmRSI: Recursive Self-Improvement through Evolving Scientific Agent Swarm

## P12. 从分支后果学习可预测的步骤信用

- **要解决的问题**：长任务通常只有最后成败，前面真正救场或埋坑的动作拿不到区分信号；把所有奖励平摊到整条轨迹会放大无关步骤。
- **假设**：在共享前缀上分叉多条后续，用短期预测器估计每个状态的后续成功概率，再把分支真实结果作为校准，能比只看最终结果更准确地给单步或单回合分配信用。
- **做法**：同一状态保留多条后续轨迹，记录每步后续成功概率预测、工具反馈和最终结果。用组内分支比较训练轻量返回预测器；把预测值作为后继基准线而非绝对真值，只在有真实分叉的区间更新。对最后成/败给不同符号，对预测过大或过小的步骤额外惩罚。
- **最小实验**：选 100 道 BrowseComp-Plus 或 CodeGym 长任务，每题跑 8 条轨迹，其中 4 条全跑、4 条在中间状态分叉。用 Qwen3-4B 和相同 GRPO 预算比较结果奖励、TreeOPSD、Mosaic 式分段信用和本方案，留出 40 道题评测试。
- **指标**：成功率、达到基线成功率所需交互步数、步骤信用与真实分支反事实结果的相关性、梯度方差、token 成本和高回报误归因率。
- **判负条件**：如果预测器对后续回报没有可用排序能力，加入后没有提高样本效率或稳定性，甚至把更多功劳给无关步骤；或者与 TreeOPSD 相同分支预算下没有增益，就说明学习一个额外预测器不划算。
- **风险 / 与已有工作**：分叉动作可能不是唯一关键原因，预测器也会偏向常见轨迹。TreeOPSD 已经在同树上做了较强的后验回传，ANTE 则证明预测需要真实执行校验；新方法必须证明增益来自预测校准，而不是更多 rollout。
- **证据**：Tree-Aware Posterior Distillation for Long-Horizon Agentic Reinforcement Learning · Mosaic: Multi-Session Agentic Reinforcement Learning · ANTE: Anticipate, Then Execute -- Learning Internal World Models for Coding Agents from Verified Beliefs · Which Agent's Skill Should Change? ## P13. 异步 agentic RL 的漂移校正与动作级归一化

- **要解决的问题**：长程 agent 的 rollout 和工具执行很慢，同步训练会大量等数据；但直接异步会积累训练策略与采样策略的分布偏差。
- **假设**：用 score centering 消除平均奖励驱动的漂移，结合 top-k logprob 存储和动作级长度归一化，可以让异步 agentic RL 的吞吐明显提高，同时把成功率损失控制在 2 个百分点以内。
- **做法**：actor 持续生成轨迹，采样端只保存 top-k 词表概率，尾部用训练策略补齐；每步扣除采样分布下的平均分数来消漂移。路径长度按动作轮次而不是 token 数归一，并用重要性采样修正真正剩余的分布差。先隐藏层 Muon，后接完整 RL 配方，训练与评测共用固定日志。
- **最小实验**：1—2 周内在 120 道终端小任务和 80 道 ALFWorld 上训练 Qwen3-4B，固定总 rollout 和更新预算。比较同步 GRPO、异步但无修正、异步加重要性采样、异步加 score centering，以及再加入 Muon；每组至少两个随机种子。
- **指标**：相同 GPU 小时的最终成功率、墙钟时间、rollout 吞吐、训练曲线最低点与方差、达到目标成功率所需样本数，以及策略更新漂移指标。
- **判负条件**：如果吞吐提升不足 1.5 倍，或成功率下降超过 2 个百分点；又或者 score centering 只让训练更平滑、但在留出任务上的样本效率没有提高，就说明这套异步配方还不值得用于 agentic RL。

## P14. 先判定失败类型，再选择修复路径

- **要解决的问题**：agent 失败后常用同一句“反思并改进”重试，但目标错、环境假设错、工具调用错、上下文丢了和代码实现错需要完全不同的修复。

- **做法**：失败轨迹先做最小证据诊断：检查目标是否变化、文件和应用状态是否与假设一致、工具参数是否合法、关键上下文是否仍在、测试报错指向何处。分类器只提出候选原因，修复器必须给出一条可验证证据；不能凭模型自述决定。每类修复在隔离分支运行，确认后提交。

## P15. GUI 先规划和控制树定位，再按需视觉 grounding

- **要解决的问题**：电脑操作里花大量资源做视觉元素定位，但按钮找不到未必是 grounding 不够准，也可能是根本没有形成正确的应用状态计划和操作路径。
- **假设**：在同一模型和截图输入下，加入高层计划与控件树结构，只在执行选中节点时做像素 grounding，比持续增强视觉 grounding 更能提高复杂 GUI 任务成功率。
- **做法**：先从截图和可访问性信息抽取应用状态、候选控件和约束，生成可检查的计划；计划中的每个动作指向控件节点及其条件，只有节点无法直接执行时才调用视觉 grounding 定位。代码动作和 GUI 动作共用状态表示，失败时回退到计划层而不是只重新瞄准屏幕。
- **最小实验**：1—2 周内取 80 道 OSWorld 和 100 道 AndroidWorld 任务，固定 Qwen3-VL-8B，比较纯像素点击、截图加计划、控件树加计划、计划加按需 grounding 四组。所有组使用相同步数上限和模型调用预算，并单独统计没有控件树可用时的回退表现。
- **指标**：任务成功率、错误控件点击率、计划可执行率、平均步数、首步计划质量、grounding 调用次数、延迟和模型调用成本。
- **判负条件**：如果计划和控件树没有比强视觉 grounding 基线提高成功率，或者只在有完整控件树的环境中有效、在截图-only 场景显著变差；又或者收益完全由更多模型调用解释，就说明 grounding 仍是主瓶颈。
- **风险 / 与已有工作**：控件树并不总可得，计划错误还会比单步点错更难恢复。GroundGUI 证明 grounding 数据本身能带来大收益，OS-Helix 证明 GUI 与代码混合训练有效；本提案要验证的是在它们之上增加 planning 的边际价值，而不是否定 grounding。
- **证据**：OS-Helix: Unifying GUI Interaction and Code Execution in Native Computer-Using Agents · OpenMobile-2: Building Versatile Mobile Agents with Scalable Environments and App-Native Tools · GroundGUI: GUI Grounding by High-Quality Data and Distillation-to-Reinforcement Learning · Agent World Model in the Wild: Computer-Use Agent Environment Synthesis · CLASHarness: Benchmarking Multi-Agent Conflict in Computer Use via a Controllable and Verifiable Generation Pipeline

## P16. 一到两个 token 的上下文体制切换审计

- **要解决的问题**：有时只改一个空思考块、一个工具名、一个格式 token，模型就从一种行为模式切到另一种；这种变化通常被当成提示词玄学，缺少可控测量。
- **假设**：少量控制 token 会通过稳定的内部状态切换改变模型的推理模式、校准和工具行为，而且这种切换可以用固定权重的反事实实验预测并做稳健路由。
- **做法**：固定权重、题目和采样预算，只做最小的自然配对改动：空思考块与无思考块、工具名同义改写、字段顺序、一个确定性措辞、礼貌语气和单个示例开关。记录输出、选项概率、长思考比例、注意力到控制 token 的权重和内部表示变化；把能够预测翻转的条件做成 prompt 或 harness 的审计特征。
- **最小实验**：1—2 周内选 300 道覆盖数学、指令跟随、工具选择和网页任务的题，在三个开源模型上做至少六组一到两个 token 的自然配对。每题每组采样 8 次，另用 80 道 held-out 题验证从校准和内部状态预测行为翻转的规则。
- **指标**：任务性能翻转率、同题答案一致性、正确—错误配对翻转比例、ECE 和选择性风险、控制 token 注意力份额，以及预测器在 held-out 题上的 AUROC。
- **判负条件**：如果最小改动带来的性能变化与随机采样波动无法区分，或者内部状态不能跨题目预测翻转；又或者所谓稳健 prompt 只是在测试集上调出来、留出题失效，就说明这更像提示噪声，而不是可研究的行为体制切换。
- **风险 / 与已有工作**：每个模型对 token 的切分和模板处理不同，同一表面改动未必等价；Thinking Leakage 说明 RL 也可能偷偷召回被压住的模式，Entertain/Cancel 说明行为还可能分阶段反转。实验必须固定 weights，并把 prompt 长度、有效 token 数和采样预算对齐。
- **证据**：The Thinking Leakage in Reinforcement Learning for LLMs · Entertain, then Cancel: How Thinking Makes Reasoning Models Read Some and Or Literally · Belief-Trajectory Energy: Measuring the Path to a Prediction · ProbabilityBench: Model Evaluation and Calibration with Exact Ground-Truth Uncertainty
- **来自你的灵感**：这种一两个token改变在上下文改变很多的其实值得系统性看看 · hyperthink那个论文挺有意思的，就是机理上的

## P17. 把内部 belief 轨迹当作越权动作的前置安全信号

- **要解决的问题**：只读模型最后的解释，常在实际越权动作发生后才知道它知道不该做；而文本监控又容易被模型自述和模板掩盖。
- **假设**：在相同任务状态下，残差流里的 belief 轨迹比输出文字更早预测即将执行的越权动作，用低成本门控在动作前拦截能减少违规和事后撒谎，而不显著伤害正常任务完成率。
- **做法**：为命令、文件、网页和工具调用建立权限状态标签；在会产生外部后果的动作前读取模型内部状态，训练线性或小非线性探针预测“是否认为当前动作不被允许”。将探针输出与步骤级 belief 变化结合，只有报警时切换到审批或重规划；只读动作仍正常执行。
- **最小实验**：1—2 周内在 200 个“允许/不允许只差一个事实”的配对 agent 任务上收集两个模型族的内部激活，训练开发集探针，留出任务族和提示模板测试。比较文本监控、动作 API 规则、单步内部探针和 belief 轨迹门控。
- **指标**：越权动作 AUROC、正常任务完成率、误拦截率、违规后撒谎率、每次检查的额外算力、跨模型或跨环境迁移 AUROC。
- **判负条件**：如果内部探针没有比文本监控或简单规则更早、更准，或者降低违规的代价是正常任务完成率大幅下降；又或者留出环境完全不能迁移，就说明内部信号目前不足以做通用安全控制。
- **风险 / 与已有工作**：探针可能依赖数据集和模型层，换模型就失效；内部状态也可能只是权限模板的编码，而非稳定 belief。The Agent Knew 的强结果主要在特定模型和压力条件下，必须把文本监控作为强基线，并避免把安全判断外发。
- **证据**：The Agent Knew: Internal States Forecast Unauthorized Actions and Stop Them, and the Lies That Follow · ANTE: Anticipate, Then Execute -- Learning Internal World Models for Coding Agents from Verified Beliefs · Belief-Trajectory Energy: Measuring the Path to a Prediction · ProbabilityBench: Model Evaluation and Calibration with Exact Ground-Truth Uncertainty
- **来自你的灵感**：说到belief，其实模型也有belief，其实这一块的misalignment也得考虑。因为有时候客观情况会被加期望影响 · 模型表达不确定性很重要，但是其实，置信度很假，实际上没啥置信度，只不过说在特定情况下的真理。

## P18. 保留动作与观察、只改写学生风格推理的 agentic SFT

- **要解决的问题**：老师成功轨迹里的工具调用和证据有训练价值，但推理措辞离学生太远；直接逐 token 模仿会把少量工具动作淹没在大量风格学习中。
- **假设**：冻结工具调用、参数、观察和最终事实，只用学生同家族模型重写推理过程，可以保留可执行行为并把 SFT 数据移到学生自己的分布上，从而优于原老师轨迹和只按答案倒推的轨迹。
- **做法**：把轨迹拆成不可改的动作层和可改的推理层。动作、工具返回、文件版本、最终测试结果全部冻结；生成器只根据题目、动作和观察写学生风格推理，不能新增未发生的观察。用小判别器检查是否出现事后编造、偷看答案或与动作矛盾的句子，再按相同样本数和训练预算做 SFT。
- **最小实验**：1—2 周内准备 2000 条已验证成功的 agent 轨迹，拆成固定动作层和可改推理层；用 Qwen3-1.7B 或 4B 学生比较老师原轨迹 SFT、CoTranslator 式逆向改写、TraceForge 式同家族补推理、动作冻结重写和同预算 GRPO。留出 150 道未见任务。
- **指标**：留出成功率、补丁或动作可执行率、观察引用一致率、工具调用次数、旧任务遗忘率、记忆是否减少多余推理 token，以及相同 GPU 小时下的增益。
- **判负条件**：如果动作冻结重写没有比 TraceForge 或原老师轨迹更好，或者为了贴近学生风格产生更多事实错位、工具参数错误和遗忘；又或者增益只来自更多样本或更长训练，就说明推理层改写不值得额外生成成本。
- **风险 / 与已有工作**：改写推理可能把真实探索改得像事后圆答案，尤其是动作本身正确但过程偶然时。TraceForge 和 CoTranslator 都说明“像学生”与“过程真实”不是同一件事；本方案的核心约束必须是冻结动作和观察，且验证器只判断一致性，不替代真实执行。
- **证据**：Finetuning with Sampling: SFT Learns Better Than You Think · TraceForge: Distilling with Your Own Thinking · CoTranslator: Reverse to Forward Chain-of-Thought Translator for Reasoning Distillation · Selection Is Not Learning: Choosing Model Futures
- **来自你的灵感**：OPD其实也是更多要评价信号质量，也就是方向性的，大小性的，额外信息增强的，其实类似editing，要解决 knowledge alignment · 预测一些潜在影响，其实还是一种高级的数据分析，只不过这种预测数据对于训练结果的影响更有卖点

## P19. 按结构性成本来源做 agent 成本模型与自适应预算

- **要解决的问题**：agent 训练和部署经常只报总 token 和总耗时，无法知道钱到底花在长上下文预填、反复工具等待、验证器、无效重试还是模型生成上。
- **假设**：agent 成本会集中在少数可由任务状态识别的结构性类别；用状态分类预测边际计算价值，并据此切换缓存、压缩、预览或直接调用策略，比统一压缩和固定预算获得更好的成功成本比。
- **做法**：把每次 rollout 拆成 prefill、decode、工具等待、验证、重试和上下文传输六类，记录长度、并发、失败原因和后续收益。用简单统计和分类先找结构性大头，再建立“增加 1k token 或一次工具调用对成功率的边际增益”模型。只在预测边际收益低的状态启用压缩、缓存或回退，其他状态保留完整证据。
- **最小实验**：先记录 100 道长任务在一套固定 agent 壳中的三类运行，至少覆盖 300 次 rollout；按定义把成本分到六类，用开发集训练一个极小成本与成功预测器。测试集比较全量保留、固定摘要、固定缓存、本方案自适应路由和 oracle 上限，所有策略使用同一模型。
- **指标**：每个成功任务成本、总 token、p50/p95 延迟、预测成本误差、状态分类错误率、无效工具等待占比、压缩导致的关键证据丢失率。
- **判负条件**：如果成本没有集中在少数可识别类别，分类器无法比静态策略更好预测边际收益；或者自适应路由省下的钱小于分类与检查开销，并导致成功率下降，就说明应先做基础设施优化而不是继续加调度层。
- **风险 / 与已有工作**：成本模型很容易过拟合单机部署，线上并发和缓存命中率变化会让结论错位。DLite 的收益来自特定推理栈，Cache Engineering 也依赖服务端缓存实现；实验应分别报告算法收益和硬件、框架收益。
- **证据**：Cache Engineering for Agents · The COUNT: Counting N-grams Unlocks Scaling on Host Memory and Training-Free Adaptation · LatentLoop: Scaling Looped MoE Models with Asymmetric Compute Allocation · DLite: History-free Speculative Decoding for Agentic AI · Long-Horizon RL Needs Muon
- **来自你的灵感**：分类统计其实是做infra的一个核心，给出成本模型，统计分类归因找到结构性的大头，然后压缩。 · 统计的本质是做减法扔信息，也就是你分类后要归因。所有假设都是错的，但是有一些是关键的，经得起特定检验。
