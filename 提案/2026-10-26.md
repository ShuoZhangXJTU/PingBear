共 18 条。素材来自你的灵感清单 + 归档论文 + 主题手册开放问题；每条都要求挂真实证据、可证伪的判负条件和 1–2 周最小实验。

## P1. 按未来用途写入的可验证记忆

- **要解决的问题**：他关心的问题是：记忆压缩时不知道以后哪段信息会用到，全存会乱，删了会漏；现有 trigger 和 condition 又经常不清楚。
- **假设**：如果每条记忆同时保存证据指针、适用条件、失效条件和预测的未来使用场景，并由执行后的验证器决定保留和触发，那么在相同上下文预算下会比全量历史、摘要和普通检索更少漏用与误用。
- **做法**：先产生候选记忆，只提交一个处于激活状态的规范视图，同时保留指向原始证据的引用。验证器检查证据是否支持该条目，并在任务结束后比较“预期未来用途”和“实际是否被使用”，据此更新保留分数、触发条件和状态，而不是改写用户原文。
- **最小实验**：选 BrowseComp-Plus 的 100 题和 τ²-bench 的 100 个多会话任务，切成“先积累经历、后执行新任务”。主模型固定为 Qwen3-8B；只训练一个 1.5B 写入与触发判定器。比较全历史、固定摘要、BM25 检索和本方案，统一 8k 上下文预算。
- **指标**：后续任务成功率；记忆该写/该取的 precision 和 recall；无关记忆触发率；过期记忆误用率；总 token 和重复行动步数。
- **判负条件**：如果本方案在相同 token 预算下成功率不高于摘要或检索，并且触发 precision 和重复行动都没有改善，就说明按未来用途写入没有带来实际收益。
- **风险 / 与已有工作**：构建未来任务时容易泄漏后文信息；高 precision 也可能只是因少记而少错。它与 Memory-Centric 的开环框架相比，会增加一次验证开销，必须先证明能换回任务收益。
- **证据**：Memory-Centric Continual Learning for AI Agents · Failure Recovery via Belief Updates and World Modeling for Long-Horizon Agents · Cache Engineering for Agents · Pack Light, CarryOn: Building Object-Oriented Context for Long-Horizon Agents
- **来自你的灵感**：记忆模块能不能只写一个面，让验证器来判 · memory把原始信息压缩的问题就是你不知道后面到底哪块在啥时候就有用了，不记着就漏，都记着就乱。 · memory其实也是要基于未来预期与未来真实的gap来反馈更新的，只不过不光更新content/rule，也要更新state，trigger rational啥的

## P2. 把记忆表示成条件、证据和反例

- **要解决的问题**：他指出现有记忆缺少机器可理解的组织形式，trigger 和 condition 含糊，有时直接用原文反而更好。
- **假设**：把记忆写成“主张、原始证据、何时适用、何时失效、反例”的结构，并用反例持续校验，会比自由文本摘要提高适用判断准确率，而不牺牲原文可追溯性。
- **做法**：每条记录包含事实或动作、证据原片段、适用范围、排除条件、有效期和来源。系统只维护一个激活视图，但任何结论都能跳回原文。验证器同时检查正例是否命中、反例是否被错误命中，失败时缩小适用范围或冻结该记忆。
- **最小实验**：从 100 个长任务中抽 300 个决策点，为每点构造正例、近似例和冲突例。比较原文直塞、自然语言摘要、事实三元组和本方案。主策略固定不训练，只比较写入格式和检索判定。
- **指标**：适用判断 precision/recall；冲突例误触发率；检索后任务成功率；输入 token；从结论回到原始证据的命中率。
- **判负条件**：如果结构化记录在一半以上冲突例上仍误触发，或者没有任何格式稳定优于原文直塞，就说明“找一种机器可懂的记忆语言”这一方向在这批任务上不成立。
- **风险 / 与已有工作**：格式可能只是便于程序检查，不一定便于模型使用；人工构造反例也可能放大设计者偏见。它和 Memory-Centric 的资源约束观点一致，但尚未证明结构越丰富越好。
- **证据**：Memory-Centric Continual Learning for AI Agents · Failure Recovery via Belief Updates and World Modeling for Long-Horizon Agents · Belief-Trajectory Energy: Measuring the Path to a Prediction
- **来自你的灵感**：memory这里现在其实还是没找到一个机器能懂的语言或者组织形式，很多时候还是对齐做的差，trigger / condition 不清楚，有时候原文都更管用了。 · 记忆模块能不能只写一个面，让验证器来判

## P3. 用决策模型接管 agent 的局部控制

- **要解决的问题**：他看好 Jev 类决策模型做 router 或 controller，但孤立选择题分数无法代表真实 agent 中的控制效果。
- **假设**：让小型决策模型只在 agent 真实走到的状态上做局部动作选择，并在动作前置条件或证据不满足时退回大模型，会在成本与成功率之间优于每步都问大模型或固定阈值切换。
- **做法**：控制器读取目标、约束、候选工具动作、控件树和最近执行结果，选择下一动作或下一子流程。验证器检查该动作是否满足当前状态条件；只有证据冲突、前置条件不明或高风险动作才回退给大模型，而不是依赖单一概率阈值。训练数据包含真实失败后到达的状态。
- **最小实验**：在 τ²-bench 的零售和电信任务中选 250 题，用 Qwen3-4B 做控制器、Qwen3-32B 做回退专家。比较大模型每步执行、4B 全接管、固定概率阈值和本方案；三者共享同一工具运行时和最大交互步数。
- **指标**：任务成功率；每任务美元成本与大模型调用次数；端到端延迟；回退 precision；高风险动作前的漏回退率；同质量下的成本前沿。
- **判负条件**：如果本方案没有任何成本—成功率 Pareto 点优于固定阈值，或者回退成本抵消了全部节省，就说明 Jev 式控制器不适合作为这组任务的通用路由层。
- **风险 / 与已有工作**：小模型可能记住工具名而不理解状态，回退验证器也可能过松。JevAgentHarness 已显示孤立题名次会反转，因此必须用真运行时而不是离线选择题作最终判断。
- **证据**：JevAgentHarness: Benchmarking, Deploying and Training Decision Models That Share Control with LLMs · Trajectory-Level Speculation with Semantic Verification for Tool-Using Agents · LEV: Thinking Fast and Deep with Looped Decision Models · Pack Light, CarryOn: Building Object-Oriented Context for Long-Horizon Agents
- **来自你的灵感**：现在jev as router或者controller感觉是个挺好的应用点 · confidence很假，实际上没啥置信度，只不过说在特定情况下的真理

## P4. 规划与执行解耦的混合推理流程

- **要解决的问题**：他希望把 thinking before thinking 和 hybrid reasoning 引入 agent，让复杂判断多想、简单执行少耗，同时避免所有步骤都套长思维链。
- **假设**：把“制定和修订计划”与“逐步执行工具动作”分开，并只在预测后果不稳定或动作不可逆时增加内部计算，会比固定深度推理获得更好的质量—延迟前沿。
- **做法**：规划器先给出目标、约束和待验证分支；执行器只做当前动作选择。每个分支先预测自身风险与所需深度，简单分支早停，高风险分支多跑几轮隐藏迭代后再执行。保留一个语义任务模式，防止长思考把字面约束推得过窄。
- **最小实验**：在 ALFWorld 和 τ²-bench 各取 100 题，用同一 Qwen3-4B 实现直接行动、固定先规划、固定四轮内部迭代和本方案的动态深度。先用 1k 条公开轨迹训练轻量规划/执行适配器，再在留出任务评测。
- **指标**：相同延迟或 token 预算下的成功率；平均思考轮数；不可逆错误率；对同义改写和格式扰动的动作一致性；简单题与难题的分层收益。
- **判负条件**：如果动态深度从未超过最佳的固定深度策略，或者多轮思考只在计算预算增加时才涨分，就说明过程解耦没有改变 Pareto 前沿。
- **风险 / 与已有工作**：LEV 的材料提示循环结构需要在预训练阶段学会，事后加循环可能无效；长思考还可能改变语用解释。它和推理型 harness 的边界要先在小模型上验证。
- **证据**：LEV: Thinking Fast and Deep with Looped Decision Models · Entertain, then Cancel: How Thinking Makes Reasoning Models Read Some and Or Literally · OPMD: On-Policy Mechanism Distillation Beyond Output Supervision · DLite: History-free Speculative Decoding for Agentic AI
- **来自你的灵感**：我觉得现在agent里有那个过程解耦很重要，有人做了那个thinking before thinking很值得细看。另外加速类的hybrid reasoning agent · hyperthink那个论文挺有意思的，就是机理上的

## P5. 以动作意图为监督单元的训练

- **要解决的问题**：他提出的 actionOPD 想用意图而非整条输出作为监督单位，因为轨迹级奖励和 token 级模仿都可能抓不到真正的决策。
- **假设**：在学生自己走到的状态上对齐教师对“下一步意图”和“可用动作机制”的判断，再结合后续分支结果，会比 token 级 OPD 或只学成功轨迹更省样本并更能迁移。
- **做法**：把教师轨迹切成观察、查询、修改、验证、恢复等意图段；学生自己跑轨迹，教师只在这些决策状态上给出意图及操作机制的分布。损失集中在决策位置，并把同一前缀的不同后续结果作为后验权重，减少长工具输出对梯度的支配。
- **最小实验**：从 BrowseComp 和 SWE 工具轨迹中选 3k 条，训练 Qwen3-4B 学生。比较教师轨迹 SFT、普通 token OPD、只用最终成败的 GRPO 和意图级 OPD；三者在 200 道留出题上使用相同工具预算。
- **指标**：留出任务成功率；下一动作正确率；意图对齐率；平均工具步与 token；达到给定成功率所需训练样本数；跨任务族迁移。
- **判负条件**：如果意图级监督仅在训练分布上涨分、在留出任务族上不如 token OPD 或更贵，就说明“意图是更好的监督单元”没有得到支持。
- **风险 / 与已有工作**：意图标签容易由事后规则拼出来，可能把教师原本没有的因果结构强加给学生。OPMD 和 TreeOPSD 分别在数学推理与长程 RL 上有效，组合到 agent 上仍是新问题。
- **证据**：OPMD: On-Policy Mechanism Distillation Beyond Output Supervision · Tree-Aware Posterior Distillation for Long-Horizon Agentic Reinforcement Learning · Mosaic: Multi-Session Agentic Reinforcement Learning · Trajectory-Level Speculation with Semantic Verification for Tool-Using Agents
- **来自你的灵感**：actionOPD其实也类似，用意图当监督单元 · OPD其实也是更多要评价信号质量，也就是方向性的，大小性的，额外信息增强的

## P6. 先预测后果再行动的可验证状态模型

- **要解决的问题**：agent 常在没有核对环境后果时执行不可逆动作，失败后又丢掉之前获得的证据；单一置信度也不能说明它在哪个条件下可信。
- **假设**：若每次高影响动作前预测“执行后环境状态、工具输出或测试结果”，执行后用真实结果更新带证据范围的状态，并据此回滚或重排候选，会比事后反思和普通重试减少错误，同时提升恢复成功率。
- **做法**：维护结构化状态：当前目标、候选动作、预测状态变化、支持预测的证据、适用范围和验证结果。执行后在隔离副本或可回滚环境中对答案；不一致时撤销该分支并提升反证权重，而不是把一次失败直接写成永久规则。
- **最小实验**：在 OSWorld 风格任务中选 120 个可重置任务，加入一个小型状态预测器。比较直接执行、文本反思、固定重试和本方案；禁止读取最终检查器状态作为预测输入，只允许使用当前可见证据。
- **指标**：任务成功率；不可逆错误率；预测结果与实际结果的匹配率；恢复成功率和平均步数；每个状态预测的校准误差；额外延迟。
- **判负条件**：如果在相同工具步数和计算预算下，预测后行动没有降低不可逆错误或提高恢复率，或者预测准确率与最终成功无关，就说明状态模型只是额外开销。
- **风险 / 与已有工作**：预测器可能利用评测环境的稳定规律作弊，跨到新应用就不成立；Failure Recovery 的增益来自多个组件，尚未拆清各自贡献。必须与失败后直接重试做严格同预算比较。
- **证据**：ANTE: Anticipate, Then Execute -- Learning Internal World Models for Coding Agents from Verified Beliefs · Failure Recovery via Belief Updates and World Modeling for Long-Horizon Agents · Agentic World Action Models · Belief-Trajectory Energy: Measuring the Path to a Prediction
- **来自你的灵感**：mindact那个论文，我觉得挺值得工程参考的，抽chain of thought，搭环境，能不能有个world model有planning能力 · 说到belief，其实模型也有belief，其实这一块的misalignment也得考虑。

## P7. 一两 token 改动引起的决策敏感性分析

- **要解决的问题**：他想系统性研究为什么上下文里很小的改动会显著改变模型行为，以及这种敏感性是否意味着 harness 不可靠。
- **假设**：语义等价扰动不应改变动作，而数字、否定词、单位、权限和约束词等证据锚点的单 token 改动会集中导致动作翻转，并且这些翻转能预测后续失败。
- **做法**：先测量，不直接训练：对同一决策状态生成保持语义的格式扰动，以及只改一个数字、否定词、单位或工具参数标签的语义扰动；记录下一动作、隐藏状态路径和最终结果。再加入规范化与一致性损失测试能否减少无关翻转。
- **最小实验**：从 BrowseComp-Plus 和 OSWorld 轨迹抽 400 个动作状态，每点生成 5 个语义等价扰动和 5 个单字段关键扰动。比较动作翻转、隐藏层预测变化与真实下游成败；再用 200 点训练一个小的一致性适配器。
- **指标**：语义等价扰动的动作翻转率；关键字段扰动命中率；扰动敏感度预测下游失败的 AUROC；适配后的成功率、校验调用数和额外 token。
- **判负条件**：如果语义等价扰动与关键字段扰动造成的翻转率没有差异，或翻转不能预测下游失败，就说明“关键 token 驱动行为不稳定”的解释站不住脚。
- **风险 / 与已有工作**：构造扰动时容易改变任务本身；隐藏层指标也可能只反映措辞。Entertain 的材料来自语言理解实验，迁移到 agent 决策需要重新验证。
- **证据**：Entertain, then Cancel: How Thinking Makes Reasoning Models Read Some and Or Literally · Score Centering Stabilizes Off-policy Reinforcement Learning · Cache Engineering for Agents · Belief-Trajectory Energy: Measuring the Path to a Prediction
- **来自你的灵感**：这种一两个token改变在上下文改变很多的其实值得系统性看看 · 统计的本质是做减法扔信息，也就是你分类后要归因。

## P8. 用 rubric 做轨迹质检和修复训练

- **要解决的问题**：轨迹质检高度依赖人工，而单次 LLM 判断容易漏掉伪造执行、目标漂移和过早停止。
- **假设**：把轨迹完整性检查拆成可追溯到日志的 rubric，并由独立验证器引用具体步骤判断，会比一个总分裁判更可靠地找出坏轨迹，并能直接生成重试和训练信号。
- **做法**：检查项覆盖目标是否完成、工具调用是否真发生、数字能否回到日志、约束是否满足、失败后是否错误收尾。每条缺陷必须附步骤编号和证据；失败的轨迹交给修复器，只有修复后的证据重新通过检查才进入训练池。
- **最小实验**：收集 300 条失败和 150 条成功 agent 轨迹，人工标 90 条作验证。比较人工、标量 LLM 裁判、成对裁判和 rubric 验证器；随后用被接受轨迹与直接重试各做一次 4B LoRA。
- **指标**：缺陷识别 macro-F1；假放行率；缺陷证据定位准确率；修复后成功率；训练后留出任务增益；每条轨迹的评审成本。
- **判负条件**：如果 rubric 验证器在人工标注上没有明显优于标量裁判，或它选择的轨迹在训练后不能提高留出表现，就说明质检规则还没有成为有效监督。
- **风险 / 与已有工作**：验证器会学习讨好 rubric，出现“按规则写得像通过”；人工标签也可能有争议。它比 Selection Is Not Learning 的整轮验收更细，但不能替代最终冻结测试。
- **证据**：Into the Unknown: Benchmarking AI agents on open scientific research problems · CLIFT: Conformal Self-Verification for Web Agent Training and Test-Time Scaling · Selection Is Not Learning: Choosing Model Futures · FC-SWE: Failure-Conditioned RL for Long-Horizon Software Engineering Agents
- **来自你的灵感**：轨迹质检其实人工依赖很大，但是实际上rubrics那个能力应该是能建设到上头的 · 分歧和推翻，尤其是推翻，其实很重要

## P9. 把有证据的分歧作为信用信号

- **要解决的问题**：他希望利用模型分歧，但过于一致有时才有问题；难点是不能把随机噪声或故意少数派当成好信号。
- **假设**：只在对具体主张和证据有分歧时保留少数意见，并把这种分歧与同题分支结果结合，会比多数投票更准确地预测失败分支和分配信用。
- **做法**：让多个评审使用不同 rubric 或上下文看同一条轨迹，先对齐它们争论的具体主张，再计算证据重叠和冲突强度。分歧大时增加采样或降低该分支信用，但不用“越不一致越好”作目标；最终仍要求反证和可执行检查。

## P10. 让 actor、critic 和环境一起做 RSI

- **要解决的问题**：只优化 actor 容易把固定奖励和环境漏洞学进去；他提出 actor、critic、env 要一起自我改进，但现有工作多只改其中一部分。
- **假设**：把策略、评分器和环境生成器作为独立版本共同演化，并在每轮用新的留出题和独立有效性检查接收改动，会比只更新 actor 获得更好的跨环境迁移并减少 reward hacking。
- **做法**：把改动拆成 actor 基因、critic/rubric 基因和环境/任务生成基因。每轮只提议一小批变化，交叉组合评估；评分器改动必须与 actor 改动分开验收，新任务要经过可执行、非初始完成和证据判分检查。坏版本保留历史但不得进入下一轮。
- **最小实验**：用 OSWorld 的子集 120 题和 BrowseComp 类 100 题，各跑 3 轮小规模 RSI。比较 actor-only、actor+critic、三者共同演化；actor 用 4B 或 8B，所有轮次共享冻结的保留测试集和独立有效性检查。
- **指标**：新留出环境上的成功率；原环境回归幅度；reward hacking 率；评分器与用户意图一致率；每轮有效训练小时；被拒绝改动的比例。
- **判负条件**：如果三基因共同演化没有提高新留出成绩，或提升只出现在自己生成的任务和评分器上，就说明联合 RSI 只是把漏洞一起放大。
- **风险 / 与已有工作**：变量同时变动会让归因困难，两周一版实验可能算力吃紧。它与 Harness Scaling 的受控变化、WildAWM 的可执行环境筛题应结合，严格保留新鲜测试。

## P11. 以有效任务吞吐衡量 RSI 基础设施

- **要解决的问题**：他认为流程加速和评测是 RSI 的关键，但常见指标是 token/s 或单次延迟，未必代表一轮能多产生多少可信训练信号。
- **假设**：对 RSI 更有预测力的是“单位时间通过的、与留出集独立的有效任务数”，而不是原始推理吞吐；只有正确性和任务分布保持稳定时，缓存或推测解码的提速才会转化成 RSI 进展。
- **做法**：把生成、工具等待、验证、环境重置、训练和评测拆开计时，记录每个环节的浪费。比较普通生成、KV 缓存复用、推测解码和两者组合在完整闭环里的有效产出，并检查任务是否通过独立有效性门。
- **最小实验**：在 120 个可重置任务上做 1 周 profiling，接普通、缓存、推测和组合四种服务；每种跑 2 轮 mini-RSI，模型与数据预算固定。记录任务生成、验证、重置、训练的占比，并做端到端成本模型。
- **指标**：每 GPU 小时的有效任务数；端到端延迟和输出吞吐；留出集质量；无效/不可执行任务比例；两轮后的相对提升；各环节成本占比。
- **判负条件**：如果原始 token 吞吐和端到端有效任务吞吐对两轮提升的预测能力相同，或提速配置没有在质量不降的情况下增加有效任务，就说明“先做 infra 提速”不是当前主要杠杆。
- **风险 / 与已有工作**：测量可能被单机、单模型和缓存命中率绑死；缓存收益也可能只在重复前缀多时成立。该提案研究基础设施与 RSI 的因果关系，不会直接把吞吐提升等同于能力提升。

## P12. 把失败诊断反写成语料新题

- **要解决的问题**：失败轨迹很有价值，但直接重放可能反复学同一个环境怪癖，甚至把错误原因一起学进去。
- **假设**：先从可验证失败中抽出“操作意图与真实后果不一致”的原因，再反写出新的可执行题，并用独立验证器检查题目真实、可解且未见过，会比原始失败重放带来更好的留出迁移。
- **做法**：从失败补丁或日志中抽取触发条件、错误状态和可观测后果；倒推生成新任务，任务和修复方案必须能执行，且不能只改变注释或测试。训练时保留原失败证据和反证，生成器与验收器分离，防止自己出题自己判。
- **最小实验**：从 300 条已验证失败的终端或 SWE 轨迹出发，每条生成一个新题。经可执行、初始未解、唯一性和不同修复方案检查后，比较失败重放、普通合成题和本方案继续训练 Qwen3-4B，一次训练后在 150 个未见任务上测。
- **指标**：留出任务成功率；失败模式复现率；题目可执行率和可解率；重复题比例；训练后回归幅度；从失败到修复的步骤数。
- **判负条件**：如果反写题没有比失败重放提高留出成功率，或者提升集中在生成器重复使用的同一模式上，就说明它只是在扩充相似样本。
- **风险 / 与已有工作**：失败反写可能制造现实中不会出现的规则；验证器也可能把原轨迹风格当真实性。Terminal-RSI 和 SWE-at-Scale 已覆盖部分路径，本提案必须用独立留出测试证明不是数据量增加。

## P17. 用可回滚状态账本管理 harness 自进化

- **要解决的问题**：harness 的提示词、记忆、流程、工具代码和评分器都能改，但变化混在一起后很难知道哪次修改造成收益或回归，他提出 state 本身也应成为 RSI 的细粒度对象。
- **假设**：把每种可变状态单独版本化，记录父版本、改动证据和适用范围，并采用单基因修改、新鲜题验收和影子重放，会比直接接受整轮 harness 修改减少坏提交，并提高后续迭代效率。
- **做法**：状态账本分别记录系统提示、技能包、记忆条目、控制逻辑、工具实现和验证器；每次更新只允许少量基因变化，保留可回滚快照。候选版本先在旧轨迹影子重放，再到全新留出任务与当前版本比较；用户手写内容和已确认标签不进入自动改写范围。
- **最小实验**：在一个现有 agent harness 上跑 3 轮，每轮 150 题。比较无账本整轮替换、固定回滚点和状态账本；每轮只改一类状态，记录更新前后在旧题、新题和用户约束上的表现。
- **指标**：新留出成绩；坏提交比例；回滚次数和恢复时间；改动到实际回归的归因准确率；无关状态是否被误改；每轮有效迭代时间。
- **判负条件**：如果状态账本没有降低坏提交或恢复成本，甚至在可归因性变好时让开发速度显著变慢，就说明把 state 细粒度版本化不值得作为默认机制。
- **风险 / 与已有工作**：账本可能只增加工程开销，不能证明科学假设；状态之间还会相互依赖，单基因修改可能掩盖组合效应。Self-Evolving Harness 的理论条件仍未在复杂生产环境中验证。
- **证据**：Self-Evolving Agent Harness · Harness Scaling for Generalizable Agentic Reinforcement Learning · Evolving with Open Worlds: Towards Recursive Self-Improvement for Future Forecasting · Memory-Centric Continual Learning for AI Agents · DiscoveryRSI: Recursively Learning to Discover Valuable Hypotheses
- **来自你的灵感**：state这件事情越来越多被提起了，其实这东西可以做成rsi的一环，rsi必然要越来越细 · 就是得ACE一起RSI，actor，critic，env。

## P18. 反例优先的科研假设评审器

- **要解决的问题**：开放科研 agent 会写出像样但未经真实执行的论文；他想强调分歧和推翻，而不是只让多个模型互相赞同。
- **假设**：让评审器把假设拆成可验证主张，主动生成反例和失败条件，并要求每个结论有日志证据，会比通用评分或多数票更早识别不可靠研究方案和错误轨迹。
- **做法**：从提案抽取假设、关键机制、预期结果和最小实验；为每个主张生成能被推翻的检查项，先寻找反证，再区分“日志已证明”“只是推断”和“材料没有”。多评审只在具体主张上争论，禁止用整体文风或多数一致替代证据；推翻后要求重写假设或实验。
- **最小实验**：从 20 篇归档论文构造 100 个后续研究提案，其中一半注入未执行实验、错误数字或缩小任务范围的缺陷；另 20 个由作者人工确认。比较通用评审、多模型多数票和本反例评审器，再让 3 名同行抽样复核。
- **指标**：发现不实主张和伪造执行的 precision/recall；对正确提案的误杀率；主张到日志证据的可追溯率；推翻后修订质量；每次评审成本。
- **判负条件**：如果反例评审器相比通用评审没有提高缺陷识别，或主要靠提高拒稿率换 precision，就说明“主动找推翻”没有形成更好的研究判断。
- **风险 / 与已有工作**：评审器可能用表面反例压掉新颖但暂时证据不足的想法；人工标注成本也高。它和 DiscoveryRSI 的可证伪性目标一致，但必须把“提出反例”和“真的验证反例”分开。
- **证据**：Into the Unknown: Benchmarking AI agents on open scientific research problems · DiscoveryRSI: Recursively Learning to Discover Valuable Hypotheses · Selection Is Not Learning: Choosing Model Futures · CLIFT: Conformal Self-Verification for Web Agent Training and Test-Time Scaling
- **来自你的灵感**：分歧和推翻，尤其是推翻，其实很重要 · 所有假设都是错的，但是有一些是关键的，经得起特定检验。而且关注反转、成立等条件，对已知保持审慎
