# 2026-10-16 科研提案（列举式）

共 6 条。素材来自你的灵感清单 + 归档论文 + 主题手册开放问题；每条都要求挂真实证据、可证伪的判负条件和 1–2 周最小实验。

## P1. 把记忆的触发条件写成能被验证器判真假的谓词

- **要解决的问题**：记忆条目用自然语言写「什么时候该用」，trigger / condition 模糊；按相关性检索出来的记忆经常不适用，模型有时不如直接看原文。
- **假设**：如果每条记忆的适用条件写成可执行、能判真假的谓词（而不是描述性文字），并在注入前由一个小验证器逐条判过，记忆误用率会明显下降、长任务成功率上升。
- **做法**：记忆条目拆成三段：原始证据指针、结论/规则、适用条件谓词。适用条件写成可判定的形式（字段比较、状态检查、可运行的小测试），注入前用便宜验证器（规则加小模型）判定，不通过就不注入；信用分配只记在「谓词为真且真被用上」的步上。
- **最小实验**：拿 CL-Bench 风格或 ReHarness 的多轮设置，人工把 200–300 条现有记忆的「什么时候用」改写成谓词，跑三组：(a) 整段历史全塞 (b) 只按相关性检索 (c) 加谓词验证；同一模型、同一 token 预算。
- **指标**：记忆误用率（注入后导致错误动作的比例）、任务成功率、每步注入 token 数。
- **判负条件**：若加谓词验证后误用率和成功率与「只按相关性检索」没有显著差别，或谓词通过率高于 95% 而错误率不变，说明瓶颈不在触发条件。
- **风险 / 与已有工作**：很多适用条件是连续、主观的，写不成谓词，标注成本高。与 Relevance Does Not Imply Applicability 的逐画面重挑结论有重叠，增量必须落在「把适用性显式化成可验证对象」而不是隐式重挑。
- **证据**：Relevance Does Not Imply Applicability: Experience Activation for Personal GUI Agents · Recurrent Harness for Agentic Continual Learning · Learning How to Remember: Memory Modality Selection for GUI Agents
- **来自你的灵感**：记忆模块能不能只写一个面，让验证器来判 · memory这里现在其实还是没找到一个机器能懂的语言或者组织形式，很多时候还是对齐做的差，trigger / condition 不清楚，有时候原文都更管用了。

## P2. 用「预测的未来需求 vs 真实需求」的差距去更新 state 和触发条件

- **要解决的问题**：记忆压缩的难点是不知道后面哪块信息什么时候有用：不记就漏、都记就乱；现在的更新只改内容，不根据预测失准去改状态和触发条件。
- **假设**：用「预测后面会用到哪些记忆」与「实际用到哪些」之间的差距当反馈，去更新状态表示和触发条件（而不只是改内容），能在相同上下文预算下提高长任务成功率。
- **做法**：训一个轻量预测器，从当前状态预测后续 K 步需要哪些记忆条目，标签用真实后续使用记录；每轮用预测-实际 gap 做三件事：改记忆内容、改状态表示、改触发条件；对照只更新内容不更新触发条件的版本。
- **最小实验**：选一个长任务（ALFWorld 长轨迹或 Terminal-Bench 的 20–30 个任务），先标注「哪条记忆在后续真被用到」，训一个小预测器（MLP 或 0.5B 模型），再用它决定每步加载哪些记忆；对照组只更新内容。
- **指标**：后续 K 步内真正需要的记忆的召回率与精确率、任务成功率、注入 token 数。
- **判负条件**：若预测器对「后面会用到哪条记忆」的排序 AUC 接近 0.5，或据此更新状态/触发条件不能提高成功率，则「记忆压缩本质是 planning」这条不成立或不可操作。
- **风险 / 与已有工作**：「后来真的用上了」这个标签很难客观定义，容易退化成检索 rerank 换个名字。预测状态那篇只在 3 维合成序列上验证，迁移到真实 agent 无证据。
- **证据**：Recurrent Harness for Agentic Continual Learning · Generative sequence modeling for infinite memory processes via predictive states · Stateless Language Agents: Scaling Long-Horizon Automated Research · Balancing Memory Pathways: Analyzing and Improving Memory Utilization in Hybrid LMs
- **来自你的灵感**：memory把原始信息压缩的问题就是你不知道后面到底哪块在啥时候就有用了，不记着就漏，都记着就乱。这其实是一种planning能力，如果能够判断未来所需。memory其实也是要基于未来预期与未来真实的gap来反馈更新的，只不过不光更新content/rule，也要更新state，trigger rational啥的

## P3. 把 state schema 也放进 harness 自动搜索的空间里

- **要解决的问题**：现在 harness 自改进只动提示、控制流、工具和上下文管理，agent 的状态定义和记忆字段是写死的。
- **假设**：把 state schema（有哪些字段、状态怎么定义、什么时候写）也当成可编辑对象一起搜索，开放世界留出基准上的增益会大于只搜索代码与提示。
- **做法**：在 Harness^2 / RRSI 的循环里加一类编辑：state schema 的字段增删与写入时机；沿用同一任务的对照执行判优劣，并用噪声门限与泄题检查防过拟合。
- **最小实验**：在一个工作台基准的开发集上跑两个搜索空间：A 只改提示/控制流，B 加 state schema 编辑；同 token 预算各搜 10–15 轮，留出集不少于 3 个。
- **指标**：留出集分数（非同源基准）、每轮 token 成本、涨分是否落在开发集之外。
- **判负条件**：若 B 组留出集不比 A 组高，或 B 只在开发集涨、留出集掉，说明放开 state 搜索不是有效方向。
- **风险 / 与已有工作**：与 RRSI 高度相关，增量必须说清是「搜索空间多了一类对象」。空间变大后过拟合和 token 成本都会失控。
- **证据**：Harness^2: Recursive Agent Harnessing for an Open World · RRSI: Regularized Recursive Self-Improvement of Agent Harnesses · Recurrent Harness for Agentic Continual Learning · RSI-Anything: Unlocking Recursive Self-Improvement with World Models
- **来自你的灵感**：state这件事情越来越多被提起了，其实这东西可以做成rsi的一环，rsi必然要越来越细 · 就是得ACE一起RSI，actor，critic，env。小米那论文也是这个意思，

## P4. actor / critic / env 一起改：把出题和判分也拉进自改进循环

- **要解决的问题**：自改进多在改 actor 或 harness，练习环境和判分器固定；判分器放久会被钻，题目池很快饱和。
- **假设**：让 env（出题加判分器）和 critic 与 actor 同步演化、并让判分器钉在 agent 看不到的底稿上，同算力下留出基准的分会高于只改 actor，且判分器被钻的比例不上升。
- **做法**：用「底稿倒着造题 + 稠密进度奖励」起一个小环境池；每轮按 actor 的失败分布造新题并更新 critic；判分器挂在 agent 读不到的参考实现上；另留一个冻结审计集专门抓钻空子。
- **最小实验**：造 100–200 个可自动判分的短任务环境做池子，跑两组：A 固定池加固定判分器；B 每轮按失败分布加 20 道新题并更新 critic。同一 actor、同一 token 预算。
- **指标**：留出基准通过率、判分器在冻结审计集上的误判率、单轮 wall-clock。
- **判负条件**：若 B 组留出集不高于 A 组，或冻结审计集上的误判率随轮次上升，说明协同演化没有净收益。
- **风险 / 与已有工作**：造环境成本高，1–2 周只能做很小规模；critic 和 env 一起改容易互相掩护，必须有独立审计集。
- **证据**：Tev: Scaling Long-Horizon Agentic Environments with Dense Progress Rewards · WorkRover: Scaling Long-Horizon Cowork Agent Training Via Recursive Environment Evolution · RSI-Anything: Unlocking Recursive Self-Improvement with World Models · A Cheap Verifier is Good Enough: LLM Post-training is Robust to Erroneous Rewards
- **来自你的灵感**：就是得ACE一起RSI，actor，critic，env。小米那论文也是这个意思， · 流程做快和评测其实是RSI的关键，快速迭代+可验证的环境和反馈测试才能保证最终的scaling RSI。

## P5. 迭代速度是不是 RSI 的乘数：先量一条「每 GPU 小时能力增益」曲线

- **要解决的问题**：大家都说流程要做快、环境要可验证，RSI 才转得起来，但没人量过「快多少」到底换成「涨多少」。
- **假设**：在固定总算力下把单轮反馈延迟减半，单位算力的能力增益提升会超过线性，即迭代速度是乘数而不是可互换的资源。
- **做法**：同一套自改进循环跑三种单轮延迟（同步等全部 rollout、流式边到边训、提前预取评测），其余全部固定，画能力 vs GPU 小时曲线。
- **最小实验**：小模型加一套 100 道可自动判分的终端/代码题，三档延迟配置各跑同样 48 步，每 6 步打一次留出评测，记录累计 GPU 小时。
- **指标**：能力增益 / GPU 小时（效率曲线斜率）、达到同一分数所需 wall-clock。
- **判负条件**：若三条能力-算力曲线基本重合，说明瓶颈不在延迟，加速只是省时间不换分数。
- **风险 / 与已有工作**：加速通常伴随样本质量和批大小变化，因果难拆；这种实验吃算力，1–2 周只能给代理结论。
- **证据**：How to Measure RSI · QwenGyre: An Elastic Reinforcement Learning Framework for Training xLong-Horizon Agents · Tev: Scaling Long-Horizon Agentic Environments with Dense Progress Rewards · Speculative Evaluation of Stochastic LLMs
- **来自你的灵感**：流程做快和评测其实是RSI的关键，快速迭代+可验证的环境和反馈测试才能保证最终的scaling RSI。

## P6. 把模型之间的分歧当奖励，但得分清是洞见还是无能

- **要解决的问题**：一致性好不等于答对，模型之间过度一致反而可能是问题；但分歧也可能只是集体犯错。
- **假设**：只有在分歧能被外部证据仲裁的任务上，用多份采样的分歧当奖励才优于只看结果；在没人能仲裁的任务上，分歧奖励会退化成噪声或被钻。
- **做法**：在可精确算概率的表格自博弈环境里，把奖励从结果换成分歧加权结果（分歧大且最终被证据支持的那条加权更高）；同时在双 agent 互评环境里监控合谋率，把「分歧奖励」和「减少合谋」两种效应显式分开。
- **最小实验**：用 HiddenBench 式表格环境跑三组奖励：纯结果、结果加等量随机噪声、结果加分歧加权；再在一个开放式写作或研究任务上重复，比与人类偏好的相关。
- **指标**：留出任务正确率、与人类偏好排序的相关、合谋检出率。
- **判负条件**：若分歧加权与「结果加等量噪声」表现无差别，或分歧稳定地被模型用来刷互评通过率而真实正确率下降，则这条被推翻。
- **风险 / 与已有工作**：分歧可能来自无能而不是洞见；这与「减少合谋」的方向直接冲突，两个方向的张力必须在实验里显式对照，不能只报有利的一面。
- **证据**：Training LLMs for Multi-Agent Collaboration with Verifiable Information Rewards · Evaluating LLM Creativity through Long-Tail Performance · Emergent Collusion in Long-Horizon LLM Agent Interaction · Open-Endedness Bench: Measuring Epistemic Process from Agent Records
- **来自你的灵感**：模型表达分歧，其实反而是一种好的reward，过于一致有时候才有问题。这个在测评中其实可以多考虑 · 分歧和推翻，尤其是推翻，其实很重要
