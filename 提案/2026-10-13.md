# 2026-10-13 科研提案（列举式）

共 3 条。素材来自你的灵感清单 + 归档论文 + 主题手册开放问题；每条都要求挂真实证据、可证伪的判负条件和 1–2 周最小实验。

## P1. 记忆只写一个面，入库交给可重放验证器判

- **要解决的问题**：现在智能体记经验时是自己判断该不该记，一次失败就可能被写成一条通用规则，之后换任务还在生效；而且条目里的触发条件写得含糊，模型不知道什么时候该用。
- **假设**：让写记忆的模型只输出一条单面断言（条件→动作），不入库，由独立验证器在可重放的环境前缀上跑一遍再决定收不收，能同时降低错误入库率并提高跨轮成功率。
- **做法**：写手只产出「触发条件 + 动作 + 来源轨迹片段」三件套，不做取舍判断；验证器照 EVISKILL 的做法重建任务前缀、跑加了这条改动的动作，返回接受/修正/拒绝三档；没过的进暂存账本留到下一轮用新轨迹再比，过期条目按 ACE 的教训做成一次性提醒而不是常驻规则。
- **最小实验**：选 ALFWorld + ScienceWorld，骨干 Qwen3-8B，同一套 harness 只换记忆模块，跑三组：(a) 不留经验 (b) 模型自判入库、总结成规则 (c) 单面写入 + 重放验证器。每组三个周期，每周期用同一批任务前缀，同 token 预算，两卡以内两周能跑完。
- **指标**：每周期 held-out 成功率、错误入库率（入库后被回放判负的比例）、触发条件误触发次数、每条记忆的取用 token。
- **判负条件**：如果 (c) 的 held-out 成功率不高于 (b)，或者错误入库率降了但成功率不涨（说明验证器只是在删有用条目），这个想法就不成立。
- **风险 / 与已有工作**：重放要求任务前缀可重建，真实环境常常拿不到；写手和验证器同模型容易互相背书；结论可能与《Learn2Play Bench》「完整记录优于总结」直接冲突，需要按同一预算比。
- **证据**：Learn2Play Bench: How Well Do LLM Agents Learn from Experience in Unfamiliar Environments? · EVISKILL: Grounding Skill Evolution in Replayable Evidence · Context Evolution (ACE) vs. Runtime Intervention (AgentGuard) · Agent Memory: Task Knowledge / Skill / Failure Knowledge
- **来自你的灵感**：记忆模块能不能只写一个面，让验证器来判 · memory这里现在其实还是没找到一个机器能懂的语言或者组织形式，很多时候还是对齐做的差，trigger / condition 不清楚，有时候原文都更管用了。

## P2. 把 harness 里的 router / controller 换成只回选项和分数的小决策模块

- **要解决的问题**：现在决定「下一步走哪条路、调哪个工具」是让大模型逐字生成一段文字，慢、贵，还会把推理噪声写回上下文。
- **假设**：把路由和控制改成一个「状态进、选项/分数/真假出」的小决策接口，路由准确率基本不掉，而单步延迟和 token 消耗明显下降。
- **做法**：照《Contrastive Language Models》的三段配方训一个动作选择头：问答对预训练 → 难负例 → 真实操作轨迹；状态侧向量缓存、只重算动作侧；线上用固定接口挂在 harness 里，和原来的 LLM 文本路由并存做 A/B。
- **最小实验**：在一个 agent benchmark 的子集（如 Terminal-Bench 或 τ²-bench 的零售域）抽出所有「下一步该调哪个工具」的决策点，构造 5 万条状态-动作对，训 1.7B 和 4B 对比模型（三段配方按 1/100 规模缩），baseline 是同骨干的 LLM 文本 router，两周内可完成。
- **指标**：路由 top-1 准确率、每步决策延迟、每任务 token、下游任务成功率。
- **判负条件**：如果小决策模块的路由准确率掉超过 3 个点、下游成功率掉超过 2 个点，或者延迟省不到 2 倍，那它换不回收益。
- **风险 / 与已有工作**：《The Jev in Harness》和《Contrastive Language Models》都只有标题页或 README 级证据，「和 Jev 打平、快 9 倍」不可核；状态编码和 harness 改造工程量可能超出两周。
- **证据**：The Jev in Harness（SEP.24） · Contrastive Language Models · NeoHorse-1: Towards Recursive Self-Improvement via Agentic Post-Training with Routing Harness · SanSi: A Looped Typed Decision Model for System 1.5 Thinking
- **来自你的灵感**：现在jev as router或者controller感觉是个挺好的应用点

## P3. 把校准过的 verifier 当成 RL 奖励和门控，而不是把信心直接当分

- **要解决的问题**：用模型自报信心或单一裁判当 RL 奖励会偏：难题上信心会反转，判分器换个领域就失效，整组全错时奖励直接归零。
- **假设**：按「模型 × 信心档」在线校准的 verifier 分数，配合逐题可靠性门控，能比原始信心或用答对/答错当奖励得到更稳的训练和更高的 held-out 分数。
- **做法**：用 MARGIN 的在线校准（三档信心、衰减 0.04、冷启动收缩 100），只在 verifier 判定该题够可靠时才用它估的分数发奖励（Trust the Critic More 的逐题门控），并按 OpenJev-RLCD 的两步法先校准答案分布再强化推理，避免两个梯度互相淹没。
- **最小实验**：在数学题（AIME 子集）+ 一个文本 agent 任务上训 Qwen3-1.7B GRPO，固定 8 卡：三组分别是 0/1 奖励、原始信心加权、在线校准 + 门控奖励，各 120 步，同时记录校准用的对错标签。
- **指标**：held-out pass@1 与 avg@8、verifier 相对人工标注的 AUROC、训练熵与裁剪比例、奖励作弊率（空话、抄答案、改记录的比例）。
- **判负条件**：如果校准门控组的 held-out 分数不高于 0/1 奖励组，或者校准后 AUROC 没升，说明在线校准在这套设定下不成立。
- **风险 / 与已有工作**：校准依赖事后对错标签，只适用于可判分任务；τ²-bench 这类没有标准训练集的环境只能先做不训练版本；门控太严会把难例全砍掉，学习信号反而更少。
- **证据**：MARGIN: Runtime Confidence Calibration for Multi-Agent Foundation Model Coordination · OpenJev-RLCD: A Working RLCD Implementation · Trust the Critic More · EasyPPO: Stabilizing the Critic Is Key
- **来自你的灵感**：记忆模块能不能只写一个面，让验证器来判 · state这件事情越来越多被提起了，其实这东西可以做成rsi的一环，rsi必然要越来越细
