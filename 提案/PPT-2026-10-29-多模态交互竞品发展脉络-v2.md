# PPT v2：多模态交互竞品发展脉络

## Deck contract

- **Change from v1**：不再把多模态等同于摄像头问答；不再用少量年份冒充完整时间线；每页同时容纳产品动作、交互机制、反响和证据边界。
- **Core message**：多模态交互的价值不在于增加一种输入，而在于把人的视觉、语音、空间、屏幕和任务上下文连成可用闭环，并在正确时机给出可验证的帮助。
- **Evidence rule**：日期必须有一手来源；厂商功能、独立评测、销量/活跃与推断分开呈现。
- **Density rule**：内部报告版，每页至少包含“总判断、事实、解释、证据/边界”四类信息，尽量压缩无意义留白。
- **Visual direction**：延续米白、深墨、橙红、深绿的编辑风格；高密度网格、时间轴、分栏、矩阵和脚注。
- **Image usage**：none。
- **Notes**：v2 不生成讲者备注。
- **Output**：`产品/多模态交互竞品发展脉络-v2.pptx`

## Page roster

### P01 封面
- **Title**：多模态交互竞品发展脉络
- **总判断**：这不是一部摄像头助手史，而是感知、对话、行动和载体逐步汇合的历史。
- **分内容**：2011–2026 五条并行线；内部研究版 v2。
- **视觉**：标题 + 五条轨道索引 + 年份区间。
- **来源**：本地三份洞察报告。

### P02 定义与总判断
- **Title**：多模态交互的竞争，正在从“增加输入”转向“完成任务”
- **总判断**：真正的差异来自五层能力能否连成闭环。
- **分内容**：输入、上下文、时序、行动、载体五层；每层列代表能力与产品。
- **视觉**：五层堆栈 + 右侧结论与三个衡量问题。
- **来源**：三份洞察报告综合整理。

### P03 2011–2017：语音与视觉分别成熟
- **Title**：语音入口和视觉入口先各自成立，尚未真正融合
- **总判断**：2011–2017 的关键词是“入口”，不是“多模态闭环”。
- **分内容**：Siri 2011、Echo 2014、Google Assistant 2016、Bixby 2017；Lens 2017、Seeing AI 2017；交互仍是单通道为主。
- **视觉**：两条并行时间线 + 三条限制。
- **来源**：Apple、Amazon、Google、Samsung、Microsoft 官方发布。

### P04 2018–2019：从识图走向实时叠加
- **Title**：实时取景和语音加屏幕，把多模态从“识别”推进到“边看边操作”
- **总判断**：这一段不是断档，而是交互从静态图片走向实时反馈。
- **分内容**：Lens 2018 进入相机并实时取景；2019 实时翻译叠加画面；Google Smart Display 2018；Alexa APL 2018、2019 GA；语音与屏幕开始协同。
- **视觉**：相机轨道、屏幕轨道、模型轨道三段式时间轴；每段附产品反馈。
- **来源**：Google Blog、Amazon Science/Developer。

### P05 2020–2021：场景感知与第一视角试水
- **Title**：设备开始跟随人，第一视角硬件试水，但价值闭环仍未成立
- **总判断**：2020–2021 有真实进展，也有重要的产品失败。
- **分内容**：Echo Show 10 屏幕跟随用户；Lens 扩展到居家学习和购物；Ray-Ban Stories 第一视角；CLIP 让图文表示共通；Stories 低持续使用。
- **视觉**：上半部产品时间线，下半部“能力进步/产品失败”双栏。
- **来源**：Amazon、Google、Meta、OpenAI、WSJ 转引。

### P06 2022–2023：视觉语言模型改变交互上限
- **Title**：视觉语言模型让图像成为可对话上下文，通用助手开始出现
- **总判断**：2022 是底层模型拐点，2023 是产品化拐点。
- **分内容**：Flamingo 2022、GPT-4V 2023.09、Gemini 2023.12、Be My AI 2023.09；从单帧识别到多轮解释。
- **视觉**：模型里程碑 + 产品里程碑双轨；标注“能力已验证”与“体验待验证”。
- **来源**：DeepMind、OpenAI、Google、Be My Eyes。

### P07 2024：实时多模态进入平台入口
- **Title**：摄像头、语音、屏幕和执行边界，在平台助手层面首次被同时讨论
- **总判断**：2024 的产品竞争由“看图”升级为“连续共享现场”。
- **分内容**：GPT-4o、Project Astra、Gemini Live、Apple Visual Intelligence、Copilot Vision、Humane/Rabbit 反例。
- **视觉**：五列产品矩阵，统一字段：输入、上下文、动作边界、载体、反响。
- **来源**：OpenAI、Google、Apple、Microsoft、独立评测。

### P08 2025–2026：设备化、全双工与主动交互
- **Title**：多模态从 App 功能变成终端能力，竞争开始围绕“何时开口”
- **总判断**：实时性、第一视角和主动引导成为新分野。
- **分内容**：Gemini Live 扩大上线；华为小艺看世界；Meta Display；小米/夸克 AI 眼镜；SeedRealtime 2026；Meta Muse 2026；Guided Vision 2026；Snap anticipatory AI。
- **视觉**：终端/Agent 时间轴 + Muse 的后台执行、早期采用、设备分层与 Agent 网络四栏。
- **来源**：Google、华为、Meta、字节 Seed、Snap；Muse 官方发布、Q3 财报、华尔街见闻与 Reuters。

### P09 全景竞品地图
- **Title**：当前竞争由五类玩家共同构成，不是一个“助手榜”
- **总判断**：系统助手、智能硬件、屏幕家居、汽车座舱、基础设施层各有不同战场。
- **分内容**：列出报告中的 20+ 产品，按五类聚合；标出成熟度、主要输入、主要场景。
- **视觉**：五列产品地图，每列 3–5 个产品；底部标出“不可横向排名”。
- **来源**：多模态交互全球竞品报告。

### P10 系统与 App 助手
- **Title**：平台助手最强的是入口和上下文权限，最弱的是任务验证证据
- **总判断**：谁拿到屏幕、系统和账号，谁更接近任务闭环。
- **分内容**：Gemini、ChatGPT、小艺/小艺看世界、Apple Visual Intelligence、Copilot Vision、Bixby、超级小爱、SeedRealtime。
- **视觉**：高密度 8 产品对照网格：实时性、系统权限、执行边界、主要场景。
- **来源**：全球竞品与产品层报告。

### P11 眼镜与可穿戴
- **Title**：AI 眼镜从显示设备变成第一视角入口，但仍未解决日常价值
- **总判断**：成功来自自然载体和明确任务，失败来自替代手机、低可靠性和隐私压力。
- **分内容**：Ray-Ban Meta、Meta Display、无摄像头 Ray-Ban Meta Audio、Muse 接入计划、Android XR、Snap Specs、华为眼镜、小米/夸克、Google Glass、Ray-Ban Stories、Humane、Rabbit。
- **视觉**：三段“成功/混合/失败”泳道，每条含产品、交互、反响。
- **来源**：全球竞品、销量报道和独立评测。

### P12 电视、家庭与屏幕终端
- **Title**：屏幕终端的优势是现成入口，风险是任务常被手机替代
- **总判断**：电视和家庭设备的价值集中在内容发现、看护与陪伴，不在通用视觉问答。
- **分内容**：Samsung Vision AI、海信、小度；能力、交互、变现方式、证据缺口。
- **视觉**：三栏场景拆解 + “手机替代风险”侧栏。
- **来源**：全球竞品报告。

### P13 汽车座舱与空间交互
- **Title**：汽车提供手机没有的空间信息：谁在说、坐哪里、指向什么
- **总判断**：多音区、ToF 和车身传感器是真正差异化输入，但车规和隐私门槛更高。
- **分内容**：理想同学、NOMI；多音区、空间定位、指向、车内服务、情感陪伴；与通用手机助手对比。
- **视觉**：座舱传感器图 + 产品对照 + 风险。
- **来源**：全球竞品报告及引用的官方/媒体报道。

### P14 无障碍与高信任场景
- **Title**：无障碍是目前最接近真实价值的垂直场景，但付费来自服务与兜底
- **总判断**：任务明确、视觉不可替代、人工接管清楚，使这类产品比通用助手更容易成立。
- **分内容**：Seeing AI、Be My AI、vivo看见、Be My Eyes Workplace；谁用、谁付费、免费基线、效果证据、缺口。
- **视觉**：用户流程 + 商业结构 + 正反证据。
- **来源**：产品层和开源产品化报告。

### P15 基础设施、API 与开源
- **Title**：开源和多模态基础设施降低了“能做”的门槛，但没有证明“能卖”
- **总判断**：模型层、传输层、编排层、应用层必须分开看。
- **分内容**：SeedRealtime、TwelveLabs、拍立淘；Vision-Agents、LiveKit、Pipecat、Dograh、VLX-Flow；Muse Secure VM 作为闭源全栈对照；托管 vs 自建成本。
- **视觉**：五层技术栈 + 代表性仓库/产品 + 未验证项。
- **来源**：开源产品化报告。

### P16 市场反响分层
- **Title**：反响强、反响混合和明显失败，分别说明了不同问题
- **总判断**：强反响来自真实任务，混合来自缺少独立结果，失败来自产品承诺超出交付能力。
- **分内容**：强反响：Lens、Seeing AI/Be My AI、Muse 早期设置/日活与 Ray-Ban Meta 销量；混合：Gemini、Copilot、夸克、Agent 网络；失败：Glass、Stories、Humane、Rabbit。
- **视觉**：三层高密度清单，每项带证据类型和限制。
- **来源**：前文全部核验来源。

### P17 成败机制与商业模式
- **Title**：任务、载体、反馈、信任和单位经济性共同决定产品能否留下
- **总判断**：模型能力只是入场券，商业模式决定长期生存。
- **分内容**：成功/失败五因素；硬件捆绑、企业 SaaS、API 计费、免费公共服务、交易生态五类变现；Muse 对应免费入口、商家交易费和高阶订阅。
- **视觉**：左成功/失败机制，右商业模型表。
- **来源**：三份报告综合。

### P18 机会与空白
- **Title**：通用视觉问答已拥挤，真正空白在实时任务闭环和失败恢复
- **总判断**：机会集中在 harness、主动引导、安全护栏、垂直无障碍、现场作业、座舱和视觉交易。
- **分内容**：七个方向，每项写目标客户、为什么现在、壁垒、关键风险。
- **视觉**：七宫格机会矩阵，每格高密度信息。
- **来源**：全球竞品和开源产品化报告。

### P19 趋势判断
- **Title**：未来竞争从“看得见”走向“判断何时帮、帮到哪一步”
- **总判断**：四条主线：连续协作、主动交互、行动闭环、垂直工作流。
- **分内容**：每条主线附已发生证据、未解决指标、对我们的影响；纳入 Muse Network / Personal Agent Protocol，并附五问评估清单。
- **视觉**：四行趋势矩阵 + 底部评估清单。
- **来源**：综合。

### P20 年份审计
- **Title**：关键年份与事件审计
- **总判断**：所有进入时间线的事件必须有明确年份与一手来源。
- **分内容**：2011–2026 事件表，逐条列事件、日期、来源和证据等级，包含 Muse、Ray-Ban Meta Audio 与 Q3 财报口径。
- **视觉**：紧凑双列年份表。
- **来源**：官方发布页。

### P21 来源与证据边界
- **Title**：来源、事实强度与证据缺口
- **总判断**：厂商材料只能证明“上线”，独立评测和真实使用才能证明“有效”。
- **分内容**：官方来源、独立评测、销量/活跃、华尔街见闻与财报、本地洞察；明确缺少任务成功率、时延、留存、付费与人工成本；补充三份洞察与 Muse 增补的章节覆盖矩阵。
- **视觉**：三列来源索引 + 底部“报告章节 → PPT 页码”覆盖矩阵。
- **来源**：完整 URL 清单。

### P22 补页 01：完整时间线
- **Title**：2011–2026：从“帮我查”走到“看着我一起做”
- **总判断**：四个阶段分别解决入口、融合、理解和执行；用户少做一步，系统就多承担一层责任。
- **分内容**：语音/视觉入口、实时取景与屏幕、多轮理解、实时视频与全情境 Agent 连续串联。
- **视觉**：一条连续时间轴 + 四个阶段卡 + 每阶段用户原话。
- **来源**：P20 年份审计及官方来源。

### P23 补页 02：产品体验清单
- **Title**：每个产品到底能帮人干什么
- **总判断**：同一个“多模态”，有的是帮我查，有的是陪我做，有的是替我把事办完。
- **分内容**：系统助手、眼镜/屏幕/家庭/汽车、无障碍/基础设施三大类，逐个商品写具体用户动作。
- **视觉**：三列高密度产品体验清单；顶部放“这是什么、下一步怎么做、能帮我订吗、陪我一起做、记住提醒”等用户问题。
- **来源**：三份原报告与 Muse 增补。

### P24 补页 03：横向布局
- **Title**：大家不在同一层竞争：从“答一下”到“替我做”
- **总判断**：横轴看行动深度，纵轴看上下文范围；六维能力共同决定产品位置。
- **分内容**：视觉搜索、实时感知、工作执行、全情境 Agent、无障碍、交易/API 五类位置；2026 最新 Muse、SeedRealtime、Guided Vision 高亮。
- **视觉**：二维定性布局图 + 六维判断轴 + 2026 边界框。
- **来源**：产品层、全球竞品与 Muse 增补。

### P25 补页 04：经验教训
- **Title**：行业不是没有技术，而是很多产品没把任务做完
- **总判断**：成败逻辑是“看懂→会说→会判断→会执行→会负责”的因果链。
- **分内容**：不要把看懂当完成；不要要求换设备却没有十倍省事；不要把演示当稳定体验，也不要把下载当长期采用。
- **视觉**：五段因果链 + 三个坑及对应启示。
- **来源**：历史竞品、失败案例与 Muse 指标边界。

### P26 补页 05：云核心网未来
- **Title**：不要再做多模态 App，做它依赖的实时交互底座
- **总判断**：云核心网的优势是连接、会话、时延、边缘、身份、权限和 SLA。
- **分内容**：实时媒体面、端边云协同、Agent 会话层、Agent 互操作层；建议做实时多模态 QoS、Agent Session Fabric 和可信 Agent 通道。
- **视觉**：四层能力架构 + 三个产品方向 + 0–30 天、1–3 月、3–6 月、6–12 月路线。
- **来源**：基于历史与 Muse 证据的推断；页面明确标注尚待客户验证。
