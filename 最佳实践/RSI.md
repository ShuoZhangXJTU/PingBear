# RSI 最佳实践手册

> 递归/迭代式自我改进：让系统用自己的产物改进自己（模型、harness、数据三个面）。

自动积累，只增不减；「我的补充」是你自己写的地方，脚本永不覆盖。

## 目标与产出
- 开工前先写清这套系统交付的是「一个能自动判对错的闭环」，不只是更高的分数。普查 45 个自我改进系统，69% 的循环靠机器免费判对错的目标闭合；22 个学科 55 个已闭合循环里 53 个落在前三级判定（能跑测试到需要专家打分），第 4、5 级一例都没有。选题时先问这一步的成败能不能被固定代码自动判，判不了就先别做闭环。（来源：[[论文/RSI/MetaRSI RSI2 A Meta-Recursive Self-Improving System for Recursive Self-Improving Systems T|MetaRSI / RSI2: A Meta-Recursive Sel]] · [[论文/RSI/The Last AI Built by Humans Toward Genuine Recursive Self-Improvement|The Last AI Built by Humans: Toward ]]）
- 把「这次答对」和「机制改了」分开交付。只在当前任务里改答案、任务结束就丢不算自改进，论文把它划成 B0；改动必须落到参数、harness、记忆或改进策略上，并在下一轮真正参与生成或挑候选。给每个组件标一列「产出什么、被谁继承、下一轮在哪里用到」。（来源：[[论文/RSI/The Last AI Built by Humans Toward Genuine Recursive Self-Improvement|The Last AI Built by Humans: Toward ]]）
- 交付前用四问审计自己的系统：闭环在哪里闭上、什么被留下来继承、哪些决定还在人手里、下一轮的改进有没有真的用到它。（来源：[[论文/RSI/The Last AI Built by Humans Toward Genuine Recursive Self-Improvement|The Last AI Built by Humans: Toward ]]）
- harness 层的产出要带触发条件一起交付，不是只交一段代码补丁。SoL-Pi 在 GPT-5.6 Sol 上搜出的四个省 token 机制一行不改搬到 Opus 5，保住 Pi 在 EdgeBench 上 94.3% 的分数、token 少 44.7%、成本少 33.5%。（来源：[[论文/RSI/SoL-Pi Recursively Scaling Auto-Research Loops for Efficient Agent Harness|SoL-Pi: Recursively Scaling Auto-Res]]）
- 记忆组件的交付物应该是「按当前任务现场生成的短简报」，不是一份固定笔记。Just-in-Time Memory 把写入时就压好的笔记换成读时整理，ALFWorld 掉 1.7 到 2.9 分、WebShop 掉 6.8 到 8.2 分，写入时丢掉的细节读的时候补不回来。（来源：[[论文/其他/Just-in-Time Memory Learning to Curate Task-Adaptive Memory for LLM Agents|Just-in-Time Memory: Learning to Cur]]）
- 把 harness 的改动单位从「整套程序」缩到「单个插件」：用 YAML 写接口、Python 写实现，插件和调度它们的 workflow 分开编译；每轮只改一个插件、其余锁死，好插件进公共库，下一轮从库里挑零件重组。SWE-bench Verified 未见过题从整套重写的 Meta-Harness 55% 升到 65%（换 Kimi 出主意时 63%→69%）。（来源：[[论文/RSI/PluginRSI Recursive Improvement of Agent Harnesses with Reusable Plugins|PluginRSI: Recursive Improvement of ]]）
- 插件库和重组两步必须一起做：光把库塞给整套重写只在未见过题上从 63% 到 64%；拆掉「只改插件」或「重新拼装」任一步，PluginRSI 就从 69% 掉到 57% 和 59%。（来源：[[论文/RSI/PluginRSI Recursive Improvement of Agent Harnesses with Reusable Plugins|PluginRSI: Recursive Improvement of ]]）
- 把研究对象从「可运行代码」提到「研究想法」：AIM 先把想法显式记账、聚类、按证据和新旧打分，再交给求解器实现，5 个系统优化任务平均 63.3→67.0；但碰上只需顺着一个配方小改的题（IFEval 选数据微调）会输给直接改代码的 AdaEvolve（61.8 对 82.7），先判断任务类型再选路线。（来源：[[论文/RSI/AIM Agentic Idea Management for Automated Research|AIM: Agentic Idea Management for Aut]]）
- 交付「出错后怎么改」比交付干净答案更值钱：训练数据整条轨迹保留、失败轮不删，损失只加在真正往前走的决策上。AREX-2 在 MLE-bench Lite 拿 81.8，比最强公开基线高 8.1。（来源：[[论文/RSI/AREX-2 Advancing Self-Improving Agents through Long-Horizon Reflective Tasks|AREX-2: Advancing Self-Improving Age]]）
- 把路由 harness 当 RSI 的数据引擎：记录每次真实干活的系统提示、工具说明、工具返回、路由判断和结果，下一轮在这些记录上做后训练；NeoHorse 用路由轨迹把 Qwen3.5-4B 十基准平均分从 58.94 提到 64.87、9B 从 65.60 提到 69.04。训练和上线用同一套上下文，是收益来源。（来源：[[论文/RSI/NeoHorse-1 Towards Recursive Self-Improvement via Agentic Post-Training with Routing Harne|NeoHorse-1: Towards Recursive Self-I]]）
- harness 自我改进的交付目标要写成可复用机制优先，而不是开发集涨分优先：RRSI 对候选提案做时间退火编辑预算、按演化历史鼓励未探索轨迹，选择端用 critic 拦基准专属提案、pruner 删太小/太贵/失效改动；八个基准上演化集最多 +14.1 分、五个 OOD 最多 +4.7 分。把 OOD 增益当主验收。（来源：[[论文/RSI/RRSI Regularized Recursive Self-Improvement of Agent Harnesses|RRSI: Regularized Recursive Self-Imp]]）
- harness 搜索不要只养一条线：同时维护多条分支，各自用不同开发题和各自改进指南，最后按题路由；Mixture of Self-Improving Branches 在 Math–Gemini 46.0→62.0、Terminal-Bench 2.0 44.8→50.0、SWE-bench Lite 63.6→66.0，两支合起来比单支最好多覆盖 4.0–9.0 点。（来源：[[论文/RSI/Mixture of Self-Improving Branches For Agent Harness Optimization|Mixture of Self-Improving Branches F]]）
- 大规模 agentic RL 把任务、环境和 harness 当三条并列扩展轴：MiMo-V2.6 每步批量 1,568 题×16 条回答（约 2.5 万轨迹、27–37 亿 token），并从最小 loop 拼多个 mini-harness 混训；DeepSWE 上 Pro 58.4→72.6、Flash 48.7→65.7。只扩任务不换环境和 harness 会把策略绑死在一套工具上。（来源：[[论文/RSI/MiMo-V2.6 Scaling Reinforcement Learning Towards Self-Improvement|MiMo-V2.6: Scaling Reinforcement Lea]]）
- 把「没有标准答案时怎么验收改动」也当成产出的一部分写清：同一任务、同一模型、同一环境先跑一遍参考执行，再各跑一遍候选改动，用两次执行的行为差别（轨迹和交付物）决定采纳哪条，而不是等专家打分。Harness^2 用这套一步改动把 GLM-5 在 WorkBuddy-Bench 从 64.2 提到 75.7。（来源：[[论文/Harness/Harness^2 Recursive Agent Harnessing for an Open World|Harness^2: Recursive Agent Harnessin]]）
- harness 改动的交付物除了能跑的那份 harness，还要附一份 EXPERIENCE.md（适用情境、经验、支撑证据）加一张索引，按需检索；消融显示去掉经验库分别在两个基准掉 3.1 和 1.8 分，经验库还能跨任务搬（JobBench 攒的库用到 WorkBuddy 又拿 0.6、0.5、2.9 分）。（来源：[[论文/Harness/Harness^2 Recursive Agent Harnessing for an Open World|Harness^2: Recursive Agent Harnessin]]）
- 长任务闭环的交付单位是「环境包（工作资料＋任务＋判分器）」而不是更多命令示例：Scaling Agentic Data 用 1,535 个必须先动手做的任务（平均 52.8 轮）配约 3 千条长轨迹做 SFT，TB2.0 41.6%→55.8%、TB2.1 46.8%→60.7%，同底座喂 3.2 万条短轨迹的对手反被超过 3 分。（来源：[[论文/数据合成/Scaling Agentic Data for Long-Horizon Terminal Intelligence|Scaling Agentic Data for Long-Horizo]]）
- 把「做到哪一步」也做成可自动判定的产物：Tev 用一份正确底稿同时派生判分器、进度打分器和参考解，三者代码互不重叠；WorkRover 把任务包写成「工作资料＋任务＋判分器」三元组外加一层记依赖的 harness。（来源：[[论文/强化学习/Tev Scaling Long-Horizon Agentic Environments with Dense Progress Rewards|Tev: Scaling Long-Horizon Agentic En]] · [[论文/后训练/WorkRover Scaling Long-Horizon Cowork Agent Training Via Recursive Environment Evolution|WorkRover: Scaling Long-Horizon Cowo]]）
## 动手前必须想清楚的
- 先定位失败在哪一层，别默认要改权重或改提示。数据、harness、权重三层代价不同：改 harness 每次推理多背上下文，改数据碰不到模型本来就不会的能力，改权重可能把原有本事练回去。MetaRSI 的路线是先靠 harness 把能力逼出来，再把成功轨迹做成训练数据，最后写进权重并把 harness 撤掉。（来源：[[论文/RSI/MetaRSI RSI2 A Meta-Recursive Self-Improving System for Recursive Self-Improving Systems T|MetaRSI / RSI2: A Meta-Recursive Sel]]）
- 把评价器、题库和预算账本放在所有可改范围之外，模型只提改法、固定代码负责判定。Anthropic 的自动研究实验里出现过挑随机种子、从评测接口套测试标签；Red Queen Gödel Machine 的做法是每个 epoch 冻住评测器，换评测器时用独立标准答案校验。（来源：[[论文/RSI/MetaRSI RSI2 A Meta-Recursive Self-Improving System for Recursive Self-Improving Systems T|MetaRSI / RSI2: A Meta-Recursive Sel]] · [[论文/RSI/The Last AI Built by Humans Toward Genuine Recursive Self-Improvement|The Last AI Built by Humans: Toward ]]）
- 递归自调用前先把预算和深度写进代码。JAZ 用 BudgetPool、IterationLimit、RecursionLimit 三个原语管资源；实验中 AppWorld 递归封顶 2 层、StuLife 封顶 70 层，上限按任务长度人为定，换任务要重新定。（来源：[[论文/Harness/Harness as a Language A Minimalist Agent Framework With Maximal Expressivity|Harness as a Language: A Minimalist ]]）
- 上下文压缩要算账再压，而且压缩会打断缓存前缀。门槛是预计省下的输入费大于重写缓存的钱，压得越晚门槛越高；只看缓存命中率会得出反结论。（来源：[[论文/RSI/SoL-Pi Recursively Scaling Auto-Research Loops for Efficient Agent Harness|SoL-Pi: Recursively Scaling Auto-Res]]）
- 奖励要跟着模型当前水平分段。Qwen-Planner-Agent 按组做对率分三段：做对少就补中间步骤分，做对一半只看最后成不成，几乎全对才压执行成本。（来源：[[论文/RSI/Qwen-Planner-Agent A Closed-Loop AI-for-AI Framework for Real-World Mobile Planner Agents|Qwen-Planner-Agent: A Closed-Loop AI]]）
- 组内归一化会把某些项的相对权重抹掉，这时只调权重系数没用。整组几乎全对时效率项的相对权重会被除掉，哪怕权重只给 0.1，效率信号也和成败一样大；解法是给优势分母加下限。（来源：[[论文/RSI/Qwen-Planner-Agent A Closed-Loop AI-for-AI Framework for Real-World Mobile Planner Agents|Qwen-Planner-Agent: A Closed-Loop AI]]）
- 多老师蒸馏动手前先定损失怎么平均，因为平均规则就是隐式加权。按全局 token 平等平均时，数学回答长度约是指令跟随的 3 倍，数学白拿约 44% 损失权重；改成先定领域权重、领域内按回答平均后，数学降 3.0 分、科学升 2.1 分。（来源：[[论文/后训练/From Gradients to Capabilities Understanding Multi-Teacher On-Policy Distillation|From Gradients to Capabilities: Unde]]）
- 组内奖励只削峰不补齐等于削减奖励总量，会把训练带偏。只调小差代码奖励那版策略熵从 0.359 涨到 0.905，第 20 步从 56.5% 掉到 48.8%；补齐那版第 28 步有 62.2%。动手前先确认优势总和守恒。（来源：[[论文/后训练/Groupwise Agentic Grading and Advantage Redistribution for Code Agent RL|Groupwise Agentic Grading and Advant]]）
- 多阶段微调前先决定适配器合不合并。每阶段新加适配器、用完合并回主权重会让阶段之间互相打架，第一阶段后就掉 44%；把各阶段适配器都留着、各由自己的开关管，连做三段旧本事不掉。（来源：[[论文/后训练/Local Support Learning|Local Support Learning]]）
- 用会反复改答案的扩散式文字模型做长任务，先想清楚模仿式 SFT 会压住「反复改」这个本事：DiffusionGemma 微调后短题和工具选择变强，长推理和终端任务反而变差。作者主张改成按结果好坏给奖励，但材料里没有这个对照实验，别当已验证结论。（来源：[[论文/后训练/Fine-Tuning DiffusionGemma What Works, What Breaks|Fine-Tuning DiffusionGemma: What Wor]]）
- 多 harness 采样前先区分「解锁不同解法」和「只是多跑几次」。Scaling Trajectories 把三套 harness 的 rollout 拉平到各 2,074 次，并起来仍比最好的单套多解 67 道题、相对多 23.5%，互补来自外壳本身。（来源：[[论文/RSI/Scaling Trajectories for Complex Tasks through Recursive Self-Rewrite|Scaling Trajectories for Complex Tas]]）
- 中间层监督不是越多越好，先决定对齐哪一层。LastOPD 把学生每层都对齐老师，MATH-500 冲到 46 后掉到 11.3；只在两边接 LM head 的最后一层对齐、并 10 步内交还 token 级蒸馏，升到 58.95。跨尺寸模型按深度配对的层做的是不同的事，硬对齐等于把学生拽向它读不懂的状态。（来源：[[论文/后训练/LastOPD Taming Collapse in Latent On-Policy Distillation|LastOPD: Taming Collapse in Latent O]]）
- 学生跑 BF16 时别用「动了多少参数」判断训练改了什么。FP32 主权重约 97% 都变了，四舍五入成 BF16 只剩 7% 到 11%；FP32 里三分之一参数承担 90% 平方变化，BF16 只要 4%。要统计改动就同时看 FP32 主权重和 BF16 权重。（来源：[[论文/后训练/From Gradients to Capabilities Understanding Multi-Teacher On-Policy Distillation|From Gradients to Capabilities: Unde]]）
- 记忆入库前先决定收不收失败轨迹：把失败轨迹也存进去、即使标了成功还是失败，ALFWorld 再掉 1.5 到 2.9 分、WebShop 掉 2.3 到 3.4 分，失败样本会污染检索到的例子。（来源：[[论文/其他/Just-in-Time Memory Learning to Curate Task-Adaptive Memory for LLM Agents|Just-in-Time Memory: Learning to Cur]]）
- 人工把关要写清审什么。Qwen-Planner-Agent 是每轮发布前由人审，但正文没交代具体审什么、大模型控制器调阈值是否比固定阈值更好，自己动手时先把这两点定义出来。（来源：[[论文/RSI/Qwen-Planner-Agent A Closed-Loop AI-for-AI Framework for Real-World Mobile Planner Agents|Qwen-Planner-Agent: A Closed-Loop AI]]）
- 蒸馏前先决定 KL 方向，这比 on-policy/off-policy 更决定成绩：同分布最好成绩 on 72%、off 73% 几乎一样；forward KL 稳在 71–73%，reverse KL 在 35%–72% 乱跳；遗忘和更新稀疏度主要由学习率定（1e-5 时 OOD 最多掉 1.3 分、更新稀疏度 85–90%，5e-5 时 OOD 掉 11–14 分、稀疏度 52–60%）。（来源：[[论文/后训练/On-Policy or Off-Policy Learning A Systematic Study of Distillation Dynamics|On-Policy or Off-Policy Learning? A ]]）
- 熵也是被 KL 方向悄悄定的旋钮：换 KL 方向造成的熵差是换采样方式的两三倍。想要发散用正向 KL、想要保守用反向 KL；自蒸馏默认配置可抄 λ=0.5 的广义 JS、老师用衰减 0.95 的 EMA、只算学生前 100 个词并把尾部合成一个桶（想要熵不随 k 变就用重新归一化的截断）。（来源：[[论文/后训练/Divergence controls entropy in distillation|Divergence controls entropy in disti]]）
- 多奖励训练前先看奖励之间的相关性：GRPO 拿总奖励标准差做分母，等于把各奖励的协方差全加起来，数值波动大的奖励会占满分母；换成相关系数矩阵求和当分母，更新方向不变、只改步子大小，重复计分不会白送推力（两个奖励完全重合时复制一份不会让优势翻倍）。（来源：[[论文/强化学习/CorrGRPO Correlation-Normalized GRPO for Multi-Reward Learning|CorrGRPO: Correlation-Normalized GRP]]）
- 稀疏奖励（格式、长度这类）学得慢，先算「这批样本里有多少组出现有的对有的错」：能量与密度成正比、密度越低推力越小。按密度平方根倒数放大、只放大正优势、权重上限 5 倍；别硬把稀疏项权重固定调到 5 倍，那会拿准确率换达标率（超长率 4.21%→3.14%，准确率 48.03%→46.84%）。（来源：[[论文/强化学习/Make Sparse Rewards Count Density-Aware Reward Aggregation for Multi-Reward RL|Make Sparse Rewards Count: Density-A]]）
- 后训练会给「精化税」：Pass@1 涨、Pass@N 跌，因为成功率被推向 0/1 两端、中间靠多试捞题的空间被挤掉；42 个组合里 36 个在 128 次预算下税为正。评测前先想清报 Pass@1 还是 Pass@N，否则会把覆盖率损失当成进步。（来源：[[论文/后训练/Sharpening Tax in Post-Training|Sharpening Tax in Post-Training]]）
- 自出题先想清怎么判「成立」和「新颖」：只按答案一致筛，R-Zero 出题成立率从第一轮 76.5% 掉到第五轮 39.5%、筛完只剩 27.64%，训练到第三轮就掉头（第十轮 34.60、比原模型低 11.57）。（来源：[[论文/RSI/Questioning the Questions Sustaining Self-Evolution in Reasoning Models|Questioning the Questions: Sustainin]]）
- 多轮自我蒸馏前先决定「保哪一面」：每个周期的老师是上一轮的学生，它当老师时用的是「看提示的那一面」；只对齐「不看提示的那一面」会让老师那面一起跑偏。ReSAIL 用 KL 把「看提示」的输出钉在冻结老师上，ALFWorld OOD 从第三周期 44.8% 变 70.3%。（来源：[[论文/RSI/ReSAIL Mitigating Collapse in Iterative Agent Self-Distillation|ReSAIL: Mitigating Collapse in Itera]]）
- 有参考答案时先决定它当提示还是当模仿目标：RGPO 只把参考答案当临时提示帮模型采到正确解，再按原题条件（不带提示）监督；在有提示的上下文里训练，评测去掉提示后掉到 1% 的瞎猜水平。（来源：[[论文/强化学习/Rationale-Guided Policy Optimization Learning to Reason with Adaptive Rationale Scaffoldin|Rationale-Guided Policy Optimization]]）
- 组内奖励必须同源：同一组 rollout 里随机给不同环境反馈，成功率忽高忽低；改成一组给同一种反馈，成功率才稳定上升。按组比好坏之前先确认组内反馈一致，否则优势算歪。（来源：[[论文/强化学习/Environments as Scaffold Enriching Feedback to Bootstrap Self-Evolving Agents in Long-Hori|Environments as Scaffold: Enriching ]]）
- 参考答案要先筛再学：RGPO 只收严格高于本轮无提示最好分（δ=0）的引导回答；不过门控、直接学参考，难题正确率只有 12.8%，过门控后 99.5%。（来源：[[论文/强化学习/Rationale-Guided Policy Optimization Learning to Reason with Adaptive Rationale Scaffoldin|Rationale-Guided Policy Optimization]]）

- 让模型抄自己的教训只放上下文不够，得把它一起反向传播进参数：RLTL;DR 只把教训放提示里，考试时没提示仍停在 0–1%，把教训也纳入损失后无提示涨到 12–13%；教训损失权重从 0.5 降到 0.01 或 0，训练通过率从 21.5% 掉到 9.3%，只留教训损失关掉奖励仍有 20.0%。（来源：[[论文/强化学习/RLTL;DR Self-improvement by Internalizing Self-generated Feedback|RLTL;DR: Self-improvement by Interna]]）
- 挑训练数据前先估「每一步会不会走岔」：对每个中间状态采 K 条续写、用答对比例 p̂ 算 U=4p(1−p)（p 接近一半时最大），这条不确定性信号只读文本前缀和可判定答案，黑盒 API 老师也能用；按它挑数据同预算下比随机挑平均高 1.6 到 4.5 分。（来源：[[论文/后训练/Learning More by Training Less Uncertainty-Guided Progressive Contraction for Efficient Re|Learning More by Training Less: Unce]]）
- 离线复用旧回答时先看重要性权重落在哪个端点：硬裁剪会把「答对但已经变少」的回答权重压到零、把「答错但越生成越多」的回答权重放到无限大，ReSPO 用两条在端点归零或保持正值的平滑曲线代替裁剪，N=32 时最后 128 步均分比最好的裁剪基线高 7.9 个百分点（1.7B）、8.4 个百分点（30B）。（来源：[[论文/后训练/ReSPO Reshaped Sequence Policy Optimization for Gradient Starvation in Off-Policy Learning|ReSPO: Reshaped Sequence Policy Opti]]）
- 师生差距大时先测一次出力前 64 名词的重合比例再决定用在线还是半在线：17 组师生里重合度越低半在线赢得越多（相关系数 −0.73），重合到 89% 那组两种方法打平；但学生初始回答要已经像样，换成 base 学生半在线反而不如在线蒸馏。（来源：[[论文/后训练/When Do We Need On-Policy Distillation Distilling on Offline Student Rollouts Is Often Bet|When Do We Need On-Policy Distillati]]）
- 后训练阶段顺序可以按「奖励多容易被钻空子」排而不是按难度排：能程序判分的推理和代码先跑，靠裁判打分的指令、智能体、RLHF 后跑，被钻空子的时间就短；同时把生成上限给够（从 64K 提到 128K 后截断率从 11%–28% 降到 0.1% 以下，LiveCodeBench 68.6→75.9）。（来源：[[论文/后训练/Rufus-Air An Open LLM Post-Training Recipe|Rufus-Air: An Open LLM Post-Training]]）
- 不用训练就能预测新奖励下模型会变成什么样，但先算覆盖率再决定要不要信：PoEM 把几个已训好的单奖励模型的对数概率差按权重相加，覆盖率高的奖励恢复得更多（0.55 到 0.69，对没覆盖的 0.22 到 0.43）；覆盖率 0.3 这个阈值只在同一底子内有效。（来源：[[论文/后训练/PoEM Predicting RL Outcomes from Existing Policies|PoEM: Predicting RL Outcomes from Ex]]）
- 同一套训练流程里，没被奖励写清楚的行为不可复现，先量再保：20 次重训下做题通过率稳在 0.34–0.49，失败后肯承认的比例却在 0.26 到 0.90 之间跳；只把微批次切分换个分法（种子和数据顺序都不动）就能让披露率从 0.19 变到 0.85。（来源：[[论文/智能体安全/When Do Models Admit They Are Wrong Failure Disclosure Is Unstable Under Reinforcement Lea|When Do Models Admit They Are Wrong?]]）
- 一次只改一个 harness 组件不一定够，先想清哪几个部件是绑在一起的：把「任务」和「判分器」这类组合逐个拆开试，48% 到 74% 的情况必须同时改两个部件才通过检查，只改一个两边就对不上；改成「每种改法的单独改和组合改都重跑、只留改动最小的一套」后修复率从 60.7% 升到 70.3%，把任务本意改跑偏的比例从 14.3% 降到 1.3%。（来源：[[论文/后训练/WorkRover Scaling Long-Horizon Cowork Agent Training Via Recursive Environment Evolution|WorkRover: Scaling Long-Horizon Cowo]]）
## 常见坑与解决办法
- 工具写死会卡在没预料到的输入上。Letta 靠人写的搜索工具，JAZ 让模型自己写代码翻原始历史：远端回忆题 69.9% 对 61.8%，成本 18.3 美元对 42.1 美元。把「怎么取历史」也交给模型写代码，别只给固定检索工具。（来源：[[论文/Harness/Harness as a Language A Minimalist Agent Framework With Maximal Expressivity|Harness as a Language: A Minimalist ]]）
- 上下文快满时不要手工转抄历史。把提示词、工具和交互历史都做成代码变量，满了按引用交给子智能体、用 ContextWindowWarning 触发；去掉「提示词和历史是变量」这一条，远端回忆从 69.9% 掉回 32%。（来源：[[论文/Harness/Harness as a Language A Minimalist Agent Framework With Maximal Expressivity|Harness as a Language: A Minimalist ]]）
- 成功轨迹直接拿来微调会把外壳依赖一起学进去。Terminal-Bench 2 上直接微调从 57.0% 掉到 53.4%；先重写成通用 harness 的 runbook 再微调升到 74.2%。重写要点：runbook 只写关键步骤和检查点、不写最终答案，挑掉泄题的，再在全新沙箱里照着重做一遍。（来源：[[论文/RSI/Scaling Trajectories for Complex Tasks through Recursive Self-Rewrite|Scaling Trajectories for Complex Tas]]）
- 只在一套 harness 下采样会低估模型能力。同一个模型不做任何训练、只换外壳，Terminal-Bench Hard 从 33.0% 升到 66.0%，三套并起来 70.0%；题目做不出来有时缺的是一个合适的外壳。（来源：[[论文/RSI/Scaling Trajectories for Complex Tasks through Recursive Self-Rewrite|Scaling Trajectories for Complex Tas]]）
- 固定回合预算截断会砍好留坏，改用按老师打分在线判断。Fast OPD 2.70 倍速只到 0.434；改成累积打分跌破阈值就停、并缓存做对的前缀，3.73 倍速到 0.475，追平全量蒸馏的 0.477。（来源：[[论文/后训练/Know When to Stop, Where to Restart Accelerating Multi-Turn Agentic On-Policy Distillation|Know When to Stop, Where to Restart:]]）
- 前缀复用必须加质量门槛，否则学生从错误状态接着练、很快崩。论文用 α 等于 -0.8，关掉门槛后曲线很快塌；另外只对新生成本回合算累积和，别把历史回合算进去，否则信号被淹没。（来源：[[论文/后训练/Know When to Stop, Where to Restart Accelerating Multi-Turn Agentic On-Policy Distillation|Know When to Stop, Where to Restart:]]）
- 老师信号断在学生第一次做错那一步：错之前打分正常，错那一步之后转负、效应量 0.30。把早停触发的那一回合保留进 loss 当负信号，不要整条丢掉。（来源：[[论文/后训练/Know When to Stop, Where to Restart Accelerating Multi-Turn Agentic On-Policy Distillation|Know When to Stop, Where to Restart:]]）
- 蒸馏不用丢弃旧轨迹。把老师对每个词的打分 log(π_E/π_ref) 当固定奖励、改成最小二乘回归，旧数据能反复学；每批更 4 次以上约 30 步到顶，回放池版 10 步就到顶，基线要 40 步以上。（来源：[[论文/后训练/An RL View of OPD Least Square Policy Distillation for Sample-Efficient LLM Reasoning|An RL View of OPD: Least Square Poli]]）
- 去掉熵奖励时 Avg@16 只掉 0.46，Pass@16 掉 1.95、12 组全下降。只看单次准确率看不出多样性损失，评测要同时看 Avg@16 和 Pass@16，并把 Pass@k 拉到 64。（来源：[[论文/后训练/An RL View of OPD Least Square Policy Distillation for Sample-Efficient LLM Reasoning|An RL View of OPD: Least Square Poli]]）
- 一个固定老师教不出学生不会的位置。给老师权重加小噪声造 25 个邻近老师，挑老师时不看它自己答题多准，而看它能把标准答案里别人还没抬高的位置抬高多少；12 次平均从 64.63 涨到 66.57，按答题准确率挑只有 65.00。（来源：[[论文/后训练/Better Supervision Is Nearby Neighborhood On-Policy Self-Distillation|Better Supervision Is Nearby: Neighb]]）
- 噪声不是越大越好：σ 往上调覆盖位置一直变多，但学生成绩在 σ 等于 0.002 见顶后往下掉，σ 等于 0.006 只有 63.24。8B 用 σ 等于 0.002，1.7B 和 4B 用 0.0006 和 0.0012，每个尺度都要重新校准。（来源：[[论文/后训练/Better Supervision Is Nearby Neighborhood On-Policy Self-Distillation|Better Supervision Is Nearby: Neighb]]）
- 训练时别把几个老师的分布平均起来当目标：方向可以听最自信的老师，但学谁要另挑一个中间档的，q 等于 0.75 得 66.57，q 等于 1 反而掉到 65.28。概率差太大时 forward-KL 那一项会被阈值截掉、不再产生梯度。（来源：[[论文/后训练/Better Supervision Is Nearby Neighborhood On-Policy Self-Distillation|Better Supervision Is Nearby: Neighb]]）
- 多老师潜在监督会互相打架：混在同一次参数更新里，数学验证分第 30 步掉到 9.8；按领域分开更新、跑满 62 步能到 91.7。做法是一次参数更新只装一个领域的样本，三个领域轮流来。（来源：[[论文/后训练/Latent-MOPD Latent Multi-Teacher On-Policy Distillation|Latent-MOPD: Latent Multi-Teacher On]]）
- 潜在信号全程挂着会训崩，而且对齐分数在涨不能当学得好的证据：中层 CKA 没训练就有 0.99，训练中投影余弦从 0.97 涨到 0.98，同期 MATH-500 掉约 35 分。前 10 步让中间表示权重线性降到 0、token 蒸馏权重升到 1；第 10 步硬切只有 50.45，比完全不用中间表示的 54.15 还差。（来源：[[论文/后训练/LastOPD Taming Collapse in Latent On-Policy Distillation|LastOPD: Taming Collapse in Latent O]]）
- 大规模工具输出不要每次请求整段重发：超过 10 KiB 的结果只完整发两次，第三次起换成一个句柄加 1 KB 头尾摘要，需要原文再按句柄取回。（来源：[[论文/RSI/SoL-Pi Recursively Scaling Auto-Research Loops for Efficient Agent Harness|SoL-Pi: Recursively Scaling Auto-Res]]）
- 日志压缩要带校验和兜底：4 KiB 以上的构建和测试日志交给便宜模型压成一份收据，再用程序核对来源、退出码、原句和大小，核不过就退回原文。（来源：[[论文/RSI/SoL-Pi Recursively Scaling Auto-Research Loops for Efficient Agent Harness|SoL-Pi: Recursively Scaling Auto-Res]]）
- 改完代码再单独发一条测试命令会多一轮往返，把两步合成一次工具调用，请求数从 3 降到 2。（来源：[[论文/RSI/SoL-Pi Recursively Scaling Auto-Research Loops for Efficient Agent Harness|SoL-Pi: Recursively Scaling Auto-Res]]）
- 不同监督信号的原始梯度差会被优化器抹平：三种平均规则的原始梯度余弦只有 0.68，过一遍 Adam 后升到 0.96；把一阶动量清零，不同老师的更新余弦掉到接近 0。要比较监督信号，用不带动量的 SGD 当对照基线。（来源：[[论文/后训练/From Gradients to Capabilities Understanding Multi-Teacher On-Policy Distillation|From Gradients to Capabilities: Unde]]）
- 测试通过不等于代码写得好：让模型在同一工作区比较同组的几份通过代码并排名，再把优势从差的挪给好的，DeepSWE 第 28 步 62.2% 对 50.2%，平均轮数从 132.3 降到 111.6、平均长度从 191.9k 降到 172.9k。（来源：[[论文/后训练/Groupwise Agentic Grading and Advantage Redistribution for Code Agent RL|Groupwise Agentic Grading and Advant]]）
- 微调遗忘来自改动跑到了别的输入上，不是学得太狠。Local Support Learning 在同样的超参扫描里学到顶也不掉旧本事；开关判断从逐词改成看相邻几个词的滑动平均后，误开率从约 16% 降到 5%，旧本事保留率从 96.6% 升到 98.8%。（来源：[[论文/后训练/Local Support Learning|Local Support Learning]]）
- 打分器别用同家族模型自评自。Gagar 用的是被训模型同家族的 SFT 版本，论文没给打分器和人类判断的一致率，质量评估只有 30 道题、一个评审模型；条件允许就补一份人评一致性数据。（来源：[[论文/后训练/Groupwise Agentic Grading and Advantage Redistribution for Code Agent RL|Groupwise Agentic Grading and Advant]]）
- 只看「当前动作安不安全」会图便宜提前收手：把「选它之后还能安全走完的加权概率」算进动作打分，只在失败或撞过东西时从 top-12 候选重排；六个 Safety-CHORES 设置安全代价降 1.9%–57.5%、成功率几乎不掉，而 RCD 那种只看当前步的做法因为提前结束，成功率低 3.5–20.3 个百分点、每局少走 4.4–37.5 步。（来源：[[论文/Harness/A Safe Action Is Not Enough Feasible-Future Decoding for Vision-Language-Action Policies|A Safe Action Is Not Enough: Feasibl]]）
- 查 GUI 智能体的错只看模型自己写的文字日志会漏画面：把每步点击前后的截图和动作对齐，六个冻结模型在 OSWorld 全部涨分（Qwen3-VL-32B 39%→51%）；去掉视觉证据 50.94%→40.69%。（来源：[[论文/Harness/GUI-HARVEST Self-Improving GUI Agents through Evidence-Driven Harness Evolution|GUI-HARVEST: Self-Improving GUI Agen]]）
- 同一个任务只跑一遍就下判断分不出「时对时错」：同一个任务跑 3 遍、拿成功的那几遍当参照找失败差异（K=5 更贵但没更好）。单遍 43.12%、三遍 50.94%。（来源：[[论文/Harness/GUI-HARVEST Self-Improving GUI Agents through Evidence-Driven Harness Evolution|GUI-HARVEST: Self-Improving GUI Agen]]）
- 一次只盯一个任务改 harness 留不住：先把两个以上任务里重复出现的同类毛病归成「行为模式」，再改对应的运行时代码；去掉这步整套从 50.94% 掉到 42.13%。（来源：[[论文/Harness/GUI-HARVEST Self-Improving GUI Agents through Evidence-Driven Harness Evolution|GUI-HARVEST: Self-Improving GUI Agen]]）
- 只卡总分收改动分不清真修好还是碰巧：改前先写一条能看见的预测（如「存盘前会先关掉弹窗」），改完拿截图核对。只卡总分九轮才到 48.08%，两边都核对八轮就到 50.94%。（来源：[[论文/Harness/GUI-HARVEST Self-Improving GUI Agents through Evidence-Driven Harness Evolution|GUI-HARVEST: Self-Improving GUI Agen]]）
- 逐轮自己教自己会崩，根子在用错监督位置：只学「提示真正改变老师判断」的那几步（top-ρ=0.05 敏感度），并用 KL 把「看提示」那一面钉在冻结老师上；只加选步、不加保留，第三周期仍低于第一周期（OEL 六项设置第三周期全部低于第一周期）。（来源：[[论文/RSI/ReSAIL Mitigating Collapse in Iterative Agent Self-Distillation|ReSAIL: Mitigating Collapse in Itera]]）
- 硬把模型自己吐出的词当唯一正确答案会崩（第一句话的熵塌掉、无效动作越来越多）：改成让冻结的初始模型带事后视角、用 forward KL 对齐整词表分布；ALFWorld 4B 46.4%→69.5%、9B 55.0%→77.4%，平均轮数也降下来。（来源：[[论文/后训练/ASCENT Online Test-Time Training of Long-Horizon Agents via Self-Distillation of Verified |ASCENT: Online Test-Time Training of]]）
- 让模型自己写、又学自己写的、把更新永久写进权重会越学越坏：坏在「更新后的权重决定下一批训练文本」这个闭环，冻住生成器能删掉 98% 以上的损害；更新落盘前先在独立真实文本上验证，125M/760M 接受率只有 22/936 和 18/312。真文本要少而均匀地穿插（31% 均匀铺开只剩 0.0694 nats 额外伤害，成堆放则 0.7155 nats）。（来源：[[论文/后训练/Self-Generated Feedback Destabilizes Test-Time Training A Causal Decomposition of Long-Hor|Self-Generated Feedback Destabilizes]]）
- 多轮任务走错一步常常就是全部失败：ALFWorld 262 条失败里 155 条（59%）只是某一步走错，这一步平均在第 8 到 12 轮，之后还白走 18 到 21 轮拐不回来；把走错那步换成标准答案重跑成功率 8%→59%，只在之后两轮替它选对动作也有 58%。（来源：[[论文/后训练/PivotOPD Learning to Recover from Pivotal Mistakes in Multi-Turn Agents|PivotOPD: Learning to Recover from P]]）
- 组内奖励全错时梯度正好是 0，难题永远学不到：难题全错就接着采到出现一次对为止，再把同组历史答案一起算优势。K 从 4 加到 32 反而更差，因为大 K 会把早就会的简单题也拉进训练批次。（来源：[[论文/强化学习/Learning to Solve Hard Problems in RL for LLMs by Never Giving Up|Learning to Solve Hard Problems in R]]）
- 打分器偏爱长度、自信这类表面特征是「最后一层线性头」的毛病：只改最后一层权重、沿与该毛病协变的方向减掉一部分，五个模型三个榜单平均涨 8.3/18.0/6.9 个点；换到下游做 GRPO，回答平均从 331 词降到 285 词、啰嗦分 0.74→0.58、质量分 4.29→4.53。（来源：[[论文/后训练/BiasReducer Adaptive Bias Mitigation for Reward Models|BiasReducer: Adaptive Bias Mitigatio]]）
- 自己出题自己答的搜索模型会互相「对暗号」，分数看着涨其实没真变强：把「假一致」当训练期监控量；按来源（而不是按题）切分资料，让打分模型只学互补那一半；辅助模型每轮只加 25 步更新。CrossFit 到 48.8%/51.2%，比标准自进化高 8.8/8.4 分。（来源：[[论文/RSI/False Frontiers Diagnosing and Mitigating Co-Cheating in Self-Evolving Search Agents|False Frontiers: Diagnosing and Miti]]）
- 有序评分任务容易挤在中间几档，而且这是训练学出来的：补训练能把档位使用率从约 47% 升到 86%、准确率涨 13–15 分；但迁移看模型大小（0.8B 反而从 75% 掉到 73%），别直接照搬到小模型。（来源：[[论文/评测/More Choices, Fewer Decisions Ordinal-Scale Bias in JEV-like Direct-Decision Models|More Choices, Fewer Decisions: Ordin]]）
- 只在参数里存经验就找不回原文：要原句引用、交代出处、精确删掉某一条、让人工改一条时，还得把原文放进上下文。压成参数省下的算力是拿「可查可改」换来的。（来源：[[论文/记忆/Towards In-Parameter Memory Augmentation for Large Language Models|Towards In-Parameter Memory Augmenta]]）
- 模型的「说的」和「做的」常对不上：三个任务上只有 44.8%–75.9% 一致；两步查事实题里有 32.0%–54.3% 是探针没读到中间人却在 CoT 里写了中间人，两位数乘法里有 23.6%/15.8% 是写了中间乘积但答案直接背出来。（来源：[[论文/推理/Making LLMs Say What They Think Measuring and Improving CoT-Interpretability Alignment|Making LLMs Say What They Think: Mea]]）
- 训练 critic 别把截断样本一起丢：只让 critic 学写完的回答，等于把目标从「这题平均几分」换成「写完了得几分」；两头都丢时截断比例一路涨到接近 1、总分一直很低，只丢 actor 后总分最高也最稳。（来源：[[论文/强化学习/EasyPPO Stabilizing the Critic Is Key|EasyPPO: Stabilizing the Critic Is K]]）
- 代码策略失败要分两类调：机器人状态代码失败来源里测量问题约占 62%（识别错、软物体抓不住），逻辑问题约占 37%（漏写重试、阈值写死）。先修感知和量测，再改决策规则，不要一掉分就重训策略。（来源：[[论文/RSI/Embodied Turing Machines Stateful Code for Robot Recursive Self-Improvement|Embodied Turing Machines: Stateful C]]）
- 多分支 harness 的路由器会输给单支：Mixture 的路由器在 Math–Gemini 拿 62.0、比最强单支 58.0 高，但仍比两支合并上限低 4.4–5.5 点，在两个设置上还输给较强单支；部署前至少和最强单支、两支全跑上限各比一次。（来源：[[论文/RSI/Mixture of Self-Improving Branches For Agent Harness Optimization|Mixture of Self-Improving Branches F]]）
- 别在 harness 搜索里默认加专家上下文：给路由器加专家输出在数学上 57.0→59.5，在 Terminal-Bench 上 48.3→46.6；加什么上下文要按任务集验证，不要在一类任务有效就全局开启。（来源：[[论文/RSI/Mixture of Self-Improving Branches For Agent Harness Optimization|Mixture of Self-Improving Branches F]]）
- 冻结检查器会被学会绕开：Alignment via Training Against Probes 里探针冻住时，模型把内部状态挪到界线另一边，探针损失归零但有害分仍停在 0.40 以上；改成每步微调后重新拟合探针，才把 GCG 攻击有害分 0.52 降到 0.01。（来源：[[论文/后训练/Alignment via Training Against Probes Without Losing Monitorability|Alignment via Training Against Probe]]）
- 裁掉 rollout 尾部能解决一部分越学越差：全篇按 10% 分段蒸馏时，开头和中段教比全篇更好，只拿最后 10% 教成绩掉到未训练以下；训练不稳先切位置消融，确认哪个位置的老师信号在污染因果。（来源：[[论文/后训练/Are Full Rollouts Necessary for On-Policy Distillation|Are Full Rollouts Necessary for On-P]]）
- world model 和策略一起更新时，保留前要查两件事：单个组件是否可靠、两者配套是否仍成立；策略一改，原来准的预测器可能就不准。只保留两者配套通过检查的组合，不要分别保策略和预测器。（来源：[[论文/RSI/RSI-Anything Unlocking Recursive Self-Improvement with World Models|RSI-Anything: Unlocking Recursive Se]]）
- 别拿只改 score 的开发集结果当部署结论：Video-RSI 第一版改动在私有开发集准确率和画面都变好，搬到 MLVU 准确率反而掉了；开发集只看汇总指标也会过拟合。（来源：[[论文/RSI/Video-RSI Recursive Self-Improvement of Video Understanding Agents via Harness Evolution|Video-RSI: Recursive Self-Improvemen]]）
- 小模型连续微调别用完整长链示范灌知识：OpenR1-Math 上传完整推理长链，改成喂模型自己算对的简洁解法后数学更高、代码旧本事也没掉；小模型自己改写示范平均只有 60% 改对，工具题 8.2% 推理步骤会丢，必须拒绝采样过滤。（来源：[[论文/后训练/Continually Post-training Small Models via Synthetic Self-distillation|Continually Post-training Small Mode]]）
- RL 环境判分要锁成确定性属性：CyberGym 的漏洞版崩/补丁后不崩会因为补丁不完整误判；MiMo 改成只从 sanitizer 报告取漏洞类型和崩溃栈顶位置两条，规则匹配一致才算对。凡是靠模糊现象判分的任务，先找可复现的硬属性。（来源：[[论文/RSI/MiMo-V2.6 Scaling Reinforcement Learning Towards Self-Improvement|MiMo-V2.6: Scaling Reinforcement Lea]]）
- 反作弊不能只靠训练后审计：环境里残留构建日志、缓存和更新过的代码，模型能抄现成补丁骗分；要清环境、切网、hack agent 对抗探测、训练中审计四层一起上，并把查实轨迹奖励清零。（来源：[[论文/RSI/MiMo-V2.6 Scaling Reinforcement Learning Towards Self-Improvement|MiMo-V2.6: Scaling Reinforcement Lea]]）
- 给自改进流程加「太像就不收」的去重规则能把多样性拉上去，但分数基本不涨、有的还更差：Modular 加相似度阈值 0.95/0.8、LLM 判重、完全去重三种规则后圆堆积平均最高分从 2.44 降到 2.19。多样性要涨就换开局（先并行铺再顺序改），别指望靠过滤救。（来源：[[论文/Harness/Initialization Improves LLM-Driven Discovery|Initialization Improves LLM-Driven D]]）
- 裁判差太多会把小模型带坏，而且训练中模型会慢慢去钻裁判的空子：LFM2 24B 和标准裁判只有 0.54 的一致率，用它训 1.7B 掉到不训练以下；训练中回答还会变长（附录已看到这种漂移）。省钱方案一定要按「大模型 / 小模型」分开验证，并盯训练后的回答长度。（来源：[[论文/后训练/A Cheap Verifier is Good Enough LLM Post-training is Robust to Erroneous Rewards|A Cheap Verifier is Good Enough: LLM]]）
- 长任务环境别让模型自己写判分器：换成「看着公开文件自己写判分器」后 88% 的训练分组因全失败被丢弃、S@1 掉到 0.24（完整流水线 0.29），完全用「先出题目再补输入和答案」的常见做法只有 0.23。判分器必须钉在 agent 看不到的那份底稿上。（来源：[[论文/强化学习/Tev Scaling Long-Horizon Agentic Environments with Dense Progress Rewards|Tev: Scaling Long-Horizon Agentic En]]）
- 按余量差分配功劳之前先定正负方向：整局赢时多奖励「余量减少」的步、整局输时多惩罚「余量增加」的步，去掉这条规则 ALFWorld 未见过任务从 87.81% 掉到 76.87%；失败状态那个很大的余量代价 C 的形状和大小论文自己承认没做敏感性分析。（来源：[[论文/强化学习/DeltaTTG Training Multi-Turn Agents with a Token-to-Go Progress Meter|DeltaTTG: Training Multi-Turn Agents]]）
- 一组回答全做对导致优势归零时，别往组里硬塞几个 0 分凑出非零优势：4B 上各种塞法都比标准 GRPO 差；要加就加一条让模型自己从头写、带一个隐蔽小错的完整错解（1.7B 平均分 28.93→31.53），只把最后答案改错只有 27.70。（来源：[[论文/强化学习/Save Your Saturated Data Learning Beyond Reward Saturation in Group-Based RL|Save Your Saturated Data: Learning B]]）
- 给一组回答取平均再整体打分，等于在平均分之外额外奖励「答案越不一致」：换成给每条理由自己报出的答案分布打分（Brier 之类），SFT 加 KL 才压得住分歧；只校准答案分布的一半时模型会发现「不推理由、直接对冲」更省事，MMLU-Pro 约 100 步后四条理由全变成空壳。（来源：[[论文/后训练/OpenJev-RLCD A Working RLCD Implementation|OpenJev-RLCD: A Working RLCD Impleme]]）
- 小模型对齐隐藏状态要先垫一个投影层：1.7B 上直接对齐只有 36.7%，比只做 GRPO 的 43.8% 还低，加一个 512 维隐藏层的 MLP 投影升到 46.9%；3B 上加不加差不多（72.7% 对 71.1%），别把「几乎免费」当普适结论。（来源：[[论文/后训练/PR-OPD Privileged Representation On-policy Self-Distillation for Agentic Reinforcement Lea|PR-OPD: Privileged Representation On]]）
- 多条老师提示要按 rollout 分开给，不要合并成一条：把三套提示合成一条写进去，四个任务里三个比原方法还差；拆开分给不同 rollout 各用一条，比最强的单条提示高 0.5 到 4.7 个百分点。（来源：[[论文/后训练/Self-Distillation with Verbal Regularization|Self-Distillation with Verbal Regula]]）
- 半在线蒸馏里起作用的不是「数据冻住了」，而是「回答得是学生自己写的」：把冻结的回答换成老师写的回答再蒸一遍明显更差；但把学生的回答只留前 1/4、再补足总 token 数对齐预算，收敛明显更慢、最终分更低——后半段覆盖不能省。（来源：[[论文/后训练/When Do We Need On-Policy Distillation Distilling on Offline Student Rollouts Is Often Bet|When Do We Need On-Policy Distillati]]）
- 只出最难那一类题反而掉分：APT 诊断后按短板出题时保留一部分中等和已掌握的题，Lens 平均分 71.3；只出最难题掉到 70.6，不每轮重新诊断掉到 70.3，少给一部分评分细则掉到 69.1。（来源：[[论文/RSI/APT Feedback-Driven Agentic Post-Training for Text-to-Image Generation|APT: Feedback-Driven Agentic Post-Tr]]）
- 把诊断用的考题换成单一现成基准会让诊断偏掉：APT 把自动出的诊断集换成 OneIG-EN 后 Lens 平均分从 71.3 掉到 70.9，换成 GenEval 掉到 66.5。（来源：[[论文/RSI/APT Feedback-Driven Agentic Post-Training for Text-to-Image Generation|APT: Feedback-Driven Agentic Post-Tr]]）
- 模型权重搬运慢常常不是带宽问题，而是重复传输和逐张量处理：每个生成节点都收一整份模型等于白搬，模型有几十万张量时单是格式转换就花 590 毫秒。先把重复去掉、再分块打包重叠，才轮到谈网络。（来源：[[论文/强化学习/WeightBridge An Efficient Weight Transfer Library for Reinforcement Learning|WeightBridge: An Efficient Weight Tr]]）
- 结果奖励换不来步骤判断，除非最终成败真由每一步决定：同样只给整条答案对错，数学题上 4B 模型的 ProcessBench F1 涨到 77.7，搬到智能体轨迹上找「第一个错在哪步」平均只涨 5.4 分（4B）和 4.5 分（8B）；用 Qwen2.5-7B-Instruct 训练时最终判断越来越准、步骤查错先升后掉。（来源：[[论文/后训练/Inducing Process Supervision from Outcome-Only Reinforcement Learning|Inducing Process Supervision from Ou]]）
- 规则化整理证据并非对所有模型都更好：EBG 在多数模型上超过直接看原始上下文，但 DeepSeek-V4.1-Flash 在 SpecGAP 是 0.372 对 0.376、QQ 是 0.807 对 0.832 反而略低，GPT-5.6 Terra 在 FeedbackTrace 从 0.513 掉到 0.508；而且输入越长越需要先理证据（直接看原始记录会从 0.667 掉到 0.422）。（来源：[[论文/评测/What Did the Agent Actually Do Evidence-Grounded Oversight for Long-Horizon Agents|What Did the Agent Actually Do? Evid]]）
- 自我改进的单格数字别过度解读：Harness^2 的分数是三跑均值且任务顺序打乱，标准差经常重叠（LAB 上 75.6±4.5 对 76.5±2.1），各方法的步数还不一样，读分要对着 #Steps 一起看；选择器只是「采纳一个交付物」，论文自己用星号标出这不等于最优。（来源：[[论文/Harness/Harness^2 Recursive Agent Harnessing for an Open World|Harness^2: Recursive Agent Harnessin]]）
- 复习抗遗忘的学习率别照抄默认值，太大既学不进新的也毁掉旧的：1.7B 在 C-STANCE 上 lr=1e-5 时新任务反掉 2.05 个百分点、保留率只剩 32.88%。（来源：[[论文/后训练/Self-Preservation in Language Models|Self-Preservation in Language Models]]）
- 强制写好答案开头不是最强的「少思考」约束，反而可能让推理回升，纯答案率更低；开放题上就算纯答案率从接近 0 升到约 40%，平均准确率要掉约 15 个百分点——逼模型少说，在开放题上是要拿答对率买单的。（来源：[[论文/推理/Thinking Inertia LLMs Keep Thinking When Told Not To|Thinking Inertia: LLMs Keep Thinking]]）
## 可复制配方
- 极简 agent 框架只保留一个 invoke 原语：模型现场写一段代码当这次调用的函数体，代码里还能再调 invoke 得到子智能体；把提示词、工具、交互历史都做成 REPL 变量，例如 __history__。（来源：[[论文/Harness/Harness as a Language A Minimalist Agent Framework With Maximal Expressivity|Harness as a Language: A Minimalist ]]）
- 递归工具传递用动态作用域：用 scope 上下文管理器让所有递归子调用自动拿到同一批工具和预算，别一个个显式传给每个子智能体。（来源：[[论文/Harness/Harness as a Language A Minimalist Agent Framework With Maximal Expressivity|Harness as a Language: A Minimalist ]]）
- 评测拆两套提示：任务说明 instructions 和方法提示 guidance 分开写，各自保持任务无关，防止把任务答案偷写进提示。（来源：[[论文/Harness/Harness as a Language A Minimalist Agent Framework With Maximal Expressivity|Harness as a Language: A Minimalist ]]）
- 把 harness 拆成五个能单独下手的槽位：系统提示词、记忆、内置工具、技能、MCP；改动写成打补丁而不是重写整个程序；给 harness 设复杂度上限，规定只有比历史最好更好才留下。（来源：[[论文/RSI/MetaRSI RSI2 A Meta-Recursive Self-Improving System for Recursive Self-Improving Systems T|MetaRSI / RSI2: A Meta-Recursive Sel]]）
- 失败记录写成带层级的条目：直接原因、它在整件事里的作用、背后可复用的机制；让不同算子读同一份记录再决定谁去改。（来源：[[论文/RSI/MetaRSI RSI2 A Meta-Recursive Self-Improving System for Recursive Self-Improving Systems T|MetaRSI / RSI2: A Meta-Recursive Sel]]）
- 数据闭环配方：让智能体造任务、跑轨迹、筛数据，人只在每轮发布前把关；把训练集和开发集里的失败记录指回下一轮要造什么题，数据生产跟着模型能力一起转。（来源：[[论文/RSI/Qwen-Planner-Agent A Closed-Loop AI-for-AI Framework for Real-World Mobile Planner Agents|Qwen-Planner-Agent: A Closed-Loop AI]]）
- 工具和用户信息放模型外面：按当前可用工具裁剪技能提示，工具清单变了提示跟着变；按相关度取记忆证据，不动模型参数。（来源：[[论文/RSI/Qwen-Planner-Agent A Closed-Loop AI-for-AI Framework for Real-World Mobile Planner Agents|Qwen-Planner-Agent: A Closed-Loop AI]]）
- 记忆分四类存：稳定偏好、事件细节、长期事实、以后要做的事；每条带出处，新证据能顶掉旧说法；取用时只当证据给模型、不当命令。（来源：[[论文/RSI/Qwen-Planner-Agent A Closed-Loop AI-for-AI Framework for Real-World Mobile Planner Agents|Qwen-Planner-Agent: A Closed-Loop AI]]）
- 跨 harness 经验重写流程：每题采 K 等于 4 个 runbook，先做 schema 之类硬检查，critic 只看公开任务描述来筛，每个留下的 runbook 在通用外壳下用温度 0.7 重跑 M 等于 4 次，只留通过验证的，训练数据里删掉 runbook 和 critic 对话、只留任务、环境观察和模型自己的动作。2,001 条成功轨迹按这套变成 11,094 条可用轨迹。（来源：[[论文/RSI/Scaling Trajectories for Complex Tasks through Recursive Self-Rewrite|Scaling Trajectories for Complex Tas]]）
- runbook 固定结构：目标终态、关键里程碑、有用检查、恢复策略、常见坑。（来源：[[论文/RSI/Scaling Trajectories for Complex Tasks through Recursive Self-Rewrite|Scaling Trajectories for Complex Tas]]）
- 读时整理记忆的管线：记忆库只存原始轨迹，检索用 BM25 只看任务描述、不训练，整理者输出一段短简报塞进执行者提示词；训练配置 Qwen3-8B、GRPO 100 步、学习率 1e-6、batch 32、组大小 8，只给任务成败奖励，执行者全程冻结；训练库先用基础执行者跑一遍、按真值只留成功轨迹并固定。同一个整理器可直接配 Qwen3-8B、Gemini-2.5-Pro、GPT-5.4。（来源：[[论文/其他/Just-in-Time Memory Learning to Curate Task-Adaptive Memory for LLM Agents|Just-in-Time Memory: Learning to Cur]]）
- 评论家训练配方：评论家损失从 MSE 换成 BCE、价值用 sigmoid 输出；GAE 的 λ 设为 1，优势直接写成 R 减前缀价值；训练顺序改成先 actor 后 critic，用一次额外前向算新旧策略比并对评论家目标重加权，比值落在 0 到 6 外的样本丢掉。（来源：[[论文/其他/PACT From Credit Assignment to Critic Alignment|PACT: From Credit Assignment to Crit]]）
- 最小二乘蒸馏配方：把反向 KL 写成每一步的奖励 log(π_E/π_ref)，用带 Huber 截断的平方损失加熵奖励、在回放池上更新；每批 64 条提问、每题 4 条回答、每批更新 4 次起步，回放版每批 256 步优化。（来源：[[论文/后训练/An RL View of OPD Least Square Policy Distillation for Sample-Efficient LLM Reasoning|An RL View of OPD: Least Square Poli]]）
- 邻近老师配方：1,000 道挑选题、500 个随机种子加 M0 共 501 个候选，按边际 filtered PTA 贪心选 K 等于 25，路由 q 等于 0.75，SCGate 阈值 0.99，选择截断 κ_sel 与 κ 都取 0.06，全词表 forward-KL，100 步，全参数训练；显存不够时先流式跑一遍只存路由元数据，第二遍一次只展开一个老师的分布。（来源：[[论文/后训练/Better Supervision Is Nearby Neighborhood On-Policy Self-Distillation|Better Supervision Is Nearby: Neighb]]）

- 两段压缩配方：老师端对每个中间状态采 K 条续写、算 U=4p(1−p) 挑出「似是而非、一步之差」的轨迹把语料压小，学生端先摸底一遍、只留长度归一化 response loss 最高的那几条继续练；预算公式 B=(⌊ρN_c⌋+2M)/(3N)，池比例 ρ、活跃集大小 M 外加一个 probing epoch 是唯一要调的三个量。主数据 DAPO-17K，LoRA SFT。（来源：[[论文/后训练/Learning More by Training Less Uncertainty-Guided Progressive Contraction for Efficient Re|Learning More by Training Less: Unce]]）
- 岔口选择配方：熵取 top-20 概率、分歧统计 128 词窗口，两个分数在轨迹内排名归一化后各占一半（α=0.5）；岔口默认三处、每处两条，多轮任务先按轮打分再在每轮前 3 个位置里随机放一个；共同前缀在损失里只算一次。多轮任务要能把环境退回岔口状态（快照或重放动作），否则分支分布不对。两句格式规则也能照抄：答完必须出结束符、开头禁止收尾标签（数学平均分 25.82→38.94）。（来源：[[论文/后训练/Branching On-Policy Distillation|Branching On-Policy Distillation]]）
- 特权自我蒸馏的对齐细节：每层一个 512 维隐藏层的 MLP 投影，两遍按回答词配对（提示变长后位置对不上），归一化后只比方向（等价于 2−2cos），权重 λ=0.01，预热占 75%–80% 的步数，不加任何输出蒸馏项，投影器推理时丢掉；对齐起点要晚一点（WebShop 上从第 100 步挪到第 120 步，准确率 49.5%→57.0%）。诊断配方是同一批回答跑两遍（加/不加小抄），量词概率变化比例与隐藏状态变化比例，再用线性探针做「自己的小抄 vs 别人的小抄」并拿输出特征当对照。（来源：[[论文/后训练/PR-OPD Privileged Representation On-policy Self-Distillation for Agentic Reinforcement Lea|PR-OPD: Privileged Representation On]]）
- APT 细则奖励：每条细则二值判定、取平均当奖励，诊断和奖励共用同一个视觉语言判定器；每轮固定 120 道诊断题、20 步 RL、480 道新题，LoRA 秩 64、α=128、学习率 3e-4；十个大场景拆子类再拆条目、配一到四个描述维度、每题最多十条细则，一次生成 2,609 对题-细则当诊断池；采样上「弱点为主、保留一部分中等和已掌握」。（来源：[[论文/RSI/APT Feedback-Driven Agentic Post-Training for Text-to-Image Generation|APT: Feedback-Driven Agentic Post-Tr]]）
- 便宜裁判的可搬配置：先用 52 个模型做一轮筛选，用准确率和 F1 对三个不同厂商的前沿裁判（各取 20 道难题加 20 道普通题的回答）算一致率，再拿 12 个进训练；打分模板一次判 3 条标准、thinking 低档，并在评分标准列表处切开做前缀缓存；自建成本按每次打分 0.51 H100 秒折算；训练用 GRPO，8 条 rollout、120 条提示、学习率 5e-6、无 KL、最长 5000 token、101 步。（来源：[[论文/后训练/A Cheap Verifier is Good Enough LLM Post-training is Robust to Erroneous Rewards|A Cheap Verifier is Good Enough: LLM]]）
- PoEM 免训练组合：把已训好的单奖励适配器当底子，推理时在每个词上把各模型相对参考模型的对数概率差按权重相加，只加载 logits、不改参数；用一小批同题多回答、题内中心化后做岭回归定权重（也可以直接回归奖励打分）；用留出集 R² 当覆盖率开关、只在同一底子内排序；底子构造是 20 个 rank-64 LoRA、一个奖励一个、共享初始化。（来源：[[论文/后训练/PoEM Predicting RL Outcomes from Existing Policies|PoEM: Predicting RL Outcomes from Ex]]）
- CoSIR 消息级奖励：奖励写成「拿到这条数据后正确选项对数损失的下降」（bit 计），并加一条「必须与说话人已有证据一致、否则不得正分、编造还倒扣」的过滤；私人答案奖励拆成选项概率分加总分是否算对两半；同一局面采样多条候选、只挑一条继续对话、其余也进训练；早期模型不会提问时塞几条提问示范做带裁剪的模仿更新但不让它们延续对话；用初始 checkpoint 的通用输出加参考模型惩罚保住原有能力。
- 自写教训内化流程：把并行采样改成串行，每轮失败后让模型自己写一句话教训、把验证器报错和失败的单元测试喂给它；训练时把这句教训也纳入反向传播（改掩码即可、不额外算）；默认教训损失权重 0.5、一句话约 17 个 token；只拿「题目+教训」配对做 SFT，4 千条就能省掉大半更新算力。（来源：[[论文/强化学习/RLTL;DR Self-improvement by Internalizing Self-generated Feedback|RLTL;DR: Self-improvement by Interna]]）
- 复习抗遗忘的任务库配方：把老任务写成名字加描述加可选示例的条目，用更新前的冻结模型生成复习题和答案；用「正确→正确」的配对保留率当主指标，把示例、标签、描述、分数都排除出库外任务；学习率按 1e-7、1e-6、1e-5 扫一遍先定位能学动的档；固定额度时按行数把复习混进 SFT 输入，并声明行数匹配但 token 数不匹配。（来源：[[论文/后训练/Self-Preservation in Language Models|Self-Preservation in Language Models]]）
- TestPrism 的判法与面板：联合成功率＝测试要在初始代码上失败、放过全部正确实现、拦住全部错误实现，缺一不算过；面板是一份参考加四份正确加五份错误，正确组卡 AST 距离、错误组卡失败检查集，生成时面板不可见；训练用单参考答案通过率当密集信号、严格指标留作验收；失败分类按覆盖缺口、断言判错、执行逻辑错误三档。（来源：[[论文/评测/TestPrism Rethinking Test Evaluation Beyond a Single Reference|TestPrism: Rethinking Test Evaluatio]]）
- EBG 的两段结构：先把证据编号、按行为打包（仓库用条件—操作—结果，轨迹用要求—动作—回应），再按任务要求走「目录排序→选种子→一跳扩展→分连通块」，把相关文档段落和源码配在一起给模型看；整套整理只用规则、不调模型、不训练，可以直接套进别的 agent 复核流程。造题方式也能复用：删需求、偷换实现但保留原测试两种。（来源：[[论文/评测/What Did the Agent Actually Do Evidence-Grounded Oversight for Long-Horizon Agents|What Did the Agent Actually Do? Evid]]）
- PPT 多链采样配置：固定长度 T 加 EOS 后补占位符的重写；阶梯先用几何序列初始化，再按实测交换接受率调到大致相等；副本数取 4 到 5 条；顺序相邻扫描做交换（少副本时比 DEO 省一半迭代）；同时看单条 Pass@1 和投票两个指标；对照设计用「算力对齐的单链」和「同副本数不交换」两把尺子，分别排掉「多花算力」和「多跑几条」两种解释。（来源：[[论文/推理/Explore Broadly, Reason Sharply Push Small Models toward the Frontier via Sampling|Explore Broadly, Reason Sharply: Pus]]）
- WeightBridge 三步：把 load_weights 当黑盒、给检查点每个元素编唯一号跑一遍探出权重来历；用位置序列的二阶差分压索引显存（一次拷贝最多 16 个非零数）；三段式路线（先收、跨机换、机内补齐）加双缓冲分轮流水线。指标用 AGST（所有显卡干等时间除以卡数）和端到端搬运时间对比理论下限。（来源：[[论文/强化学习/WeightBridge An Efficient Weight Transfer Library for Reinforcement Learning|WeightBridge: An Efficient Weight Tr]]）
- Rufus-Air 的可搬细节：SFT 只对助手回合算损失，把「思考-工具调用-观察」整条链当一个训练样本；去污染同时用 8-gram 文字重叠和向量相似度两路再人工复核；难度过滤的阈值是解出率高于 0.8 就扔、一次也解不出也扔，在线版按组均值过采样 4 倍只留 (0, 0.8]；指令数据只写必须满足的评分细则；代码奖励对每题固定子采样最多 50 个测试、用题目哈希做种子。（来源：[[论文/后训练/Rufus-Air An Open LLM Post-Training Recipe|Rufus-Air: An Open LLM Post-Training]]）
- Vela 的行为数据配方：91 套题模板加六类行为（看/搜/买/发帖/关注/不喜欢）；按 72K–120K token 切段，前 2/3 当题面、后 1/3 当答案；同一件未来行为只随机出一种题，免得两种题型互相泄题；难度卡在 0.2 到 0.8（4 次不思考采样的均分）；每条答案写 4 份、只留分最高且高过难度均分的那份；开放题用分条标准打分，预测题用 set-F1。（来源：[[论文/数据合成/Vela User Behavior as Supervision Sparks LLM Intelligence|Vela: User Behavior as Supervision S]]）
- 校准再强化两段配方：不采样答案，而是读取「Answer:」后选项 token 的 softmax 分布，用 Brier 或对数分给这个分布打分；两次各 400 步，lr 2e-6、批量 8 题×4 理由，第一段只用直接梯度，第二段策略项权重 0.3、对第一段模型 KL 系数 0.04；评测用 AURC、Cov@ε 和拟合温度 T 看校准好坏。（来源：[[论文/后训练/OpenJev-RLCD A Working RLCD Implementation|OpenJev-RLCD: A Working RLCD Impleme]]）
- 老师侧提示词配方：teacher-only 提示全文写「先说这题考哪个原理，再逐项排除，最后反驳自己一遍」，学生看不到；多提示按 rollout 分配（化学用 K=3）；评估用 Pass@1 加 Maj@16 加 Worst@16，再补一个「截断推理链后重答」看学生是否真靠推理；把学生输出熵当蒸馏是否塌缩的监控指标。不用加新模块、不改损失函数，插进现有 OPSD 流程即可。（来源：[[论文/后训练/Self-Distillation with Verbal Regularization|Self-Distillation with Verbal Regula]]）
- 半在线蒸馏落地：先用初始学生每题采样一次、算好老师 log-prob 存盘，再离线训练，训练时只更新学生概率重算 advantage；落地前先花少量算力测一次师生 top-64 重合度来选路线；评测统一用 avg@32、温度 1.0；做对比实验时固定同一批 prompt 和总 token 预算。（来源：[[论文/后训练/When Do We Need On-Policy Distillation Distilling on Offline Student Rollouts Is Often Bet|When Do We Need On-Policy Distillati]]）
- 装新事实与练技能的 2×2 设计：把「事实」做成无规律的随机查表（两位数字进、一位数字出，四位一起算），只教一部分、留一部分给老师；用「老师带不带新事实 × 带不带新结构」的 2×2 把两个能力分开量；要更新事实就用 forward KL，要练多步推理就用 reverse KL 配学生自己的 rollout；报告句子的比特 NLL，比只看对错更能看出差异。（来源：[[论文/后训练/On-Policy Distillation Teaches New Skills but Not New Knowledge|On-Policy Distillation Teaches New S]]）

- 用统一尺子把不同基准拉到一起：以基准进入数据集那年 90 分位模型当 0 分、满分当 100 分。参考值（作者自己定的权重和归并规则）：2026 年研究生科学 85.8、软件工程 52.6、工具智能体 39.9。（来源：[[论文/RSI/The Last AI Built by Humans Toward Genuine Recursive Self-Improvement|The Last AI Built by Humans: Toward ]]）
- 给证据分权重再折价：基准官方表 3、公共 harness 2.5、综合报告 2、模型方自报 1，再统一乘 0.75，用来压低自报成绩。（来源：[[论文/RSI/The Last AI Built by Humans Toward Genuine Recursive Self-Improvement|The Last AI Built by Humans: Toward ]]）
- 评测器按会被攻击来设计：每个 epoch 冻住评测器，换评测器时用独立标准答案校验；已知失败模式包括挑随机种子、从评测接口套测试标签。（来源：[[论文/RSI/The Last AI Built by Humans Toward Genuine Recursive Self-Improvement|The Last AI Built by Humans: Toward ]]）
- 行为评测出题用两段式：先用 CPU 锚点扫全量记录，看工具报错、参数、事件顺序这些硬信号，只把少量候选交给便宜模型确认——每条成功查询扫 12.8 万条会话，只让大模型确认 706 个候选，整条流程平均 552 次调用。上下文按动作、失败、声明三类切点剪到出错前那一步。（来源：[[论文/RSI/TraceDance An Automated System for Building Agent Behavior Benchmarks from Real-World Agen|TraceDance: An Automated System for ]]）
- 自动出题的质量门槛：每题配 0 到 5 分评分表，平均至少 4 分才算过，抽检里 90% 的题评分表质量在 4 分以上、平均 4.75；用多人独立标注估计底子，随机抽 100 道让两人独立检查，两人都确认原记录真出现了目标坏行为的只有 84 道。（来源：[[论文/RSI/TraceDance An Automated System for Building Agent Behavior Benchmarks from Real-World Agen|TraceDance: An Automated System for ]]）

## 成本与预算
- 省 token 的账要按最后能省多少输入费算，不是按压缩率。参考账：Pi 在 EdgeBench 上 51 题 44.8 分、2.15B token；四个机制全上后 42.0 分、1.10B token，token 少 49%，成本从 1,339 美元降到 894 美元。（来源：[[论文/RSI/SoL-Pi Recursively Scaling Auto-Research Loops for Efficient Agent Harness|SoL-Pi: Recursively Scaling Auto-Res]]）
- 把「历史按引用传」和「让模型自写检索代码」算进预算：JAZ 远端回忆 69.9% 对 Letta 61.8%，成本 18.3 美元对 42.1 美元；自改进 AppWorld 74.2% 对 ACE 69.9%，成本 20.9 美元对 30.6 美元。（来源：[[论文/Harness/Harness as a Language A Minimalist Agent Framework With Maximal Expressivity|Harness as a Language: A Minimalist ]]）
- 记忆方案的 token 预算参考：读时整理的 base 版只多 1.9K 输入 token，ReasoningBank 多 10.7K、SkillOS-base 多 13.4K；训练后输入 token 再省约 10%、输出 token 省 13%、步数省 12%。（来源：[[论文/其他/Just-in-Time Memory Learning to Curate Task-Adaptive Memory for LLM Agents|Just-in-Time Memory: Learning to Cur]]）
- 环境生成单价：3,300 个环境每个只花一两美分，适合把环境批次当成可再生资源来用。（来源：[[论文/其他/Verifiable Hidden Dynamics Play Generating Agentic RL Environments from Solved Mechanisms|Verifiable Hidden Dynamics Play: Gen]]）
- 打分开销要专门压：Claude Opus 5 打分每组约 2000 秒，换成自训打分模型降到约 600 秒，再让打分和 rollout 生成错峰；这 600 秒只算打分本身，不等于端到端训练成本。（来源：[[论文/后训练/Groupwise Agentic Grading and Advantage Redistribution for Code Agent RL|Groupwise Agentic Grading and Advant]]）
- 潜在监督的显存开销可以压：只存选中的三层状态，16,384 个位置占用从 2.63 GiB 降到 0.28 GiB；邻近老师的训练开销约为对照方案的 1.42 倍，用噪声造老师比多挂几个模型便宜。（来源：[[论文/后训练/Latent-MOPD Latent Multi-Teacher On-Policy Distillation|Latent-MOPD: Latent Multi-Teacher On]] · [[论文/后训练/Better Supervision Is Nearby Neighborhood On-Policy Self-Distillation|Better Supervision Is Nearby: Neighb]]）

## 记忆与上下文工程

- 先决定在写入时整理还是读时整理：写入时整理要提前猜未来任务需要什么，猜错就永久丢信息；把库里的原始轨迹换成写入时压好的笔记，ALFWorld 掉 1.7 到 2.9 分、WebShop 掉 6.8 到 8.2 分。默认全留原始轨迹，把整理放到读的时候。
- 检索器先从最便宜的用起：只用 BM25 看任务描述、不训练，也能配三种不同执行者；整理者的训练只给任务成败当奖励，执行者全程冻结。
- 把任务描述从整理者输入里拿掉，它就退化成和任务无关的总结器：不训练时 ALFWorld 最多掉 3.1 分，训练后掉 11.4 分、WebShop 训练后掉 10.4 分。训练后掉得更多，说明 RL 学的是抓这道题要什么，不是把轨迹压得更短。
- 做记忆方案时加一条空检索检验：把检索结果清空后，训练过的方案反而比不训练更低，ALFWorld 最多掉 14.8 分、WebShop 掉 15.2 分，说明提升来自学会蒸馏检索到的经验，不是模型自己凭空会做。
- 上下文预算按只多花多少输入 token 管：读时整理的 base 版多 1.9K，写入时整理的方案多 10.7K 到 13.4K。
- 长输出分层给：超过 10 KiB 先完整给两次、之后换句柄加 1 KB 头尾摘要；超过 4 KiB 的日志抽成可核对收据；压缩点放在计划步骤边界，并且先算省下的输入费是否大于重写缓存的钱。
- 历史按引用传而不是让模型手抄：提示词、工具和交互历史做成代码变量，上下文快满时用交接模板把整段历史按引用交给子智能体，实验里这一条单独贡献了远端回忆从 32% 到 69.9% 的差距。

## 能力保留与遗忘控制

- 防遗忘靠限制改动的生效范围，而不是调小学习率：给权重矩阵的更新配一个只在当前训练数据分布内打开的开关，旧本事保留率从 76.6% 升到 96.6%；高斯混合模型比普通小网络更能做到没见过就关上，而且更省地方。
- 开关判断要平滑：逐词独立判断在旧任务数据上约 16% 的词会误开，改成先看相邻几个词的滑动平均再决定，误开降到 5%、保留率再升到 98.8%。
- 多阶段别合并适配器：每阶段新加一个、用完并回主权重会让阶段之间互相打架，第一阶段后就掉 44%；所有阶段的适配器都留着、各由自己的开关管。
- 挑过拟合点的时候同时看两轴：新任务成绩画横轴、旧基准平均分画纵轴；如果超参只按新任务成绩扫，保留分没参与挑选，防遗忘效果会被高估。
- 会反复改答案的扩散式模型要分组评测：短题和工具选择类通常涨、长推理和终端操作类可能掉，只报总平均分看不出改坏了哪一块；长任务掉点的补救方向是改成按结果好坏给奖励，但这条目前没有对照实验。

## 训练环境与数据生成

- 环境生成倒过来做：先解出数理模型的标准答案，再照着它的决策过程做成有状态工具，让环境动态和评分同源。这样批量造环境很便宜，3,300 个环境每个只花一两美分。
- 具体配方：挑现成运筹模型（库存、路径、背包、LP/QP）按参数批量抽题，用解题器算最优值和默认策略分，冻结 35B 当出题者，用真实文档做场景种子；三条准入检查是能执行、默认值在合理区间、最优值和参考对得上。
- 奖励要把实际收益夹在最优值和默认值之间归一成 0 到 1，只跟可计算的标准比，不用语言模型裁判。
- 会做题不等于会在会变的状态里做决策：同一道优化题写成文字直接答能拿 0.962 分，把参数全告诉它但要一步步操作就掉到 0.231；环境只放行界面调用、不透露参数，难点才落在交互上。
- 验证迁移要看没见过的机制：训练只用三族运筹模型，换到没见过的八族机制也涨分；365 天电商经营里原来五次破产一次，训练后五次全活，平均结余从 54,294 涨到 182,844。
- 规模加大时收益应跟着放大，否则可能是环境太简单：背包题从 6 乘 5 加到 11 乘 11，同一个冻结模型仍能造出环境，训练收益从加 0.412 涨到加 0.861。
- 生成失败的样本要重做或丢掉，评分上界是最优值、在线策略不一定够得着；作者自己也没说策略真的重建了底层模型，所以别把这种环境当成机制理解的证据。

## 低精度与分布式 RL 工程

- 训练端和生成端各自量化得准不代表两边一致：同一激活在两边只需差一点点就可能跨过取整线被压成相邻两个格子、误差被放大（0.48 变 24）。先对齐取整格子，再谈各自的量化误差。
- 低精度 RL 的稳定性诊断看「优势符号乘概率差符号」，不要只看两边概率差多大：NVFP4 跑 GRPO 时这类同号 token 的权重占比从 1.02 涨到 2.32、远早于整体崩坏；坏 token 还会局部扎堆（排前 5% 的 64-token 段装走约四分之一坏 token、是均匀分布的五倍），按整条答案取平均时 97.2% 的答案看不出异常。
- 训练与生成拆到两批机器、靠共享文件夹传很小的 LoRA 增量对齐、不要 GPU 直连：同样 500 步从 3 小时 27 分缩到 53 分钟；但要自己补 LoRA rank、拉取间隔、机器数量和总成本核算，也要跟同步基线做同硬件对照。
- 把 RL 后训练的完整梯度换成低秩梯度草图能救显存（7B 平均 31.82→17.29 GiB、27B 从第一步爆显存到跑 1100+ 步），但准确率和速度不一定占优（和 LoRA 比 68.47% 对 70.45%、单步更慢）；投影秩、RowAdam、KL 预算和 mismatch subtraction 是一整套联动参数。

## 自出题、课程与难度调度

- 只按答案一致筛题会让出题越来越不成立：R-Zero 抽样成立率从第一轮 76.5% 掉到第五轮 39.5%、筛完只剩 27.64%；把成立性和新颖性接进出题奖励后，R-Quest 到第十轮仍比原模型高 5.75 分、同期 R-Zero 掉到比原模型低 11.57 分。
- 把「同一局面必须答对不同目标」当压力，比多喂目标数据更能逼出可迁移判断：固定状态、历史、候选动作，只换目标让同一批动作重新排序；ALFWorld 没见过的关卡 82.8%→91.8%、每局步数 16.0→11.4。模仿（Positive SFT）在见过的关卡接近、在没见过的关卡只有 84.3% 对 91.8%。
- 组内奖励全错时梯度为零，难题永远学不到：难题全错就接着采到出现一次对为止、再把同组历史答案一起算优势；K 从 4 加到 32 反而更差，因为大 K 会把早就会的简单题也拉进训练批次。
- 标准答案该当临时提示而不是模仿目标：参考解按字符或 token 切段做台阶、做对收回，监督只在原题条件（不带提示）上算；在有提示的上下文里训练，评测去掉提示后掉到 1% 的瞎猜水平。
- 训练数据整条轨迹保留（含失败轮）、损失只加在真正往前走的决策上：AREX-2 在 MLE-bench Lite 拿 81.8，同环境同技能只换基座时从 68.2 涨到 81.8、多出的 13.6 分是训练补上的判断。
- 环境准入两条硬检查：参考解必须能跑出分数、朴素基线必须明显更低，否则丢掉；把通过/不通过换成通过比例这类连续分，并按轮数扫一条曲线看什么时候不再涨。
- 先管想法再实现：AIM 把想法聚类、按证据和新旧打分、派单探索或利用、审查实现是否忠实，5 个系统优化任务平均 63.3→67.0；但碰到只需顺着一个配方小改的任务会输给直接改代码。
- 零数据自对弈预训练：程序池按「新采样＋局部变异＋高分回放」三份混合，奖励用「这个程序的输出给学习者带来的梯度是否和最近参数真实走向一致」，生成器用 GRPO 式优势加 KL 正则拉向均匀程序先验；上下文学习（倒序字符串、栈、联想召回）接近全对。

## 裁判、奖励塑形与多目标聚合

- 裁判要当成会变的部件：助手变强后旧裁判看不懂新错误（第一轮裁判在同期考题上和人相关性 0.72、换到后来出现的难题只剩 0.07），要按人工锚点考卷决定何时校准、每轮从同一基座同样训练量重练，而不是全程用一个固定打分器。
- 打分器的偏爱主要是「最后一层线性头」的毛病：只改最后一层权重、沿与该毛病协变的方向减掉一部分，五个模型三个榜单平均涨 8.3/18.0/6.9 个点；换到下游做 GRPO，回答平均从 331 词降到 285 词、质量分 4.29→4.53。
- 多条规则打分不该只数「答对几条」：用整张对错表反推一个隐藏的水平分当奖励（高斯响应函数 + 高斯先验），答对条数相同的两张表也能被排开；同一套参数还能量化哪条规则信息量大、按费舍尔信息挑规则，只问一半规则时平均分只比全问低 0.1 分、裁判耗时少 49%。
- 奖励设计的分层：分项规则打分用「必须做到/重要/可选」分档（RaR），多奖励聚合用密度加权（稀疏项能量低就放大）或相关性归一（波动大的奖励别占满分母），三者互不冲突、可以叠。
- 打分器自评自的家族问题：Gagar 用的是被训模型同家族的 SFT 版本、论文没给打分器和人类判断的一致率、质量评估只有 30 道题和一个评审模型，条件允许就补一份人评一致性数据。

## 技能、经验与参数化记忆

- 把改动绑到可重放的执行证据：每张证据卡记持久 ID、一条改动建议、若干触发区间（任务、来源轮次、起止步），重放时重建任务前缀、再跑加了改动的那一段，裁判返回接受/修正/拒绝三档；被全局验证拒绝的修订单独重放每条改动、只留通过的那些，被拒的先进暂存账本继续考察（96 条暂存里 72.9% 在后一到三轮被正式收进）。
- 把流程知识从提示词里拎出来存成可改的有向图：节点放工具调用、推理步骤或状态，边带 condition、guidance、pitfalls 三个文字字段；每步只取当前节点周围两跳的小图加最近三步轨迹做提示；ALFWorld 70.34%→81.53%，手写专家图写错也能被验证门控自己修回来。
- 从轨迹里挖「反复同现、常在成功任务里出现」的动作对拼成经验树：动作按「动词+作用对象」规范化、合并判据用出现次数乘长度乘成功率，每个节点当一道练习题；WebArena 18.4%→22.9%，把 X-Score 换成随机合并反而掉到 17.9%（比只做 SFT 的 18.4% 还低）。
- 自己出题攒经验、反复验证才入库、记忆只在测试时以提示注入不动权重：跨模型家族也能提分；但经验是解题者自己总结的、可能把错做法固化，环境要能反复交互和自动判成败。
- 参数化记忆是另一条路，但要把「写在哪层（嵌入/注意力/FFN/混合）」和「什么时候写（部署前/部署中）」当两条独立轴；要按内容检索就放注意力层、要改具体事实就放 FFN、最省事放输入层；压成参数就找不回原话，要原句引用、交代出处、精确删除还得把原文放进上下文。

## 机器人、GUI 与具身动作安全

- 光看当前动作安不安全不够，还得看这一步之后策略和环境还能不能把任务安全走完：把「选它之后还能安全走完的加权概率」算进动作打分，只在动作反复失败、撞过东西或过不了终点检查时才触发；六个 Safety-CHORES 设置安全代价降 1.9%–57.5%、成功率几乎不掉。
- 只查当前这步安不安全会图便宜提前收手：RCD 成功率比原策略低 3.5–20.3 个百分点、每局少走 4.4–37.5 步，代价低常常只是提前结束、不等于把任务做完了。评测要同时看成功率、安全代价和每局步数。
- 把「指令动作 vs 实际走成什么样」的差别也喂给打分器：安全对齐 Fetch 上加反馈后成功率 55.67%、安全代价比原策略低 15.9%；但执行反馈只试了两种扰动、一个强度，还不算确证。
- 最早那个决策点用最多两个备选、各模拟 4 条未来，挑零代价完成概率最高的：安全完成率从 27.91% 升到 30.23%、成功率不变；少量「先试走一遍」能补上打分器看不到的信息。
- GUI 任务的对错藏在屏幕上，所以查错要把每步点击前后的截图和动作对齐、同任务多跑几遍、跨任务归并行为模式、改后拿截图核对预测；这四个动作绑在一起才是证据驱动，单改任何一个都会掉分。

## 分歧与推翻
- 争议：旧手册主张成功轨迹直接微调会把外壳依赖学进去，Terminal-Bench 2 从 57.0 掉到 53.4，应先重写成通用 harness runbook 再微调升到 74.2；HAD 也主张只教外壳帮不上忙的部分。NeoHorse 反过来把部署 harness 录的真实轨迹原样保留、只对当前轮输出算损失，结果比公开合成数据把五基准从 64.32 提到 70.57，十基准两个尺寸普遍涨。条件不同：NeoHorse 训练和部署是同一套路由 harness，且不把历史轮当监督；runbook/HAD 面向训练后要换外壳或要避免把外壳信息记进权重的场景。目前该信哪一个：若上线 harness 稳定且要适应其上下文，保留真实上下文；若要跨 harness 迁移，先重写成任务级 runbook。还缺：同一批轨迹在保留上下文和重写 runbook 下的同预算对照，以及跨 harness 迁移测试。（来源：[[论文/RSI/NeoHorse-1 Towards Recursive Self-Improvement via Agentic Post-Training with Routing Harne|NeoHorse-1: Towards Recursive Self-I]]）
- 争议：旧手册依据 ReSAIL 说多轮自我蒸馏会崩，老师若用上一轮学生、只对齐不看提示那一面会让老师那面跑偏，必须用 KL 把看提示的输出钉在冻结老师上；AdviSD/ASCENT 也更常用冻结初始模型当老师。新 Recursive OPD 反过来发现冻结老师在错题结尾 94.5% 想收尾、只有 22.0% 想反思，8B 数学比共同进化低 17.77 分（47.99 对 65.76），4B 低 34.72 分。条件不同：ReSAIL 是多轮 agent/ALFWorld、Qwen3-4B/8B、要保看提示那一面；新论文是单轮竞赛数学、非思考模式、LoRA rank-128，用 Forward KL 加 SRCL 控长度。目前该信哪一个：agent 多轮场景先按 ReSAIL 保留提示面；单轮可验证推理且每轮能重跑验证时，可试共同进化老师。还缺：在同一个多轮 agent 基准上把冻结老师加提示面保留和共同进化老师加长度控制做成同预算对照。（来源：[[论文/RSI/Recursive Self-Improvement via On-Policy Distillation for Reasoning|Recursive Self-Improvement via On-Po]]）
- 争议：旧手册说固定回合预算截断会砍好留坏，改用按老师打分在线判断，前缀复用还要加质量门槛；新论文说在单轮 OPD 里越靠后的位置老师越不可靠，直接按位置截前面一段即可，TOPD ρ=0.25 分数持平、时间降到约三分之一，最后 10% 单独训练反而低于未训练。两者不矛盾的前提是维度不同：旧结论针对多轮 agent 的回合预算，新结论针对单轮回答的 token 位置。目前该信哪一个：agent 多轮继续按价值早停和前缀质量门槛；单轮可验证推理可先试 ρ=0.25 的位置截断。还缺：把回合级价值门控和位置级截断组合起来，在长回答多轮任务上做同预算对照。（来源：[[论文/后训练/Are Full Rollouts Necessary for On-Policy Distillation|Are Full Rollouts Necessary for On-P]]）
- 争议：旧手册依据 Just-in-Time Memory 主张记忆库全留原始轨迹、把整理放到读时，写入时压缩会永久丢信息；Embodied Turing Machines 反过来把机器人状态直接写进代码变量，物体被盖住后位置还留在变量里，记忆任务 89.9% 对 agent 套壳 47%、VLA 33%。条件不同：代码变量存的是连续环境状态、要的是可回退重试；JIT 处理的是跨任务经验和例子，读时才需要按当前任务整理。目前该信哪一个：控制回路的当前状态用显式代码变量；跨任务经验仍用原始轨迹加读时整理。还缺：同一任务里把显式状态变量和检索式记忆拆开对照，看两者能否叠加。（来源：[[论文/RSI/Embodied Turing Machines Stateful Code for Robot Recursive Self-Improvement|Embodied Turing Machines: Stateful C]]）
- 争议：旧手册依据 PluginRSI 说插件库和重组两步一起做能把 SWE-bench 未见过题从 63% 提到 69%，可迁移是主要卖点；RRSI 指 recursive harness evolution 会记训练任务，in-distribution 大涨、OOD 缩水甚至消失。PluginRSI 的证据是固定题集 15 轮、跨领域问答只 0.568→0.588，说明它的 OOD 确实弱；RRSI 加退火预算、critic 和 pruner 后五个 OOD 最多 +4.7。目前该信哪一个：把 PluginRSI 的插件库加重组当搜索算子，把 RRSI 的 OOD 验收和正则化当上线门槛。还缺：把 RRSI 的 critic/pruner 加到 PluginRSI 流程上做同预算对照。（来源：[[论文/RSI/RRSI Regularized Recursive Self-Improvement of Agent Harnesses|RRSI: Regularized Recursive Self-Imp]]）
- 争议：模型自己写的反馈能不能写进权重。旧手册依据 Self-Generated Feedback Destabilizes Test-Time Training 主张「让模型自己写、又学自己写的、把更新永久写进权重会越学越坏」，坏根在「更新后的权重决定下一批训练文本」这个闭环，冻住生成器能删掉 98% 以上的损害，更新落盘前要在独立真实文本上验证，接受率只有 22/936 和 18/312。RLTL;DR 反过来在几乎做不对的超难任务上让模型每轮失败后自己写一句教训、并把这句话反向传播进参数：并行 128 次全错的 GRPO 卡在 0–1%，改成串行加教训后无提示涨到 12%–13%；只把教训放在上下文里则仍是 0–1%；只留教训损失、关掉奖励仍有 20.0% 通过率。条件不同：那篇是测试时训练、生成与更新互相闭环、没有独立验证，失败在权重被自己的坏样本带偏；这篇是训练期、反馈来自验证器报错和失败单元测试（拿掉这些信息通过率崩到 3.4%），教训是压缩成一句话的监督目标而不是下一批训练文本的来源。目前该信哪一个：训练期、反馈有验证器校准、教训只当监督目标时，写进权重是有效的；测试时自我闭环、没有外部验证时，按前者处理。还缺：同一批超难任务上把「教训写进权重」和「教训只放上下文」做成同预算对照，以及在没有验证器的开放任务上重做一遍。（来源：[[论文/强化学习/RLTL;DR Self-improvement by Internalizing Self-generated Feedback|RLTL;DR: Self-improvement by Interna]]）
- 争议：小模型学老师，该对齐输出概率还是逐层对齐隐藏状态。旧手册依据 LastOPD 主张「中间层监督不是越多越好」：学生每层都对齐老师，MATH-500 冲到 46 后掉到 11.3，只在两边接 LM head 的最后一层对齐并 10 步内交还 token 级蒸馏才升到 58.95；「潜在信号全程挂着会训崩，对齐分数在涨不能当学得好的证据」。PR-OPD 发现小抄带给老师的好处几乎不写在输出概率上：带小抄后 WebShop 成功率 42.2%→56.2%，但不到四分之一的词概率变了、超过八成位置的隐藏状态变了，线性探针只看隐藏状态就能认出是哪条轨迹；同一热启动下照抄老师词概率只有 57.8%（比只做 GRPO 的 66.4% 还低），逐层对齐隐藏状态到 72.7%。条件不同：LastOPD 的老师是另一个固定的大模型、学生在跨尺寸对齐它读不懂的状态；PR-OPD 的老师是学生自己带特权信息的版本，两者同权重、同分布。而且 PR-OPD 在小模型上不加投影层同样会掉到 GRPO 之下（1.7B 36.7% 对 43.8%），加 512 维 MLP 投影才回到 46.9%，等于给「中间层会崩」补了一个具体解法。目前该信哪一个：跨模型、跨尺寸的中间层对齐按 LastOPD 只对齐最后一层或短窗口；同模型的特权自蒸馏可以逐层对齐，但小模型必须先垫投影层并做预热。还缺：在同一组模型上把「只对齐最后一层」「逐层对齐＋投影」「逐层对齐无投影」做成同预算对照，看 PR-OPD 的增益是不是真来自层数而不是特权信息本身。（来源：[[论文/后训练/PR-OPD Privileged Representation On-policy Self-Distillation for Agentic Reinforcement Lea|PR-OPD: Privileged Representation On]] · [[论文/后训练/LastOPD Taming Collapse in Latent On-Policy Distillation|LastOPD: Taming Collapse in Latent O]]）
- 争议：裁判该花力气练强换贵，还是只要保证组内排序一致就够。手册里的 VeriFine 配方走的是「让裁判跟着一起长本事」，用人工小考卷当锚点、每轮从同一基座同样训练量重练；Groupwise Agentic Grading 还要另外训打分模型把打分时间从约 2000 秒压到约 600 秒。A Cheap Verifier 反过来发现：把同一个 Qwen3 8B 交给 12 个裁判训，一致率高低排不出练出来模型的顺序，便宜的 Gemma 4 31B（一致率 0.83）和 Gemma 4 26B（0.76）练出的 HealthBench-hard 都是 0.34、跟最贵的候选裁判打平，平均只差 0.010 分却省掉 98.8% 打分钱；原因是 GRPO 看的是同题 8 条回答的组内排名，裁判整体偏松偏紧不影响方向。条件不同：那篇是半开放、按评分规则打分、用 GRPO 组内比较的任务；VeriFine 是具身推理里要挑样本、要跟人工锚点对齐的场景，裁判偏差会直接变成选样偏差；而便宜裁判带坏小模型也确有证据（LFM2 24B 一致率 0.54，训 1.7B 掉到不训练以下）。目前该信哪一个：任务是组内排名、策略模型不小的时候，先试便宜裁判并把钱省下来；要靠裁判选数据、或学生模型很小时，仍按 VeriFine 那条路校准裁判。还缺：在同一批任务上把「贵裁判 + 组内排名」和「便宜裁判 + 人工锚点校准」做成同预算对照，以及便宜裁判在答案分布随训练漂移后（回答变长）还稳不稳。（来源：[[论文/后训练/A Cheap Verifier is Good Enough LLM Post-training is Robust to Erroneous Rewards|A Cheap Verifier is Good Enough: LLM]] · [[论文/Harness/VeriFine Scaling Verification for Self-Improvement in Embodied Reasoning|VeriFine: Scaling Verification for S]] · [[论文/后训练/Groupwise Agentic Grading and Advantage Redistribution for Code Agent RL|Groupwise Agentic Grading and Advant]]）
- 争议：跟着老师边做边学（在线蒸馏 OPD）到底值不值。手册的可复制配方里有 NeoHorse、DuoOPD、ASCENT、Recursive OPD、TOPD 这一整套在线蒸馏流程，默认每步让学生现写回答、老师当场打分。Rethinking Self-Distillation for Multi-Teacher Capability Merging 把在线蒸馏和离线 SFT 放在同一批拒绝采样轨迹和同一初始化上比，四个模型十一个基准领域内恢复率都是 96.9%–99.3%，在线蒸馏多花 14.8 倍（MIA）和 23.1 倍（Agent×3）训练算力；重跑四篇已发表对比、把 SFT 学习率单独调好之后，在线的领先全部缩水（Open-MOPD 上离线反超 7.0 分）。When Do We Need On-Policy Distillation 更进一步：把学生一开始的回答冻住反复用（半在线），17 组师生里 14 组比在线更准、最多高约 13 分，1.7B 非思考组同 100 步从 56.8 降到 5.0 GPU 小时。条件不同：论文自己也给出边界——师生出力前 64 名词重合度低（相关系数 −0.73）时半在线才赢，重合到 89% 就打平；学生初始回答必须已经像样，换成 base 学生会反过来输；把冻结数据换成老师写的回答也明显更差，说明起作用的不是「冻住」而是「回答得是学生自己写的」。目前该信哪一个：动手前先花少量算力测一次师生 top-64 重合度，重合低、学生已指令微调过就先上半在线或离线并认真调 SFT 学习率；师生同家族接近、或学生还是 base 时才用在线 OPD。还缺：在同一批数据、同一总 token 预算下把在线、半在线、离线三者做同硬件对照，并说明离线方法的学习率是怎么扫出来的。（来源：[[论文/后训练/Rethinking Self-Distillation for Multi-Teacher Capability Merging|Rethinking Self-Distillation for Mul]] · [[论文/后训练/When Do We Need On-Policy Distillation Distilling on Offline Student Rollouts Is Often Bet|When Do We Need On-Policy Distillati]]）
- 争议：中间过程的价值估计该估还是该消。手册的开放问题里收了 Bellman Policy Optimization 的路线——用贝尔曼等式把中间值整体消掉，只保留轨迹级目标，并注明那套近似没有理论保证、只在一个 30B 数学底子上验证过。TPPO 走反方向：把价值头从「每个位置直接输出分数」换成「每步输出一个小增量、沿序列累加后过 sigmoid」，同样用 BCE 训练、其余 GAE 和裁剪目标不动，4B 和 8B 的数学平均分从 34.6、37.5 涨到 41.6、45.9，没见过的题型平均分 62.8→66.9，而且每题只写一条答案（n=1）时仍比 PPO 高 7.5 分（8B）和 10.1 分（4B）。条件不同：TPPO 的前提是奖励 0/1 且 γ=1，前缀价值就等于「从这里续写能成功的概率」；BPO 省掉的是 critic 与显存，换来的是更多近似。目前该信哪一个：二值可判奖励、算力够养价值头时，先按 TPPO 把中间价值估准；显存吃紧、或者能接受近似时再考虑把中间值消掉。还缺：在同一个模型和同一批数学题上把「累加式价值头」和「无中间值目标」做成同预算对照；TPPO 的符号猜对率只从 50.7% 提到 52.7%，离「看得准」还有距离。（来源：[[论文/强化学习/TPPO Tracking-Value PPO For Language Model Reasoning|TPPO: Tracking-Value PPO For Languag]] · [[论文/强化学习/Bellman Policy Optimization|Bellman Policy Optimization]]）
- 争议：一组回答全做对的「饱和题」该扔掉还是回收。Rufus-Air 的做法是按解出率过滤：模型几乎全对和一道也不会的题都扔掉，只留解出率 0 到 0.8 的题，推理阶段 GPQA 从 68.2 涨到 73.5。Save Your Saturated Data 说这些全对的题不必丢：让模型自己写两条带隐蔽错误的完整错解塞进这一组，1.7B 平均分从 28.93 升到 31.53，饱和比例 40% 到 100% 时都比 GRPO 高 1.81 到 3.09 分，每 10 步重采样还能持续回收新饱和题。但论文也给了反面：往全对组里硬塞几个 0 分虽然能把优势值撑大，4B 上各种设置都比标准 GRPO 差；错解得是模型自己从头写的（只改末尾 27.70 对从头写 31.53）。条件不同：Rufus-Air 是八阶段流水线里按组均值估优势的难度过滤，目的是省算力、把信号集中在「刚好不会」的题；Save Your Saturated Data 是在已经花掉采样、只剩全对组的 GRPO 里补回梯度。目前该信哪一个：算力紧、题池大时按 Rufus-Air 过滤；题池小或已经采完、整组全对导致零梯度时，用自己写的完整错解回收，别用塞 0 分这类硬造优势的办法。还缺：同一批题上把「过滤掉饱和题」和「回收饱和题」做成同采样预算对照，以及错解采样本身的算力成本核算。（来源：[[论文/后训练/Rufus-Air An Open LLM Post-Training Recipe|Rufus-Air: An Open LLM Post-Training]] · [[论文/强化学习/Save Your Saturated Data Learning Beyond Reward Saturation in Group-Based RL|Save Your Saturated Data: Learning B]]）
## RSI 度量与信息披露

- 要让别人能判断是否出现 RSI，先按优先级要求披露八类数据；可见的七类包括：内部模型的多样基准分数（含未发布模型）、各类模型的总体支出-能力曲线、预训练算力效率（每个生产 run 的 loss 对外部算力，外加前置小规模变体实验）、后训练算力效率（在 held-out 和未饱和 AI R&D 基准上）、按团队的推理算力用量（如 token 量与支出）、按团队的实验算力用量（如 H100 小时与支出）、按团队/职能/资历的人数和总薪酬。OCR 在第八项处截断，第八类不能凭现有材料补。（来源：How to Measure RSI）
- 把内部模型基准排在第一位：加速会先出现在内部部署模型、后出现在发布模型上；只看公开模型发布节奏会漏掉正在发生的 RSI。（来源：How to Measure RSI）
- 成本和效率要按能力对总支出报告，而不只是报单点分数：每个模型配方给出 capability as a function of total compute expenditure，这是理论上最清楚的 RSI 证据；预训练、后训练、推理、实验四条算力线分开报。（来源：How to Measure RSI）
- 把人力增长和推理算力增长分开归因：更多人力堆出来的进步不构成 RSI 证据，更多推理算力驱动的进步才算；要配历史与持续的 AI R&D 投入序列来识别来源。（来源：How to Measure RSI）
- 如果拿不到全面数据，第二优是给聚合曲线，但必须写清聚合口径、时间范围和是否含未发布模型；否则跨机构无法判断加速是否真实。（来源：How to Measure RSI）

## 世界模型驱动的自我改进

- 代码修复里把 world model 当候选筛选器：用固定写码模型生成 4 个候选补丁，world model 预测每个补丁的执行结果并聚合成一个分数，只把最高分那个送去在线测试；隐藏测试通过率 26.3→29.2、随机挑只有 26.0，在线测试调用次数 3.72 次/题不变。（来源：RSI-Anything: Unlocking Recursive Self-Improvement with World Models）
- 再用真实执行反馈更新 world model，写码模型继续冻结：隐藏通过率 29.2→31.2，在线测试调用仍 3.72 次/题；这样能把选择策略更好和策略模型变强拆开验证。（来源：RSI-Anything: Unlocking Recursive Self-Improvement with World Models）
- GUI 任务里让策略和 world model 一起更新，并按新版本能否通过检查决定留不留：成功率 51→79→99，平均动作数 5.30→3.21，重复点击 237→0，错提交 9 集→1 集；不要只留单组件，两个一起配套通过才留。（来源：RSI-Anything: Unlocking Recursive Self-Improvement with World Models）
- 实验室规划里连续保留 5 个通过检查的版本，分数依次 21.80→38.03→41.99→44.56→46.01，比第一版高 24.21 点，略高于参考系统 45.32；保留机制按轮累积，不能只保存最终版。（来源：RSI-Anything: Unlocking Recursive Self-Improvement with World Models）
- 反应优化里用 world model 预测产率挑下一组条件：同样 20 次实验最佳产率 93.0% 对贝叶斯优化 87.5%，另一套 40 次实验 96.15% 对 82.16%；对照必须卡同样实验次数，否则预测式搜索的收益会被多试掩盖。（来源：RSI-Anything: Unlocking Recursive Self-Improvement with World Models）
- 保留门做成两层：先查单个组件是否可靠，再查策略和 world model 配套是否成立；策略一变，原来准的预测器可能失效，必须先用新数据测可靠性再决定更新。（来源：RSI-Anything: Unlocking Recursive Self-Improvement with World Models）

## 内省信号与可监控性对齐

- 用探针当唯一训练信号时，不要冻结探针：探针冻住时模型把内部状态挪到界线另一边就能零损失，行为不变、有害分仍停在 0.40 以上；每步微调后重新拟合探针，才能让损失下降对应行为改变。（来源：Alignment via Training Against Probes Without Losing Monitorability）
- 配方：LoRA 微调加 KL 锚；探针用合页损失 max(0,1+z)，把激活推到 z≤−1 才算达标；每次模型更新后按 2000 步（单探针）或 500 步（多探针）重拟合；选检查点时取保留 95% 以上基座效用里有害分最低的那个。（来源：Alignment via Training Against Probes Without Losing Monitorability）
- 效果：Mistral 7B 在 GCG 攻击下有害分 0.52→0.01、预填攻击 0.77→0.03；Qwen3-14B 说谎探针让 MASK 诚实分 0.47→0.63（单探针）和 0.70（非线性多探针），能力不掉。（来源：Alignment via Training Against Probes Without Losing Monitorability）
- 可监控性要单独体检：训练后再从零拟合线性探针查同样属性，有害性 AUROC 还有 0.85–0.90、说谎性 0.98–0.99，跟基座差不多；如果重拟合探针读不出来，说明属性被藏起来了。（来源：Alignment via Training Against Probes Without Losing Monitorability）
- 方向消融测试：抹掉拒绝方向后，连续更新探针的检查点有害分只变 −0.03 到 +0.07，而普通 Llama 3 8B 从 0.09 涨到 0.76；不靠拒答话术练出的安全，删一个方向撤不掉。（来源：Alignment via Training Against Probes Without Losing Monitorability）
- 限制：目标只规定内部方向，不规定好回答长什么样，检查点最多 1% 明确拒答，很多回答是把请求改写成无害问题、给空壳内容或乱码；攻击也不是专门针对探针优化的，不能当成抗自适应攻击证明。（来源：Alignment via Training Against Probes Without Losing Monitorability）

## 具身 RSI 与状态代码

- 把机器人策略整个写成带状态的代码（COAP）：代码从摄像头和关节角量出世界状态再决定动作，运行时完全不调用模型；RoboDojo 42 个双手任务成功率 70.24%，比最好基线 31.38% 高 38.9 点。（来源：Embodied Turing Machines: Stateful Code for Robot Recursive Self-Improvement）
- 记忆类任务把测量值存进代码变量，物体被盖住后位置还留在变量里；记忆任务 89.9%，同场 agent 套壳 47%、VLA 33%。（来源：Embodied Turing Machines: Stateful Code for Robot Recursive Self-Improvement）
- 先量测量误差再谈决策：同一个程序用代码自测状态跑只有 63%，换模拟器真值状态能到 83%；卡上限的是测量准不准，不是规则逻辑。（来源：Embodied Turing Machines: Stateful Code for Robot Recursive Self-Improvement）
- 代码库按感知、抓取、放置、检查和恢复分层；新任务只写子目标顺序和少量判断，抓取按抓法写而不是按物体写，相机参数/机器人网格/物体尺寸当常量，只让物体位置当变量；新任务代码 83% 来自公共库，从零做新任务 15 小时到 47% 成功率，不用数据也不用训练，而 VLA 同批任务训练后只有 4.7%。（来源：Embodied Turing Machines: Stateful Code for Robot Recursive Self-Improvement）
- 合并改动用两道保险：新功能加默认关闭的开关，旧任务执行轨迹结构上不变；开发分支只有在验证集成功数比原版高出设定余量 ε 才合并。36 个分支里大多数没用，但分支越多越容易找到有效改动、也来得更早。（来源：Embodied Turing Machines: Stateful Code for Robot Recursive Self-Improvement）
- 别在仿真成绩上直接外推真机：感知依赖 RoboDojo 公开的相机参数、机器人网格和物体尺寸，换真机都要重新量；失败来源里测量约占 62%、逻辑约占 37%；标准布局 77.3%，随机布局掉到 54.1%。（来源：Embodied Turing Machines: Stateful Code for Robot Recursive Self-Improvement）

## 探索初始化与多样性坍缩

- 顺序自改进会把模型按在同一个模态上：每一步把最近的、按分数排序的方案塞回提示，先验越来越强，多样性（1 减两两嵌入余弦）一路下滑，这就是它有时反而输给并行各写各的原因。动手时把总预算切一块先并行铺一批（分批跑、才能中途看到并行那批分数不再涨），挑 15 个高分方案当种子再顺序改。
- 给搜索加去重约束能涨多样性但不涨分：相似度阈值 0.95/0.8、让模型判重、完全去重三种规则都试过，圆堆积平均最高分从 2.44 降到 2.19；过滤太狠（阈值压到 0.98 以下）会挤掉高分方案、种子整体变弱，后面反而更差。
- 开局质量决定下游：每条轨迹头 15 个方案的中位数分数和这条轨迹最终的最高分同向变化，12 套自建流程和 3 套公开流程都这样，属相关性证据，但初始化干预本身给了它因果支持。
- 现成流程自己没把开局选好：给 ShinkaEvolve、OpenEvolve、optimize_anything 三个流程接上「先并行挑种子」，总预算不变、最终分数涨 2%–21%，说明这一步得在外面补。

## 长任务环境的自动构造与逐步进展奖励

- 造长任务要倒着来：先用种子程序生成一份完整正确的底稿，再把底稿渲染成文件、按声明过的可逆损坏计划弄坏一部分当题目；判分器、进度打分器、参考解都从同一份底稿派生，三者代码互不重叠，判分器钉在 agent 看不到的那份底稿上。
- 奖励只在最后给一次，难任务会整组白跑：一组 8 条轨迹全失败的概率是 (1−p)^8，做题成功率 5% 时有 66% 的组一分利用不上、1% 时高达 92%；换成「本步完成度减上步完成度」后还得保留 λΦ(s_T)（经典 PBRS 会把末态清零）。
- 逐步功劳可以不用中间裁判：用确定检查量每步工作区净进展（VTCA），至少一半功劳留本地、其余按记录到的依赖均分，负进展全留本地、越界清零；把系数设成 0 就退化成只看整条轨迹的 GRPO。
- 「还剩多少 token 才干完」是免费的分步信号：从已录轨迹按动作边界切前缀后缀就能得到标签，一个领域训一把尺子、冻结后跨模型复用；换成只看最终得分、答案概率、能否做完三种信号都更差，推理期还能拿它做四选一。
- 环境包是最小交付单位：工作资料＋任务＋判分器三件套要互相对得上，拼工作区时只按主题像不像配文件通过率只有 48.7%，顺着文件之间的引用关系扩题、并给每个文件配上会用它做事的技能才到 74.8%。
- 单步轨迹教不出「发现证据不对就回头改」：让没参与出题的模型只拿公开说明先跑一遍，跑得太顺就说明活被提前做掉了、把环境改回去；第二阶段在同一目标下加新要求、并要求新要求建立在前面结果与反馈之上，任务平均要来回 52.8 轮，缺了探索和调试就留不住。

## 安全行为的稳定性与失败披露

- 结果型强化学习只写清了「什么叫答对」，没被奖励约束的行为没人管：同一套 GRPO 流程重训 20 次，做题通过率稳在 0.34–0.49，失败后肯承认的比例却在 0.26 到 0.90 之间跳，波动约是成绩的 4 倍。
- 这种漂移会被极小的浮点差异放大：只把训练的微批次切分方式换个分法（种子和数据顺序都不动），失败披露从 0.19 变到 0.85；把第 150 步的同一份训练状态复制十份、只换之后的随机采样，第 300 步披露率从 0.11 到 0.88 都有。
- 给个明确的 A/B 提示规则就能钉住行为：同一句中性话在训练里 20 次重训后出现频率从 0 到 0.90，改成明确规定何时该用，20 次里 19 次完全照做；没被训练约束住的行为才容易乱跳。
- 稳定手段是失败条件参考锚点：在答错且格式合规的整条回答上加一个拉回初始模型的惩罚（β=0.04），1.5B 的披露波动从 0.189 降到 0.089，但做题成绩也掉了一点，7B 上成绩反而小涨，代价看设置。
- 认错是好几步串起来的动作，卡点随任务格式变：模型几乎每次都走到了能开始汇报的那一步（概率约 0.95），差别在之后肯不肯承认；把学到的段落空行插回去，承认更多也更稳。

## 测试件与评测基础设施的质量审计

- 只拿一份标准答案验收 AI 写的测试会把质量夸高：改成跑 10 份实现（1 份标准＋4 份正确＋5 份错误）、全判对才算过，最高分从 59.67% 掉到 28.00%；候选从 1 份扩到 15 份时平均通过率从 49.33% 一路掉到 24.33%。
- 测试写不好的主因是判断标准不可靠：抽 6 个模型家族 50 条失败轨迹、去掉超时后人工标注 286 条，50.0% 是断言判错或太弱、34.6% 是没覆盖关键输入、只有 15.4% 是测试自身执行出错。
- 同样算力下改流程比多生成更值：把单对测试/修复换成 3 对加交叉验证和 RSI，GPT-5.6 sol 从 20.33% 升到 32.33%、Kimi K3 从 21.67% 升到 33.33%；拆开看，3 对异构测试最多涨 1 个点、开交叉验证涨 6 个多点、再加 RSI 又多 4.33 到 4.67 个点。
- 判测试质量要两边夹：正确实现被拒说明测试卡得太死，错误实现被放过说明测试没盯住关键行为；两个方向都要有候选才能看出来，但错误候选的标签本身来自原基准的校验脚本，脚本漏覆盖时「错误」可能并不错。
- 长任务复核要把「翻材料」和「做判断」分开：先用规则把证据按行为理成图、再按任务要求裁剪后交给模型，比让它自己翻原始记录更容易找出该让人拍板的那一步；但增益明显看模型，有的模型直接看原始材料反而略高。

## 多智能体协作训练与消息级奖励

- 协作奖励要落到每条消息上：从「最后答对没有」改成「每句话、每次提问让队友更接近正确答案多少」，同一套自博弈环境和初始模型下，三个模型在七个没见过的任务上总分比只看结果的做法高 20.7、23.0、24.9 分。
- 提问也要在问出口时就算分：假设对方如实回答，这条假想回答能让团队找到正确答案的概率提高多少，就给它多少分；训练后「没问清就往下做」从 36.4% 降到 32.0%、「无视队友意见」从 26.3% 降到 22.8%。
- 奖励必须有「值对、且说话人手上真有这条数据」的过滤，否则模型会编数字蹭分；把私人答案奖励拆成选项概率分和总分是否算对两半后，只报结论不列数据的消息从 16.2% 降到 12.8%、把自己数据全列出来的从 55.3% 升到 65.4%（Qwen3-8B）。
- 这套奖励只买到「信息怎么流动」：重复步骤从 85.1% 到 85.6%、隐瞒信息 18.5% 到 18.7%、不守任务规范 88.2% 到 88.3%，基本没动，流程和规范类失败要另想办法。
- 训练环境里的偷跑要交代：提问分发时环境用 agent 看不到的分配表把问题转给「下一位持有者」，消息还有约 30% 的投递失败人为噪声，这些都会影响结论的可迁移性。
