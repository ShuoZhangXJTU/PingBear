## taxonomy 回看

- 建议分组：主索引建议用「决策类型 × 对象」，而不是阶段，因为同一件事在要不要做与信不信结果下标准完全不同，这也是他本人的设计主张。 / 二级分组建议按主题域：工作推进与自主性；来源与采集；归档与检索；内容与表达质量（含小学生与费曼两档语言标准）；日报与推送；界面与产品化；版本、迁移与安全；成本与排期；科研辅助与灵感；评价体系自身的元标准。 / 每组内再按 value 做聚合视图，因为同一条原则（成本意识、诚实报告负面、不覆盖用户手写、单一事实来源）横跨多个 object，需要跨域视角才能看见。 / 建议把「对象级标准」与「元标准」分成两层：rubrics 体系自身的设计要求（不记置信度、独立模块、挂载开关、不提前筛选）单独一层，否则会污染对论文、产品或流程的匹配。 / 建议给每条标准保留一条沿革链，记录它被收窄或切分的后继条目，用于 Reflect 阶段统计哪些轴取值过多、哪些标准总被推翻。
- 缺的轴：通道或媒介轴：微信、pushplus、iMessage、Obsidian、手机、iCloud、GitHub 反复出现，而且单独决定标准（分条发送、正常字号、三按钮、手机可见）。现在只能塞进 constraints，建议把「媒介/平台」提为与 constraints 并列的轴，或至少固定为 constraints 的 channel、platform 子键。 / 时点与频次轴：每天、9 点、早八点、半夜、闲时、过去三个月同时出现。「时间尺度」（多久）与「时点/频率」（什么时候、多勤）语义不同，目前只有一个时间槽装不下。 / 权责与能力边界轴：谁能做（助手有没有权限、能不能在手机上运行、用户与助手怎么分工）属于关系与权限，不是对象属性，五轴里没有位置。 / 材料等级或证据强度：正文级、摘要级、截图 OCR 已经在他的约定里存在，但判断与情境都装不下这个维度。 / 演进状态：某条标准现在是否仍然有效、是否被后继条目推翻、继任者是哪条。这不该进判断字段，但匹配时必须知道。 / 粒度轴：单条、单篇、单主题、全库是四个不同的评价粒度，会直接改变标准。 / 动机四元缺少「注意力与打扰预算」：不要重复推送、不要一直保留历史、不要外发私人灵感，更像注意力预算而不只是 cost。 / 动机四元缺少「隐私与边界」：私人灵感不外发、密钥不外泄，是稳定原则，和诚实、复现、成本都不完全同类。 / 动机四元缺少「承诺与可信度」：他反复介意「你说没有权限」「你也不做」，这针对的是助手可信度这类元标准。
- 轴取值备注：object 建议新增：知识库或归档产物、自动化管线或定时任务、交互界面或产品、隐私与安全、版本与仓库、内容呈现、采集源。 / decision 建议新增：怎么归档或怎么组织、怎么验证或核查、何时做（排期）、要不要推送。原设计已有要不要做、选哪个、信不信结果、何时停、怎么表达、交给谁。 / state 建议新增：阻塞或失败、迁移或变更中、冷启动或补齐、等待反馈。原设计已有未开始、已运行、结果已出、出现冲突、要交付、复盘。 / constraints 建议规范化并新增：通道或媒介、平台、安全、网络环境、成本或预算、受众、时间尺度；新增是否公开或开源、是否进入长期记忆。 / trigger 常见取值族建议固定：新素材出现、任务失败或超时、预期产出缺失、用户提问、用户手写内容可能被覆盖、发现与既有结论冲突、到达定时时点。 / goal 建议新增：产品化、日常运营或自动化、个人知识管理或灵感积累。原设计已有发论文、落地、学懂、建长期能力。 / value 建议新增：自主推进不推诿、完整不隐藏且不替用户筛选、用户手写内容优先、单一事实来源与一致性、按时可翻阅、隐私不外发、低摩擦。 / cost 建议新增：重复劳动、任务悄悄停摆、漏跑无人发现、密钥泄漏、迁移丢功能、用户反复找补、编号错乱。 / role 建议新增：产品负责人以外的运营者或运维、资料整理者、工具使用者。原设计是研究者、工程 owner、学习者、产品负责人，但「整理资料」与「跑日常运营」在这批发言里是两种明显不同的立场。
