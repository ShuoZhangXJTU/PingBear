# 业界洞察：沙漏流程与分级标准 · v0.3

先广泛看清行业，再聚焦关键问题核验，最后形成能指导产品选择的判断。

## 三层标准

- **常驻原则**：实事求是、保留来源与条件、关键缺口回退补证。模型每步只加载这三句。
- **当前阶段卡**：每次只加载当前环节的目标、2–3条要求、产出和过关条件。
- **按需细则**：遇到评价统计、实测或因果问题时才查。原话、沿革和完整证据留档，不反复塞入提示词。

## 沙漏怎么走

| 环节 | 这一步做什么 | 交付什么 |
|---|---|---|
| 1 定题 scope | 明确用户、任务、要作的决定与边界 | 问题定义 |
| 2 广搜 scan | 覆盖产品、历史、失败案例和多类来源 | 广泛候选池 |
| 3 筛选 select | 根据目标和差异分配深核预算，保留反例 | 重点与取舍理由 |
| 4 深核 verify | 检查宣传、评价、实测与量化口径 | 主张—证据—条件表 |
| 5 综合 synthesize | 解释人机分工、体验、技术和商业取舍 | 规律、边界与替代解释 |
| 6 决策 deliver | 展开可选路径、代价、验证和转向条件 | 可执行的产品判断 |

入口广，筛选后收窄，核验处最深；综合后再展开选择。发现关键缺口回到广搜/核验，不能顺着流水线硬写结论。

## 使用方法

执行标准的唯一来源是 [[配置/洞察标准/阶段卡.json|阶段卡]]。`bridge.py` 以 `task=industry_insight, stage=当前环节` 加载，阶段缺失时只返回流程导航；不会加载六张卡或整库 rubrics。

六步产物通过版本化依赖图交接；撤销/重做只影响真实依赖分支，旧产物保留，失效结果标记待复核。详见 [[配置/洞察标准/依赖图与局部重做]]。

进度、Git 版本和各入口的实际接线在 [[研究路线/运行总览]]；从 [[今日简报]] 顶部进入。执行完成与证据可信分开记录。

原始候选池完整保留，未入选不等于错误。结构检查通过只说明格式和引用可检查，不能代替真实证据与人的语义审查。

涉及产品、公司竞争或商业化时，广搜必须加入面向投资和产业决策的市场研究媒体，如华尔街见闻、财联社、36氪、The Information、Reuters、Bloomberg、WSJ、FT。它们适合快速提炼战略动作、商业逻辑、市场预期和竞品判断；关键数字与高管原话仍要回到财报、发布会、监管文件或一手访谈核验。不要把投资人报道中的判断直接当作产品效果事实。

需要时查看 [[配置/洞察标准/核验细则]] 或 [[配置/洞察标准/综合细则]]。按需细则不自动注入。

## 本轮确认与验收

你已认可此前五条补强：总负担与责任放到综合；商业归因放到综合；差评样本与测量边界放到深核；机构初筛放到广搜，具体结论的证据要求留在深核。它们已转为阶段要求，不再保留“待讨论”标签。

每步只检查本阶段的产出；最后才检查报告是否有关系主线、体验与技术取舍、条件化证据、决策与反证。缺证据可以交付缺口，不能用篇幅补齐。
